# 数据契约 · schema_version=1

`knowledge.sql`是关系存储结构；`schemas/records.schema.json`是核心交换记录的JSON Schema；各模块CSV是人工可编辑导入模板。CSV中的数组/对象字段用JSON字符串，缺值为空单元格并附状态/原因，入库时解析为null。JSON与SQL字段映射由未来适配器显式完成，不能假定同名自动等价。

## 稳定标识与连接

| 对象 | ID | 来源与必需连接 |
|---|---|---|
| 来源 | source_id | URL/本地路径、取得时间、使用范围 |
| 文件/快照 | document_id | 来源、文件哈希、类型、身份状态 |
| 期刊 | journal_id | 规范身份、官方核心/稿约证据 |
| 文献 | paper_id | 元数据来源、DOI、全文document_id、阅读时间 |
| 语料集合 | corpus_id + paper_id | 20篇/100摘要/25核心/方法范例用途单列 |
| 证据 | evidence_id | 文献/文档、页段表定位、原文短摘与释义 |
| 逻辑关系 | relation_id | 原文献与多条证据，含范围和推断强度 |
| 研究运行 | run_id | 规范/配置哈希和独立阶段状态 |
| 假设 | hypothesis_id | run_id、基线证据、四路缺口、同层级与反证 |
| 数据与变量 | dataset_id / variable_id | 原始文件、问卷、年份、标签/取值/缺失 |
| 方法与范例 | method_id + paper_id | 每法至少两篇不同文章，方法与表格页码 |
| 模型与结果 | model_id / result_id | 假设、变量、方法、样本、实际代码输出 |
| 冻结包与稿件 | pack_id / draft_id | manifest哈希、隔离context_id与稿件族 |
| 正文主张 | claim_id | 句子定位→文献证据或实际结果 |
| 投稿 | submission_id | 同稿族共用在审占用，逐刊适配版本 |

## 证据等级

- direct：原文直接支持，给页/段/表和最小短摘。
- synthesis：跨多条原始证据综合，必须列出依据并说明综合步骤。
- inference：本系统新增推论或假设，不能充当已发表结论。

支持关系同时标support/contradict/qualify/context；原文作者声称与研究设计实际支持强度分开。摘要抽取中的未知字段，不用常识或后续期望填补。

## 机器校验与业务校验边界

框架工具验证目录、依赖、JSON可解析、Schema基本类型和DDL可执行；记录Schema支持外部标准JSON Schema验证器。它们不能证明文献读完、期刊今天有效、理论创新、统计识别或论文合格。业务门槛须结合证据审查。

SQL用外键维护引用、method_references主键阻止同一篇重复充两篇、partial unique index限制同稿族一个在审/已录用占用。每法2篇、核心25篇、结果已执行等跨表规则由未来业务验收器检验，当前DDL不自动完成这些判断。

## 版本与修正

纠错追加新记录/快照并标旧版失效；冻结包不可原地改写。日期用ISO-8601含时区；核验日期与来源发布/事件日期分别保存。SHA-256为64位小写十六进制，未知不得随填全零。
