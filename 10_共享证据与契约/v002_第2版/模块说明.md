# 10 共享证据与契约 · 第2版

为全文、关系、方法、变量、结果、句子和投稿提供统一ID、证据链与机器可读数据契约。

前置必读：根目录AGENTS.md、基础要求.md、项目架构.md。本模块框架已建立；业务状态为planned，除非明确的业务验收报告证明完成。

## 输入

原始/公开/授权材料及来源记录；模块结构化输出。

依赖模块：无业务前置依赖。

## 输出

- SQLite DDL与字段词典
- JSON Schema与交换格式
- 证据/来源/文件索引
- 去重、核验、权限与版本规则

标准产物名称：`knowledge.sql`、`records.schema.json`、`数据契约.md`。

## 处理流程

1. 使用稳定ID：J/P/DOC/E/R/H/V/M/RES/C/DRAFT/SUB前缀加唯一标识；DOI和来源唯一号为候选去重键，但不将可能更正的标题作为永久ID。
2. 文献分为元数据、摘要已读、全文取得、全文已读四个独立事实；文献池成员关系另表记录，允许同一文献用于20/100/25/方法多个集合。
3. 证据记录source_id、paper_id、locator、短摘/释义、支持/反对/限定、direct/synthesis/inference、审查与哈希；网页用URL、时间与快照定位，PDF用页/段/表定位。
4. 关系图谱保存概念与角色、方向、分析单位、范围、方法、原文声称强度和实际证据强度；用relation_evidence多对多连接。
5. 变量、模型、结果和句子绑定研究run与冻结包，避免不同波次或不同稿件混接；字段升级须写迁移，不能静默改名。
6. 文件清单同时记授权/用途/可共享范围；原始调查数据留在外部只读入口，公开复现包仅含可发布代码、字典和可共享结果。
7. SQLite建表脚本只定义结构；初始正式业务表为空。带expected状态的方法目录另存，不能把空数据库称作永久代表文献库已建成。

## 验收标准

- [ ] DDL可在空库执行、外键检查通过
- [ ] 交换数据可按Schema验证
- [ ] 主张能沿证据链回到原文或真实分析
- [ ] unknown与not_applicable有明确语义

## 失败与恢复

输入不可用、证据不足或访问受限时记录明确状态与缺口，保留已验证产物；不能造数据或跳过硬门槛。上游内容改变则本模块产物stale，重新锁定输入后建立新attempt。事实性错误回到产生该事实的上游修正，不在写作层掩盖。

## 空值与审查状态

null表示未知或未取到，并附unknown_reason；不适用须用明确status标记而非伪造0。事实核验状态用unverified/verified/rejected，阅读状态用not_read/abstract_read/fulltext_read，不可混用。

JSON Schema只检验数据形状；“全文是否真的读完”“引用是否支持”须业务审查，不能靠Schema证明。


## 第2版议题可空契约

research_runs.issue允许NULL，表示议题尚待第4步结合现实或理论线索生成；不以空字符串伪造已选议题。theme仍为宽泛主题输入。运行JSON以topic_state记录候选、生成阶段及未冻结状态。已有非空议题兼容保留，但不能仅凭非空认定已经核验或冻结。SQL列序及其他表不变。新库使用本版knowledge.sql；旧库先备份，再在独立连接执行migrations/v1_to_v2.sql并检查foreign_key_check；本轮只测试迁移，不操作正式数据库。
