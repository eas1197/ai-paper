# 00 项目控制 · 第2版

统筹版本、配置、依赖、阶段状态、恢复与验收，保证每次研究拥有独立工作区。

前置必读：根目录AGENTS.md、基础要求.md、项目架构.md。本模块框架已建立；业务状态为planned，除非明确的业务验收报告证明完成。

## 输入

根目录规范、模块注册表、研究主题与议题、可选研究问题、资源配置。

依赖模块：无业务前置依赖。

## 输出

- 运行manifest与输入锁定
- 阶段计划和状态报告
- 验收报告与偏离记录
- 实施路线和需求追踪

标准产物名称：`run_manifest.json`、`gate_report.json`。

## 处理流程

1. 解析已启用模块版本，检查依赖无环，读取配置，不自动选择更高目录版本。
2. 建立run_id；锁定规范、配置、模块清单、说明及模板哈希，保存主题/议题/问题。
3. 01—03只绑定一次性公共资源；每篇研究在04—07及按模式启用的08/09建立新的attempt目录，记录输入、输出、运行环境、模型调用和异常；本框架仅完成工作区初始化，执行器待开发。
4. 运行前验证上游是否passed以及哈希是否一致；不一致将受影响阶段标stale；只有业务验收器可以放行。
5. 可选投稿默认不建工作区。保留失败产物，恢复时从最早失效阶段开始。
6. 状态报告同时展示“框架ready”和“业务planned”，不能通过文件存在推断研究完成。

## 验收标准

- [ ] 模块注册齐全、依赖无环、文件可读
- [ ] 初始化不可覆盖、不可逃逸项目目录
- [ ] 状态明确区分框架完成与研究完成

## 失败与恢复

输入不可用、证据不足或访问受限时记录明确状态与缺口，保留已验证产物；不能造数据或跳过硬门槛。上游内容改变则本模块产物stale，重新锁定输入后建立新attempt。事实性错误回到产生该事实的上游修正，不在写作层掩盖。

## 阶段记录模板

未来执行器采用：`stage_id / attempt / status / upstream_manifest_sha256 / input_files / config_sha256 / environment / model / prompt_version / seed / output_files / gate_report / deviations / started_at / finished_at`。

状态改变追加事件，不静默覆盖历史。模型费用与耗时逐步记录，超预算停止该调用并保存进度。


## 第2版路由

当前配置默认single；init支持--writing-mode three_plus_review。公共资源与具体研究生命周期分开，详见运行模式说明.md。两条分支必须分别测试。
