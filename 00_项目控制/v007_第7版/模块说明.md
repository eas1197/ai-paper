# v007 全局实验模式候选

生产入口和生效版本仍由 v005 注册表决定。Dev Mode 是单次运行的显式选择，实验配额由 `dev_profile.json` 定义。总控将模式、研究主题、各模块配额和生产注册表哈希写入 `runs_dev/<run_id>/run_manifest.json`，恢复时检查哈希和命名空间。各阶段状态初始为 `planned`，阶段是否实际执行应查看该阶段自己的回执。

在项目根目录启动，以下命令以一个新的运行 ID 为例。

```powershell
$runner = '00_项目控制/v007_第7版/tools/run_mode.py'
python -B $runner --mode dev --run-id edu_dev_002 --theme '教育分流'
python -B $runner --mode dev --run-id edu_dev_002 --topic init
python -B $runner --mode dev --run-id edu_dev_002 --topic prepare
python -B $runner --mode dev --run-id edu_dev_002 --literature start
python -B $runner --mode dev --run-id edu_dev_002 --literature verify
```

文献阶段支持 `--literature resume`。配额耗尽后保持原结果和失败记录。正式模式使用 `--mode formal --run-id <id> --theme <主题>`，委托给原 v005 初始化。实验选题和文献产物带有 `formal_eligible=false`，实验入口不能调用正式冻结或正式文献交接。

当前已接入选题工作包与原生检索候选的执行入口。06 的测试复用估计引擎，其余模块配额已登记，接入和端到端验证见[审计与验收](outputs/全局实验模式_审计与验收.md)。
