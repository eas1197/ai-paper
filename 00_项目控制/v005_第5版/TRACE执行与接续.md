# TRACE 执行与接续

1. **接续和定范围。** 读根规范、[当前状态](outputs/当前状态.md)、注册表和本轮相关模块说明。按本轮意图选择深度。查询只查证回答，简单改动直接核验，有依赖的交付列输入和验收，长期工作维护当前状态及恢复点。
2. **锁定需求和阶段。** 先读相关原始要求与最近修订。保留需求编号，在[需求矩阵](需求追踪矩阵.csv)记录原文定位、有效要求、所属阶段、验收办法、状态和实证位置。变更新增日期、依据与替代关系，并核对受影响的下游。旧需求采用既存记录，无法取得的原始聊天逐字稿标明缺口。
3. **执行及恢复。** 参照[阶段台账](阶段台账.md)，使用已注册模块和对应专业技能。同一项研究沿用 run_id，续跑使用相应 attempt 与检查点。记录阶段目标、需求编号、输入版本及哈希、依赖、执行方法、日志、产物、验收条件与实际证据。上游改变时核对直接绑定，从最早失效阶段继续，保留失败记录。01—03 正式验收后按快照绑定；每篇研究依写作模式启用相应阶段。
4. **逐项验收。** 程序检查、成功运行及业务关卡分别记账。交付前把产物对应到用户要求、最新修订及验收证据。阶段通过要有明确报告和仍有效的上游锁。阶段目录、运行清单和旧报告可以作为恢复定位。
5. **更新接续点。** 阶段切换、重要决定、批处理启停、交付或暂停时，先重读[当前状态](outputs/当前状态.md)再合并更新。保持入口简短，记录有效版本、证据、阻塞和下一步。细节记入对应阶段或运行，历史保留原位置。

`python .\00_项目控制\v005_第5版\tools\project.py trace` 只读显示资源快照与当前运行目录的实际检查点。输出中的 recorded_gate_status 是当时关卡报告所载状态，依赖变更另查当前状态和阶段台账。命令按需运行。项目配置中的模型额度记录状态为关闭。
