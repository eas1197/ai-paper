# 自动论文选题 v3.0 开发与验收计划

制定日期 2026-11-20。适用范围为自动论文项目的选题与定题流程。每个开发任务交付后，在本文末尾逐条登记验收结果和证据。

## 一、目标和开发基线

v3.0 从可核实的社会现象发现研究机会，用「问题 → 文献解释 → 反诘 → 新问题」逐轮深化。最终交付一个能进入正式研究的候选，或者一份有依据的停止报告。正式题目、假设和研究设计仍由现有 G4、G5 关卡放行。课题通过 G5 后沿用 06 分析、07 写作。

- **已确认的要求**。采用开放探索方案 A、两轮文献研究、保留完整问题演化链。审查由独立智能体承担，模型暂定 **GPT‑6.2 Sol**。审查须同时判断当前质量与继续探索的边际效益，达到当前阶段目标就结束该阶段。《优化选题流程》中确认的内容及本轮修订为开发依据。[Chat 原始讨论](https://chatgpt.com/c/6b0020e4-1bc4-83ec-a3a0-bedc3d208cfc)
- **现行代码**。00 第 5 版、04 第 8 版、05 第 8 版、06 第 4 版、07 第 14 版、10 第 2 版、11 第 3 版。现行无题 `init` 返回选题任务，由 `--topic-decision` 接收优先方向，再建立正式运行。[注册表](../module_registry.json) · [现行选题入口](../选题与自动论文流程.md) · [当前状态](当前状态.md)
- **实现约定**。00 负责选题运行与交接，04 和 11 提供文献与现实材料，05 提供既有五刊选题学习与正式冻结，10 提供证据标识和定位。更新现有项目内的入口和说明。开发版先用于独立试跑，通过验收再登记默认版本。[项目架构](../../../项目架构.md) · [TRACE 执行与接续](../TRACE执行与接续.md)
- **需在试跑中定下的参数**。S04-A 可用授权或公开材料补充初查，记录范围和来源。进入 G4 的材料逐条按正式口径核验。模型与检索调用上限、单轮和全程预算用试跑实际消耗校准。试跑前写明上限和计数口径，生产值经试跑后写入配置。若技术上拿不到某项用量，记为未知，用可计数的调用上限控制。

## 二、选题系统的运行顺序

| 阶段 | 工作 | 产物和放行条件 |
|---|---|---|
| S01 开放探索 | 从理论、现实和文献找线索，把有来源的社会现象转化为研究机会。用户给出领域时按该领域探索。 | 机会地图、原始来源、审查结果。兼查单条线索的真实性、社会学意义和后续发问潜力，以及候选集合的实质差异。证据不足时定向补查。 |
| S02–S03 提问与具体化 | 复用现有五刊学习资源，形成实质不同的问题，写清对象、范围、比较、核心概念，以及不同答案会改变的判断。 | 问题卡、候选比较、保留及退回理由。问题可回查至机会卡，允许退回 S01。 |
| S04-A、S05-A、S06-A 初查与深化 | 找最相近研究，按 `Q0 → E0 → C0 → Q1` 留存初始问题、文献解释、反诘与新问题。按前提、反例、竞争解释、适用边界和证据强度追问。 | 有原文定位的解释卡和问题演化链。审查者决定继续深挖、保留分支、进入正式精读或停止。 |
| S04-B、S05-B、S06-B 正式精读与复核 | 调用现有 G4，按指定六刊、约 100 篇有效摘要和 25 篇入选全文的口径取证。复用符合正式条件的初查材料。用全文重查最接近的研究、竞争解释及边界。 | 正式证据包和复核后的问题版本。证据推翻既有判断时，回到受影响的分支或检索步骤，保留原裁决。 |
| S07–S08 反方审查与冻结 | 审查最近似的研究、替代解释、问题的贡献及数据可行性。核验原问卷和代码本，先定目标量和证据要求，再定主模型。 | 具名审查、定题决定、问题及假设与设计冻结记录。有效 G4 与 G5 通过后交 06、07，允许零题通过。 |

## 三、审查智能体和停止规则

研究智能体提交结构化结果与证据。审查智能体在独立上下文中读取候选、关键原文、上次提出的缺口和本轮新证据，给出判断。一个独立角色复用于 S01、S02–S03、深化循环和 S07，分别提供审查提纲。实际运行记录模型、任务版本、收到的证据和原始裁决。准备期验证宿主能否派发指定的 6.2 Sol 智能体并读取返回值。模型不可用时记录待审原因，替代模型须在运行配置中明示。

审查报告每次写明当前质量、支持或反对的证据定位、本轮相比上轮的实际增量、目前最重要的缺口、下一轮的具体行动及其预期收益。只写「继续查找」「再做一轮」的裁决需要补充。S01 对机会卡使用 `PASS / REVISE / REJECT / UNCERTAIN`。深化循环使用 `DEEPEN / BRANCH / READY / STOP`。`READY` 表示可以进入正式精读。程序另外保存运行停止原因，例如预算耗尽、来源不可访问或低收益且未达标。

| 审查情形 | 执行动作 |
|---|---|
| 当前阶段质量已达标 | 立即通过并交接。记录尚存但不影响放行的疑问。 |
| 未达标，且明确知道下一轮能查什么 | 写出可能找到的证据、它可能改变的判断和预计成本。收益值得投入、预算够用时，只做这项定向补查。 |
| 新材料一直重复，或只是换了问法 | 判断继续搜索的边际效益为低。质量仍不足时停止该分支并登记缺口。 |
| 暂时无可靠来源、访问受限或预算已用完 | 保存有效证据与恢复点，停止本轮。质量仍不足的候选保留未通过状态。 |

有效增量包括更可靠的原文证据、足以动摇原判断的反例、能区分两种解释的新比较，以及改变去留判断的测量核对。增加题录数、换用类似概念或重复改写标题，本身不算增量。程序执行预算和允许的状态转换，6.2 Sol 负责证据和边际效益的实质判断，正式关卡按各自规范复核。[04 正式验收说明](../../../04_议题文献与现实/v008_第8版/使用说明.md) · [05 模块说明](../../../05_研究问题与假设/v008_第8版/模块说明.md)

## 四、开发任务、交付物与验收

按 **D00 → D01 → D02 → D03 → D04 → D05 → D06 → D07 → D08 → D09** 推进。正式登记文件名时，在对应任务的验收记录补路径。开发阶段清单中的测试材料数量用于覆盖情形，选题运行的停止规则见第三节。

### D00 核定开工基线

- **目标与任务**。把 Chat 共识、本轮修订、当前版本和接口落到一份可持续对账的文档。执行现行框架只读校验。
- **交付**。本文、现行版本与接口入口、首次验收记录。
- **通过条件**。D00.1 每项开发工作都有目标、交付和可核对条件。D00.2 写明 6.2 Sol 独立审查与边际效益的放行和停止规则。D00.3 记录基线框架命令及结果。

### D01 定证据结构，手工走通真实文献案例

- **目标与任务**。先验证解释提取，复用 `paper_id`、`evidence_id`、原文定位与材料哈希。定机会卡、问题卡、解释卡、反诘与演化链字段。解释卡区分作者主张、提出的机制、观察结果、证据实际支持的程度、适用范围和系统推断。标出关键根据来自摘要还是全文。人工按结构走一遍已有可用原文。
- **交付**。证据与问题演化数据契约、填写示例、一条真实文献演化链和复核记录。
- **通过条件**。D01.1 每条解释可以回查到原页或原始摘要位置，引用断链能被发现。D01.2 覆盖摘要不足、关联被夸为机制、研究对象不同造成的表面冲突，记录事实判读。D01.3 新问题写清新增的比较、待检验条件或可区分的解释，保留一个没有实质增量的退回例。

### D02 做独立审查智能体

- **目标与任务**。实现 GPT‑6.2 Sol 角色配置和调用或交接入口。给各阶段定义读什么、怎样证伪、应返回哪些字段。申请补查时写预期发现、影响的判断和成本，复查时比较实际增量。使用三个简单裁决场景先调通，再用 D01 的材料验收实质判断。
- **交付**。智能体配置、各阶段审查指令和输出契约、独立调用记录、裁决样例。
- **通过条件**。D02.1 记录实际使用的模型和独立审查输入，能定位原始裁决。D02.2 能区分已达标、值得定向补查、低收益且不合格，给出证据及理由。D02.3 缺证据、调用失败、模型不可用及输出无效均保留为待审或失败，可按记录重试。

### D03 做深化循环和运行控制

- **目标与任务**。让问题、解释、反诘与分支可逐轮保存。程序检查引用和状态，执行预算上限。保存原始模型输出、每轮计数、停止原因和检查点。探索中的问题按版本追加，收回判断时写理由。
- **交付**。控制器、运行配置、问题分支与审查记录、断点续跑入口、离线测试结果。
- **通过条件**。D03.1 继续、分支、就绪、停止都按审查结果流转。D03.2 低收益停止和预算耗尽都可复现，未达标分支无法进入正式精读。D03.3 模拟中断后定位到最近有效轮，已完成的调用与证据可复用。

### D04 接开放探索 S01

- **目标与任务**。接入现实、理论与文献线索；对照原始来源，提取具体现象、社会学联系和可能的疑问。检索与证据归档优先复用 04／11，按来源和现象去重，调用独立审查检查单卡和候选集合。
- **交付**。S01 入口、检索记录和研究机会地图、首次审查、按缺口补查或停止的记录。
- **通过条件**。D04.1 无题探索能产出有原始来源且有实质区别的机会。D04.2 给定研究领域时保持在范围内。D04.3 重复线索、无源事实和无方向的补查被识别，符合阶段条件的机会才流入 S02。

### D05 接提问与具体化 S02–S03

- **目标与任务**。复用现有五刊选题卡与发问 Skill，形成可以交给深化循环的具体初始问题。按对象、范围、比较和解释目标核对候选差异。
- **交付**。问题卡、使用的五刊范例索引、候选比较与初审记录、深化循环输入。
- **通过条件**。D05.1 每题关联机会、明确范围和概念，并说明不同答案的用途。D05.2 审查区分实质不同的问题和表述变体。D05.3 无合格问题可退回找线索，保留退回依据。

### D06 接 00 与 G4 正式文献研究

- **目标与任务**。给正式 `init` 之前的探索留检查点，沿用同一 `run_id`。初审就绪后生成 `selected_for_stage_04` 裁决与证据索引。复用 04／11 采集、核验、精读及补证入口，逐条判定初查材料是否能计入正式口径。
- **交付**。选题入口与交接格式、正式运行样例、文献复用及缺口报告、集成测试结果。
- **通过条件**。D06.1 同一 `run_id` 可以从探索检查点进入正式运行并回查锁定裁决。D06.2 六刊来源、摘要阅读与全文实读门槛维持现行规则，辅助线索不混计。D06.3 重试或回退保存原裁决与证据，受影响的正式阶段从新版 attempt 续跑，并能读既有运行。

### D07 接正式反方审查与 G5

- **目标与任务**。用正式全文复核解释和研究贡献。独立审查找最相近的既有研究、反例、竞争解释和问卷测量风险。把通过候选送 G5，复用现有假设、目标量、证据要求和分析设计的检查。
- **交付**。全文复核记录、反方裁决、G5 输入和冻结或退回报告、06／07 交接验证。
- **通过条件**。D07.1 贡献判断可回到原文，证据不足时保留具体疑问。D07.2 G4 不通过或证据变更后，G5 拒绝冻结。D07.3 通过后，冻结交接能由现有 06／07 读取，业务复核证据可定位。

### D08 回归和真实试跑

- **目标与任务**。用可复现输入测试往返、低收益停止、预算限制、指定主题和失败恢复。用同一组真实输入、尽量可比的预算，对照现行选题方法与 v3.0，再单独跑一次无指定题目的探索。记录真实耗用和阶段缺口。
- **交付**。技术测试报告、真实试跑与对照记录、可复核的阅读材料索引、预算建议及剩余差距。
- **通过条件**。D08.1 关键回归通过，含旧入口、旧运行读取、审查失败和中途恢复。D08.2 对照分别判断原文准确性、问题增量、研究可行性和单位有效增量的工作量，报告实际差异。D08.3 无题试跑记录实际探索、停下的具体理由和证据。如果正式材料不足，如实记录待补，真实科研验收继续保留待验收状态。

### D09 版本登记与启用

- **目标与任务**。落实试跑确定的预算与来源配置。按模块版本约定更新说明、索引、注册表和 TRACE 需求记录。检查更新对锁定中的历史运行有什么影响，写明恢复与回退方法。
- **交付**。可运行的版本目录、入口说明、配置、更新记录、默认启用证据、回退说明和最终验收报告。
- **通过条件**。D09.1 准备切换的技术与真实试跑验收有可回查记录。D09.2 新运行能以指定版本走通，旧运行状态按哈希与原版重查，不覆盖历史。D09.3 需求和本清单逐项对账，报告仍待正式业务验收的项及其影响。默认启用须有独立试跑放行依据。

## 五、每次交付后怎么验收

1. **交付前逐条跑原标准**。按任务编号核对产物、运行结果和实质判断。代码可运行、技术测试通过、真实研究关卡通过分别登记。文档或文件已存在可用来定位产物，实际验收以对应证据为准。
2. **在本文续记本次对账**。每条条件记 `条件编号｜状态｜实测结果｜证据路径或定位`。状态用待做、进行中、待验收、通过、未通过或受阻。任务所有必需条件逐条通过，才把任务记为通过。修正后补一条复测记录，原失败记录保留。
3. **写清影响和恢复点**。补充本轮通过数、未通过项、是否影响下一任务、运行 ID／attempt 和接续位置。上游要求或证据改变时，复核受影响下游，失效项按新证据复验。用户新增要求写入本节变更记录，列出受影响的任务与条件。
4. **向用户报告本轮对账**。说明做完哪一步、验收几项、证据在哪、剩余什么。下一个聊天先读本文最近记录和对应证据再续做。
