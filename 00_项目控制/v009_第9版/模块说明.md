# v3.2 增量候选 · 检索时机与失败处理

复用 v008 选题指令和原生网页采集的身份、摘要、来源事件与去重逻辑。使用 v007 全局实验清单。现有生产启用状态与历史结论保留。此候选正式口径为 5+35 篇、实验口径为 5+5 篇，均为去重相关论文，不要求 25 篇全文。经典理论和权威解释单列，允许九刊外来源。七刊加 ASR 与 AJS，两刊优先使用出版社官网。

| 状态 | 操作 |
| --- | --- |
| reality | 新运行从现实观察开始。一次原生网页探索可同时比较报道、公开讨论或纪实访谈，官方材料用于交叉核实。记录现象、来源、可支持的结论及其边界，作为学术初查输入。 |
| initial | 本轮唯一初查；目标 5 篇和有来源事件的理论线索。未达标或技术中断保留检查点。 |
| preliminary_review | 用 `prepare` 获取材料与凭证绑定值。先判断研究问题的学术价值。命题仍待验证时可确认学术价值。证据可得性需要另查时，用 `academic_pass` 保留初审判断并转入 `design_review`。 |
| design_review | 核查能否取得真实、适用、可核验的证据。材料待查沿用现有待核机制，全部适用路径核查后确实缺证据才归档。学术价值和证据可得性可在同一份审查报告中分别记录。 |
| literature_budget_exhausted | 当前阶段仍有文献缺额，且原检查点的检索预算已经用完。保存核验结果、缺额、预算和终止原因，结束当前运行。 |
| S02 / S03 / S05 / S06 | 学术失败后回到对应任务，沿用现有材料复审。首败后最多两次修改，第三次学术失败退出候选池。技术问题分开记账。 |
| archived | 有学术价值但缺数据。归入根目录统一潜在选题库，当前候选结束。受审问题及运行编号与登记一致，重复登记幂等。 |
| supplemental | 仅当前初步学术审查与数据可行性均通过时可检索。排除初查文献，跨阶段去重；检索达到数量后仍需最终审查。 |
| final_review / s08_ready | 独立审查需绑定合并的文献与理论证据，检查具体问题、创新与可行性。通过后可在候选命名空间生成 S08 设计凭证。实验产物保留实验标记。 |

从项目根目录按顺序运行 `tools/staged_topic.py` 的 `init <run_id> --theme 教育`、`initial <run_id>`、`prepare <run_id>`。独立审查用 `review <run_id> --report <报告路径>` 录入，报告采用 `model`、`invocation_id`、`reason`、`question`、`evidence_sha256`、`outcome`，放行时同时提供 `academic_value=pass` 和 `data_feasibility=pass`。最终报告还给出 `design`。通过后运行 `supplemental <run_id>`；只在最终通过后执行 `s08 <run_id>`。候选正式口径在每条命令上指定 `--mode formal`。当前由执行者调用同一独立审查机制并录入结果。

新增现实优先的运行在 `init` 后先用 `prepare` 读取现实观察任务，再用 `reality <run_id> --report <观察记录.json>` 保存 `phenomenon`、`search_focus` 及 `sources`（来源地址、类型、能支持什么和证据边界），之后执行 `initial`。旧运行沿用原记录。初查方向来自观察记录，初审及终审的证据指纹包含该记录。

新运行在同一次独立审查中登记方法适配和材料可行性，[研究方法分流与交接](研究方法分流与交接.md)说明三个方法 ID、材料待核、归档门槛及 05/06/07 的接口状态。

新运行在 `reality` 与 `initial` 之间增加 `exchange`，先保存自主解释、独立反方和候选问题。见[解释反诘与事件研究](解释反诘与事件研究.md)。旧运行按原合同恢复。

独立审查沿用同一轮次。初审判断现象来源与社会张力，并将简洁的核心问句、具体情境、机制和实证设计分别处理。落盘的 `research_case` 包含 `core_question`、`context`、`hypotheses_or_propositions`。每条在文字里写明理论依据、推导、预期关系、支持或反驳所需证据。描述或探索项目可用命题或子问题。审查者判断理论链、问题覆盖和实际可检验性，程序校验结构与绑定，不按字数、假设数量或术语机械放行。

经验分析阶段根据已经取得的材料判断解释是否成立，同时说明反例、竞争解释及结论边界。选题或设计阶段无需提前给出这一结论。

检索中断或缺额时，对同一运行执行 `advance <run_id>`，也可使用当前检索阶段的 `--resume`。控制器按原检查点评估预算和缺额，复用已核验结果；续查沿用原有采集器的配置与来源校验。已用完预算的缺额记录为资源限制，不消耗学术返修次数。

实验模式的初查和补查各有最多三批，仍各需五篇。每批沿用 24 个原生搜索动作的提示上限及事后核验，控制器逐批验收，达标即接续审查。独立文献任务及定性材料检索沿用各自原预算。旧实验需要增加检索批次时，续跑绑定此前终止时的检查点和文献集合，既有批次继续计入本阶段上限，预算迁移单独留档。
## 冻结后定性写作接续

`python -B 00_项目控制/v009_第9版/tools/resume_writing.py <run_id>` 接续已冻结、已收集定性材料且有独立矩阵审查记录的实验。启动时核对冻结凭证、问题两层表述、方法、框架、材料回执与原始搜索记录。共用的问题 ID 由运行身份派生，语义版本绑定两层原问、研究方法、设计和独立终审；原有问句不需统一改写。

总控用标准输入发送研究包，每次独立审查单独启动 GPT-6.2 Sol 会话，在运行目录保存任务、响应、会话记录和 Token 用量。工具故障标记为 `technical_block`，通过的调用记录可用于断点恢复。矩阵与写作方案共用两次学术返修上限；未获独立通过时保留草稿和裁决。入口目前覆盖冻结后的定性实验交接，原选题、文献获取和数据分析入口保持原有职责。
