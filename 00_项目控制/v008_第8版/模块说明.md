# v008 选题 v3.2 候选

**现行定位：历史选题实现／独立入口仅供追溯。** 原v009仍可继承本版已存在的指令、规则、证据或兼容组件，不因历史标记而废弃其依赖；不得绕开v009原状态机或作为新的5.0总控。以下原说明保留历史语境。

以 v007 实验清单启动，保持 v005 生产注册表与历史运行。v008 复用 v006 保存、证据哈希、审查和分支控制。选题版号和实验配置哈希单独登记。

| 阶段 | 实际任务分组 | 交付和判断 |
| --- | --- | --- |
| S01 现象，S02 概念化 | opportunity | 事实或研究报告与政策目标、推测分开。解释观测量可以支持什么概念，列出不支持的解释。 |
| S03 初始问题 | question | 区分核心问题、具体问题与研究情境、实证操作三层。操作细节可待定。人群和时间限定说明它属于研究范围、数据限制或理论条件。 |
| S04 检索，S05 解释，S06 反诘 | deepening | 形成解释、条件与竞争解释，按实际需要补检或修正。通过改变答案后会获得什么不同知识，区分理论推进和设计优化。 |
| S07 独立审核 | 同一 deepening 回合独立审查，沿用 GPT‑6.2 Sol | 核心概念、知识增量与研究意义优先。补检是否值得、场域能否观察、数据能否支持分别写明。 |
| S08 定题与研究设计 | READY 后计划接口 | 完成数据、设计和正式证据复核后才可冻结。v008 实验入口仅运行到是否值得继续，S08 未接通，既有正式入口和门槛保留。 |

审查者仍使用已有结构。建议分别在 `strongest_objection` 记主要反方解释，在 `actual_increment` 记答案会改变的具体认识，在 `gap` 区分情境和数据未核实项。描述、解释、理论以及有独立价值的测量问题都可提出。若一轮变更仅调整操作方案，分类为 `design_only`；此处不授予学术深化通过。

运行命令在项目根目录执行。

```powershell

python -B '00_项目控制/v008_第8版/tools/topic32.py' edu32 init
python -B '00_项目控制/v008_第8版/tools/topic32.py' edu32 prepare
# 每轮取得独立审查后执行 record，依次传递问题包、审查报告和用量记录。
```
