## 执行粒度与上下文约束

1. **一个新对话 = 一个最小任务编号。** B01、B02 等分别执行；若任务下存在字母子项（例如 K10a），一次只执行一个子项，父项待全部子项验收通过后才完成。用户可明确授权合并少量相邻任务，但默认不合并。
2. 先读当前编号正文、所在小节的目标/验收及已完成依赖的产物路径；只按需读取源文件相关函数、配置字段和原测试。使用 GitHub 行范围读取、函数定位或分段阅读；不一次性拉取所有版本、全部运行记录、原始网页日志或全文。禁止把完整历史聊天再次塞入输入。
3. 每项先做最小只读检查，确定输入→处理→输出；只改相关文件。优先调用现有函数，代码改动与测试分别清楚记录。不新增 v013、不重写 3.x、不触碰 main 或生产注册。
4. 单项产物建议一页以内/小型 JSON 或一个独立可测试的代码改动。大文件按函数或小节处理；检索按已有批次、写作按一节、验证按一套合同。不要为节省上下文降低学术标准、减少规定文献数量或绕过审查。
5. 若单次任务仍太大、环境不支持或接近上下文容量，先提交可核查的阶段结果（代码须可安全保留；未验证明确标注），记录尚未完成的精确子项，停止；由新对话继续。不得一直重试或自动执行其他任务。
6. 真实运行与离线测试各自登记。凡需要真实 CLI、独立会话、网页工具或原始证据而当前执行器缺失时，标记 blocked/waiting，不伪造；可另行授权独立的无依赖任务，但不越过研究学术关卡。

# 0. 本轮整合目标

本轮不是继续增加功能，也不是再设计一套研究流程，而是把仓库中已经存在的研究控制器、文献检索、定性材料、写作器、独立审查和执行工具，组装为一条可运行、可检查、可恢复的 ai-paper 5.0 工作链。

六项总目标：

1. **唯一总控：** v012 是唯一的 5.0 总控候选和统一入口。
2. **完整继承 3.x：** 原 3.x 研究流程、阶段顺序、文献规则、学术门禁、材料可行性、S08 冻结和方法分流均保持权威，不重新设计、不缩水、不绕过。
3. **接通 AI-Writer 4.0：** 将既有 V15 写作计划和 V16 正文任务、来源绑定、语言核验、稿件接收与审查真正接入 v012。
4. **统一 Chat/Codex：** 统一任务输入、结果结构、来源核验、证据接收和状态回传；保留两种执行环境各自真实的凭证类型。
5. **完成自动调度：** v012 能按原流程调度任务、等待独立审查、接收回执、正确返修、检查门禁、断点续跑并记录全过程。
6. **整理 GitHub：** v012 成为唯一 5.0 候选；其他 5.0 控制器标记为历史实验/参考实现，保留代码、测试和运行记录，不删除。

本清单是施工顺序和验收合同，不是一次性开发授权。每个子任务完成后都应停下，等待用户决定是否进入下一项。

- 5.0 真实验收完成前，不将 v012 写入正式生产注册表，不覆盖 main，不删除历史模块。

# 6. 统一执行协议

每次用户下达一个最小任务（或明确授权的少量相邻任务）后，执行者必须按以下步骤工作：

1. **刷新基线：** 重新读取远端开发分支 HEAD、当前文件和相关模块；不能沿用旧快照。
2. **确认范围：** 明确本次只做哪些子任务，列出依赖、文件和禁止修改范围。
3. **先检查再修改：** 先读原模块、原测试、原文档和真实运行记录；不凭模块说明猜实现。
4. **小步修改：** 只改本项必要文件；不顺手新增控制器、不重构无关模块。
5. **运行验证：** 先运行本项测试，再运行受影响的原 3.x 和模块回归。
6. **核对真实产物：** 检查文件、哈希、状态、原始日志、审查凭证和 Git diff。
7. **更新清单：** 只将证据充分的子任务标为完成；记录提交 SHA、测试结果和未解决问题。
8. **停止等待：** 当前最小任务完成后停止，不自动进入下一个最小任务，等待用户指令。

每次交接至少说明：
- 本次完成的任务 ID；
- 修改文件和原因；
- 原模块是否保持不变；
- 测试名称、独立用例数、运行结果；
- 真实搜索/模型/审查是否执行；
- 产物位置、哈希和运行 ID；
- 未完成项、阻塞和风险；
- 提交 SHA；
- 下一项建议，但不自动执行。
