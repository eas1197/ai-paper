# D14：独立审查会话启动与身份记录合同

状态：verified（启动/身份记录合同定义，静态对照原执行器与接收器；真实独立会话运行仍暂缓）。不增设学术门禁，不改变原模型、预算、生产注册或真实凭证验真要求。

## 1. 角色、权限和启动前置

审查调度者（受信任的运行器/接收方）独立选择当前 C04 task_snapshot 和 D09/D13 审查上下文；研究者负责提交冻结输入，不能决定自身审查通过。审查者仅接收独立选择、已锁定的审查资料，按 D10–D13 合同返回候选学术裁决；原门禁负责正式状态转换。

启动前由调度者核当前研究/阶段/任务/输入版本，确定 review_kind、review_type、模型资格、已有研究者真实 session/thread 记录、原调用及时间预算、审查对象与允许的输入文件。复审另外核 D13 prior_review 与返修谱系。若没有可用独立会话、缺前置记录、无权限或预算耗尽，保留失败/阻断，不启动伪造审查、不默认通过。D18 负责把这些失败规范接回 unable_to_review；本项不提前实现接收逻辑。

默认审查无额外搜索权限；缺证据只能指出具体缺口，并另由原有授权补核任务处理。Codex 只读模式、禁止审批及不加载用户配置；Chat 不宣称具有相同 CLI 沙箱。任何宿主不能实际实施的访问隔离须明确标明限制，不可仅以 prompt 声称已保证权限隔离。

## 2. 启动方案与原模块对应

| 路径 | 独立会话启动 | 原依据及边界 |
|---|---|---|
| Codex CLI | 每个审查实例分配新 attempt，独立执行非 resume 的 exec --ephemeral；用原模型 gpt-6.2-sol（适用原 v009 审查时），只读，保存实际命令、输入、events、response、stderr、登录诊断 | v009 resume_writing.dispatch 的 reviewer=True 调用实际 argv：executable -a never exec --ignore-user-config --ephemeral --skip-git-repo-check -s read-only --json -o response.json -m REVIEWER -；cwd 为新 attempt，stdin 是实际 request JSON，timeout=480。不得虚构已登录、已执行或擅自改模型。新接续尊重原预算，不另开无约束调用池 |
| Codex 原反诘 | 原 v012 autopilot_v3.Executor.call 分配 attempt，保留预算 reservation、调用状态与真实 thread.started；研究者与批评者 session 不同，反诘仅为前置 | 原反诘回执不是正式学术审查。原 completed_call 可在严格匹配原任务/回执时恢复相同实例，不得将旧会话重新包装成新独立复审。已有 v009 resume_writing 缓存只按 request 比较，D16–D20 要补接收验真 |
| Chat | 只有平台/操作方实际能够新建与研究者分离的会话、提供可独立核对的会话及原始执行记录时，才可派发同一冻结任务；不继承研究者对话、隐藏结论或额外记忆 | C19 chat_receiving 仅核可见文本、记录路径和字节等，不提供 host_authenticated，不证明独立身份。普通同一对话角色扮演、模型自报 session、工具可见引用或多个回答均不是独立凭证；无真实会话启动/证明能力保持 unable_to_review 或 pending，不调用原门禁 |
| 受授权人工审查 | 外部实际独立审查者接收同一冻结材料，记录实际身份、独立提交渠道及原报告文件 | C15 manual record 可核文件绑定，不自动证明人工独立性；不把人工提交映射成原要求的 gpt-6.2-sol 审查。只有原节点明确允许且可验证的执行器才有资格进入其原门禁 |

## 3. 接收方所有的启动记录（D14 定义）

每次尝试独立保存 launch_request.json，不由审查模型填写。以下是字段规范，不是已有真实回执；不得生成示例 UUID、thread 或假日志作为实测证据。

| 字段 | 内容及约束 |
|---|---|
| schema_version | 显式 1 |
| launch_id | 调度者生成的唯一尝试 ID；与 D12 execution_id 关联；不是原生 thread 或 invocation 凭证 |
| task_snapshot | C04 research_id/stage_id/task_id/snapshot_sha256；必须是独立选定的当前版本 |
| review_kind / review_type | D09 与 D13 分类；technical_verification/format_check 不得派发为学术审查 |
| context_ref / permitted_inputs | 已冻结 context 与白名单文件的 path/sha256；不允许审查者使用未提交隐藏结论；仅传必要文件/内容，不开放整个研究工作区作为审查材料 |
| executor / requested_model / reviewer_role | 执行器真实类型；原节点要求的模型、独立审查角色；禁止将预期模型写成实际已使用模型 |
| researcher_session_refs | 由接收方独立提供的已有研究者会话及原始记录引用；无法确认不得写伪造值 |
| session_policy | new_isolated_session；禁止 resume 到研究者或复用前次复审；同一已完成实例仅允许按原合法恢复规则重放核对，不算新审查 |
| permissions | 读范围、禁止修改源材料、无额外搜索授权；实际宿主执行限制另记录 |
| budget | 原 workload/call allowance 与时间上限引用；缺预算不得自行放宽 |
| reservation_time | 实际调度时 UTC 带时区时间；仅说明调用预留，不能替代真实启动时间 |

请求哈希随原任务版本保存。实际尝试开始后另外保存独立 identity/execution 记录，记录 launch_id、task_snapshot、实际 executor/model（不能从 requested_model 推定）、真实 session/thread、invocation_id、开始时间、原始输入及事件/响应引用、退出状态、失败原因。未获得的字段保留 null 和缺失说明。D15 负责具体记录字段/持久化接续；D16 核 invocation 与原始回执；D17 核研究者/审查者会话及输入隔离；D18 处理无法审查；D19/D20 接回原审查入口并核实际执行可验证性。D12 的 execution_binding 仍由接收者独立选定，不能由审查者提交自我证明。

## 4. 静态验收矩阵

| 场景 | D14 启动合同要求 |
|---|---|
| 冻结任务与原预算有效，原生 CLI 可用 | 可创建新 attempt；不得事先填实际 thread 或写通过 |
| 同一 Chat 对话要求扮演审查者 | 不符合独立会话；不得生成正式凭证 |
| 无登录/工具/权限/真实身份记录 | 保留未执行或真实失败，阻断学术放行 |
| 旧任务/旧报告版本或重复执行身份 | 禁止当作新独立审查；旧回执仅按原恢复规则核对 |
| 复审无变更的冻结输入 | D13 不允许提交为独立复审 |
| 只有格式或技术检查成功 | 不产生独立学术裁决 |

逐项核对旧 v009 dispatch 的新 attempt、真实 CLI 参数、thread.started、response hash 及缓存边界；核对 v012 原反诘的预算/身份记录；核对 C15/C19/C20 对接收方独立记录与 Chat 宿主认证限制。启动方式、角色、输入范围、权限、模型和身份记录定义完备。此项是定义任务，仅静态验收，不新增代码、不运行真实 Codex/Chat、不宣称身份已验证；真实运行仍按用户暂缓策略。
