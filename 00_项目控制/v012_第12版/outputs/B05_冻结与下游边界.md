## 1. 冻结包的权威定义

原 `staged_topic.freeze(work,state)` 仅在 `state.status=s08_ready` 时运行；重算最终文献与理论及启用的上游证据哈希，要求最终报告 `evidence_sha256`、`question` 与 state 一致，`design` 非空，方法路径与最终审查 `method_assessment` 相符，适用时复核定性搜索回执。成功写入 `s08_topic.json` 后，将状态置为 `frozen`。

| S08 字段 | 权威来源/含义 | 06/07 下游不变条件（作为边界要求） | 当前执行情况 |
|---|---|---|---|
| `question` | 最终独立审查报告 `question`、`state.question` | 下游具体研究问题必须与其完全一致；转换研究方法或写作不得改写问题 | **部分强制：** v009 `question_binding.binding()` 要求 `conversion.new_question == frozen.question == state.question == final.question`；V15 `produce()` 有冻结问题相等判断；06 初采集和 V16 无直接校验 |
| `design` | 最终报告非空 `design` | 研究对象、分析单元、时间范围和推断设计不由框架修复/写作重定义；改变需退回上游审查而非改写 S08 | **冻结时强制、下游未闭合：** `binding()` 将 `frozen.design` 纳入 `semantic_version`，但未显式重验其值等于原最终报告 `design` |
| `research_method` | `state.research_method`，在 `freeze()` 时与最终审查 `select_method(pass)` 复核 | 定性只按所选路径采集；定量使用原 V14 门禁；下游 packet.method 与冻结方法一致 | **部分强制：** `binding()` 返回冻结 method.path，V15 `produce()` 检查 packet.method；但 `binding()` 未重新比较 frozen.method 与 state.method 或最终审查选择；V16 仅依据 packet.method 分类 |
| `evidence_sha256` | 原 v009 对 merged literature、theories、启用的 reality/exchange/issue/event 组成的组合 digest | 更换上游材料/研究问题前必须重审；旧冻结包不得复用于改变后的文献/理论 | **已强制于 `binding()`：** 当前组合哈希与 frozen、最终报告一致；06 初步采集和 V16 没有原生重验 |
| `review_sha256` | 最终报告规范化 digest（不同于文件字节 SHA） | 任何最终审查报告变化必须使原冻结绑定失效 | **已强制于 `binding()`：** `evidence_digest(state.history[-1]) == frozen.review_sha256`；但并不认证 reviewer 独立身份 |
| `research_case` | 最终报告的研究案例/命题上下文 | 保留审查批准的情境和理论限定；补材可细化证据，不能替换已审研究对象 | **需额外合同：** 下游无对该字段的全量不可变性重验 |
| `mode/scope/formal_eligible` | 冻结包开发模式为 experimental；`formal_eligible=false` | 冻结不等于学术独立性或 G7 正式放行 | **已写入：** 原 freeze 固定 false；V15 review request 和 V16 manifest/审查请求也不宣称正式资格 |

**哈希口径要严格区分：** 原 v009 `evidence_sha256`、`review_sha256` 使用规范化 JSON digest；`question_binding.binding()` 另外输出 `freeze_sha256`、`framework_sha256`、`receipt_sha256`（对应文件原始字节 SHA-256）。两种摘要不能直接互比。

## 2. 原 06 的接入与禁止改写边界

1. **首次定性转换/采集：** `qual_materials.validate_conversion()` 只要求 `core_question/prior_question/new_question` 等字段非空，且 prior 与 new 不同；`read_materials()` 保留原生检索事件、来源 URL 与证据哈希。**首次采集不读取 `s08_topic.json`，因此不能宣称 S08 边界此时已闭合。**
2. **框架及经验矩阵：** `framework.analysis_matrix()` 要求框架完整、receipt 为 `framework_collection`、哈希吻合，每个分析维度均有记录，并按 material_id 追溯原始证据；它不复核 S08 原问题和设计。框架可形成理论推演和暂定结论，但不得把经验欠缺当作改题许可。
3. **下游强绑定：** 进入 `resume_writing.resume()` 时立即调用 `question_binding.binding()`，要求 `frozen` 状态、S08/最终审查/研究问题/上游证据相符、conversion 与框架核心问题一致、receipt 的 run/phase/conversion/framework/events/response 哈希匹配；修复批次递归查 parent receipt、材料增删与未改动记录。
4. **允许的修复：** `repair_materials.rebind_requirements()` 仅允许变更维度的 `needed_material`；`resume_writing` 的框架修复还要求 `framework.core_question == contract.core_question`。修复新批次必须保留父子回执与新旧材料 ID 关系；不可通过覆盖冻结文件、篡改历史证据或暗改问题来满足审查。
5. **矩阵审查与适足性：** 只有首轮独立矩阵报告绑定原矩阵、决定 `pass`，且 `material_adequacy.support=sufficient` 并给出合法 eligible material IDs，才可产生 `analysis_matrix_reviewed.json`。缺失为 `awaiting_material_adequacy`，不足为 `insufficient_core_material`，不准越级写作。自填审查者模型/调用号不证明独立身份。

## 3. 原 07 的接入与禁止改写边界

- **V15 真正受约束的路径：** 原 v009 `resume_writing` 从 `binding()` 得到 `question_binding`、`specific_question` 和 `method`，将 reviewed matrix 的路径放入 packet；`writing_plan.produce()` 检查 frozen.question 对应 packet.specific_question、method 一致，重算绑定、矩阵 collection/framework digest 和分析维度，输出写作方案及含 `topic_sha256`、`analysis_matrix_sha256`、`question_binding` 的 review request。模型可调整文字与章节安排，**不可重写具体冻结问题或把新机制当作已被审查接受**。
- **V15 有较弱的可单独调用入口：** `produce()` 在 `s08_topic.json` 不存在时不会做冻结核验；当 packet 不含 `question_binding` 时，也不执行完整 binding 重验。应将这种输出视为未证实冻结链的实验方案，不得在总控中当作已审核 S08 产物。
- **V16 目前只锁定自己的输入：** `ai_writer4.prepare()` 调 `writing_plan.render()` 校验章节/来源结构和语言资源，输出 task 与 `writer_manifest.json`；`submit` 核 packet hash、章节与主张证据台账，并保留 `formal_pass=false` 和待独立审查状态。**未调用 `question_binding.binding()`，未核 `s08_topic.json` 或 V15 独立方案审查通过凭证。** 即使正文结构检查通过，也不能声明研究问题、设计与证据冻结边界得到端到端认证。
- **定量旧版边界：** V16 的 quantitative `route()` 只返回 V14 文字路径；V14 原有 G2–G6 上游通过及运行哈希门禁继续生效，不能拿新 S08 直接当原 G4–G6 的实际执行凭证。完整分流另由 B06 单独核对。

## 4. 异常拒绝、返修与版本化合同（边界要求，非本轮新增功能）

| 触发场景 | 已有拒绝/行为 | 不可放宽的接续规定 |
|---|---|---|
| S08 不存在、state 未 frozen，或冻结问题/文献/最终报告哈希改变 | `binding()` 读取并拒绝不符；V15 有条件检查 | 停在上游，保留旧冻结证据与审查记录；不得自动以新 packet 或同会话自审掩盖差异 |
| 修改 `frozen.design`、`frozen.research_method` 或 `research_case`，但仅调整下游 packet/绑定 | 当前 `binding()` 没有逐一重比最终审查的 design/method/case；`semantic_version` 会随设计/方法变化，但无法单独证明它仍是原批准版本 | **待后续代码补门禁：** 用原最终审查值与冻结包重算校验，并把审批过的冻结包文件哈希锚定于下游可信交接；不允许静默替换 |
| 06 首次采集/矩阵生成先于冻结核验，或 V16 独立启动 | 06 只验本地 conversion/receipt/framework；V16 只验 packet/style/结构 | 在自动调度前做 S08/方法/版本的前置拒绝；未获得可信 binding 和方案审查回执时保持 waiting/blocked |
| 材料不足或审查提出 source/event/framework 缺口 | 原 `resume_writing` 有限次重建矩阵、`repair_materials` 父子回执，预算/技术问题可阻塞 | 只在冻结问题不变的前提下修复材料、来源、论证边界；若必须改变研究问题/方法/核心设计，回到上游新一轮审查及冻结（新版本），不得改写原 S08 |
| V15/V16 草稿文字变更、正式 G7 放行请求 | V15 锁 packet/矩阵/方案哈希并要求方案审查；V16 锁 packet/style，formal 模式固定拒绝未有可信回执的正式放行 | 文风优化不能增加材料未支持的新事实/因果强度；V16 需接入可信冻结包、matrix、V15 `review_status` 与独立凭证后才可考虑正式放行 |
