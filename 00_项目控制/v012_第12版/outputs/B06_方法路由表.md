## 一、方法在何处被选定

1. **发生阶段：** 原 `staged_topic.review(work, state, report)` 在审查状态（包括初步/设计/最终审查及允许的复核）受理外部报告；仅当 `state.method_paths` 为真且 `outcome` 为 `pass`、`missing_data` 或 `materials_pending` 时调用 `method_paths.select_method(report.method_assessment, outcome)`。仅学术价值 `academic_pass` 会进入 `design_review`，**不构成方法放行**。`outcome=pass` 还要求学术价值与材料可行性通过；原 `route()` 得到 passed 后才写入 `state.research_method`。
2. **审查字段：** `method_assessment.paths` 必须严格且完整覆盖三条路径；每条具有 `status`（ready/missing/unknown/not_applicable）及非空 `reason`；`selected` 是独立审查选中的路径。pass 必须选择一条且该路径为 ready，ready 需要非空材料 ID 列表和 `access=verified`。online_qualitative 额外要求 `approach=public_text|ethnography`，后者需 `observation=verified`。在启用 `qual_search_receipts` 时，ready/missing 的定性判断还需真实 `search_attempt`、`receipt_sha256`、conversion/events/response 哈希、材料 ID 和问题复用解释。
3. **不允许的替代：** `missing_data` 只有全部适用路径 missing 且 `selected=null` 才能归档；`materials_pending` 只有存在 unknown 且 `selected=null` 才能等待。这两类都**不应形成下游方法选定/写作通行证**。自报 `model` / `invocation_id` 和字段结构检查不能独立认证审查主体。
4. **冻结节点：** 审查通过后非最终轮进入 `supplemental`；最终轮进入 `s08_ready`。原 `freeze()` 检查最终报告、证据哈希与设计，启用 `method_paths` 时重新计算 `select_method(final.method_assessment, pass)` 并要求与 `state.research_method` 完全一致；`s08_topic.json.research_method` 才是冻结的下游权威方法。**有条件分支：** `method_paths` 未启用的历史运行可能没有结构化 `research_method`，不能从领域、题目或写作稿件猜补所选方法；应等待原 3.x 合同明确或阻塞自动分流。

## 三、路由边界、拒绝规则与后续需补接的接口

| 条件 | 已实现的拒绝/保障 | B06 确立的总控不变合同（尚非代码实现） |
|---|---|---|
| `selected` 无效、ready 无材料或 access、ethnography 缺 observation | `select_method()` 拒绝；适用时 `verify_material_review()` 验真源搜索回执 | 原审查为唯一可授权方法选择的输入，不由 Chat、V15/V16 按研究题目猜测 |
| `missing_data` / `materials_pending` / 仅 `academic_pass` | 原审查进入归档、等待或设计审查，不形成最终 pass 冻结 | 不创建下游已放行方法，不将“路径可能可行”写成 ready |
| 最终审查与 S08 方法不一致 | 原 `freeze()` 在 method_paths 启用时拒绝 | 分流只能依据当前 run 的 `s08_topic.json.research_method.path`，并保留 `approach`、freeze SHA、审查回执 |
| S08 方法与 06 转换/框架审查方法不一致 | 原 `question_binding.binding()` 和 V15 `produce()` 可约束写作 packet.method；06 初采集未直接对照 S08 | **先补冻结前置校验，再执行定性采集或接受独立审查**；如需改变方法，返回原研究审查/重新冻结而非下游改 method |
| quantitative packet 错交 V16 定性写作 | V16 `validate_packet()` 明确拒绝 quantitative | V14 必须依其原 G2–G6 通过和数据/分析材料运行，不能只显示路径字符串即声称已接通 |
| 定性 packet 填写另一条路径、非真实冻结包或仅有 V15 文本 | V16 检查方法值及 V15 结构；未检查 S08/独立审查绑定 | 写作前强制验证 packet、S08、reviewed matrix、独立审查与来源哈希，失败保持 blocked/waiting；不得“自动纠偏”为另一研究方法 |
