## 0. 核心结论

1. 原 v009 将**学术价值判断、材料可行性判断、技术/证据完整性校验、审查主体真实性**分散在不同字段和函数中。四者不能互相替代。
2. \`review()\` 要求报告声明 \`model="gpt-6.2-sol"\`、提供非空且不重复的 \`invocation_id\`、绑定当前 \`evidence_sha256\`，并给出非空 \`reason\`、\`question\`。这些校验能检查报告声明和证据版本，**不能证明报告确由独立会话/独立审查者产生**。
3. v009 没有发现专门描述该 review 报告的 JSON Schema。实际生效的是 \`review()\`、\`select_method()\`、\`verify_material_review()\` 中的运行时字段校验。共享 \`records.schema.json\` 是定量核心交换记录 schema，含若干记录的 \`review_status\`，但不是 \`review()\` 报告 schema，也未被 \`staged_topic.py\` 用作该报告的验证器。
4. 学术通过不等于材料可行；材料回执完整不等于学术价值通过；证据哈希匹配不等于来源真实或解释正确；\`invocation_id\` 不等于独立身份凭证。
5. S08 冻结是最终审查之后的证据/设计一致性门禁。冻结包仍固定写入 \`formal_eligible=false\`，不得把 \`frozen\` 解释为正式生产资格。

## 1. 四种必须分开的判定

| 判定维度 | 它回答的问题 | 原 v009 中的主要依据 | 不能据此推出什么 |
|---|---|---|---|
| 学术价值 | 研究问题是否有理论/经验意义，是否存在值得研究的学术增量？ | 审查报告的 \`academic_value\`、\`outcome\`、\`reason\`、\`question\`；初审任务范围 | 不能仅凭文献数量、材料存在或技术校验通过 |
| 材料可行性 | 是否有真实、可核验、适用于该问题的材料与访问条件？ | \`data_feasibility\`、三条 \`method_assessment.paths\`、材料回执 | 不能由“尚未查到”直接推出“材料不存在”；\`unknown\` 不是 \`missing\` |
| 技术/证据完整性 | 报告是否绑定当前证据版本，必需字段、哈希、方法回执是否符合合同？ | \`evidence_hash()\`、\`review()\`、\`select_method()\`、\`verify_material_review()\`、\`freeze()\` | 不能证明学术判断正确，也不能证明审查者独立 |
| 审查主体真实性 | 报告是否来自被授权的真实独立审查主体/会话，而非研究执行者自审或自填身份？ | 当前只有报告自报的 \`model\`、\`invocation_id\`；上游反诘有 \`research_actor\`、\`critical_actor\`、\`critical_receipt\` | 当前代码没有充分身份认证；不得标记为已验证 |

**放行原则：** 学术价值与材料可行性是实质判定；技术/证据完整性是必要的完整性门槛；审查主体真实性是独立性门槛。正式放行应同时满足四类要求。当前代码只实现了部分字段和文件校验，独立审查主体真实性仍是明确缺口。

## 2. 正式审查阶段门禁

### G0：所有审查共用的技术与证据完整性门槛

**入口状态：** \`preliminary_review\`、\`design_review\`、\`final_review\`、\`materials_pending\`、\`S02\`、\`S03\`、\`S06\`、\`S05\`。其他状态调用 \`review()\` 会被拒绝。

| 项目 | 当前合同 |
|---|---|
| 审查主体（代码声明） | \`report.model\` 必须严格等于 \`gpt-6.2-sol\`；\`report.invocation_id\` 必须非空且不能与 \`state.history\` 中既有 ID 重复 |
| 审查输入 | 初审/设计审查/非 final 状态：\`initial/literature_matrix.json\`；最终审查：\`merged_literature.json\`；理论材料始终为 \`initial/theories.json\`；另按状态标志纳入现实、反诘、议题计划和事件比较 |
| 必需字段 | \`model\`、\`invocation_id\`、\`evidence_sha256\`、\`reason\`、\`question\`、\`outcome\`；其中前五项在 \`review()\` 入口校验，\`outcome\` 后续由路由逻辑使用 |
| 技术校验 | 当前报告 \`evidence_sha256\` 必须等于实时重算值；理由和问题非空；invocation 不得重复 |
| 放行边界 | 只表示报告字段和证据版本绑定达到代码合同；不表示学术价值、材料可行性或独立身份已经通过 |
| 失败 | 缺字段、证据哈希不一致、重复 invocation 会抛出异常；未知 outcome 最终由 \`route()\` 拒绝 |

\`final\` 的判断规则是：\`state.status == "final_review"\`，或 \`state.review_phase == "final"\`。因此最终材料源由当前状态/阶段决定，不是由报告自行声明。

### G1：初步学术价值审查

**入口状态：** \`preliminary_review\`（以及代码允许重新审查的其他非 final 审查状态）。  
**任务范围：** \`prepare()\` 的 \`review_scope.preliminary_review\` 要求先判断问题的学术价值；证据可得性尚待检查时，可用 \`academic_pass\` 保留学术判断并进入研究设计；命题是否成立留给经验分析。

| 项目 | 当前合同 |
|---|---|
| 审查主体 | 代码要求声明模型 \`gpt-6.2-sol\` 和唯一 invocation；独立身份本身未认证 |
| 输入证据 | 初查 \`literature_matrix.json\`、\`theories.json\`；若启用则包含 \`reality.json\`、\`explanation_exchange.json\`、\`issue_plan.json\`、\`event_comparison.json\` |
| 核心学术字段 | \`academic_value\`、\`outcome\`、\`reason\`、\`question\`；对正向/保留/归档类结果，\`academic_value\` 必须显式为 \`pass\` |
| 学术保留放行 | \`outcome="academic_pass"\` 仅允许初步学术审查；不能用于 final 或 \`design_review\`。成功后记录 history、更新 question、进入 \`design_review\`，不要求此时材料可行性已通过 |
| 直接进入补查 | \`outcome="pass"\` 还必须满足 \`data_feasibility="pass"\`；方法路径启用时须有 ready 路径及材料合同；通过后进入 \`supplemental\` 并保存 \`initial_sha256\` |
| 研究情境合同 | 当 \`reality_first=true\` 且 outcome 为 \`pass\`/\`missing_data\` 时，必须提交 \`research_case\`：\`core_question\` 与报告 question 一致、context 非空、\`hypotheses_or_propositions\` 为非空字符串列表 |
| 不通过 | \`concept\`、\`value\`、\`depth\`、\`increment\` 分别进入 S02、S03、S06、S05；达到既有学术失败阈值后可进入 \`eliminated\` |

**注意：** \`academic_pass\` 是“问题有学术价值、继续做设计/材料核验”的阶段性判断，不是整项研究正式通过，更不是数据可行性通过。

### G2：研究设计与材料可行性审查

**入口状态：** \`design_review\`。  
**任务范围：** \`prepare()\` 的 \`review_scope.design_review\` 要求判断是否能取得真实、可核验且适用的证据，并区分待查证据与确认不可得。

| 项目 | 当前合同 |
|---|---|
| 输入证据 | 初查矩阵、理论材料及按标志纳入的现实/反诘/议题材料；复审仍须重新绑定当前 evidence hash |
| 方法审查 | 默认 \`method_paths=true\`；\`pass\`、\`missing_data\`、\`materials_pending\` 时必须提供三条方法路径完整评估 |
| 三条路径 | \`quantitative\`、\`secondary_interviews\`、\`online_qualitative\`；每条都必须说明 status 和非空 reason |
| ready | 必须有非空 materials 字符串列表及 \`access="verified"\`；网络定性还须声明 \`approach=public_text/ethnography\`，ethnography 额外要求 \`observation="verified"\` |
| unknown | 代表材料可行性尚待核验；\`outcome="materials_pending"\` 时 selected 必须为空且至少一条路径为 unknown，状态进入 \`materials_pending\`，不放行 |
| missing_data | 只有所有适用路径均为 missing、selected 为空，且 \`data_feasibility="blocked"\` 才可进入归档；\`not_applicable\` 可排除，unknown 不能当 missing |
| pass | selected 必须指向一条 ready 路径；同时 \`data_feasibility="pass"\`；初审上下文通过后进入 supplemental |
| 定性材料回执 | 若 \`qual_search_receipts=true\`，secondary_interviews 与 online_qualitative 的 ready/missing 判断须通过真实搜索回执复核（见第 4 节） |

**重要边界：** 只有适用路径全部确认缺失才可归档潜在选题。只要仍有 unknown，就应保留在 \`materials_pending\`，不得将“尚未核实”写成“不可获得”。

### G3：最终学术审查

**入口状态：** \`final_review\`。  
**任务范围：** \`prepare()\` 的 \`review_scope.final_review\` 要求审查学术增量、经核实的材料可行性与研究设计；不要求经验解释已经成立。

| 项目 | 当前合同 |
|---|---|
| 输入证据 | \`merged_literature.json\`、\`initial/theories.json\`，以及状态标志启用的现实、反诘、议题计划、事件比较 |
| 学术判断 | 仍要求 \`academic_value="pass"\`；审查理由与 question 非空；最终问题必须与冻结时的 state.question 保持一致 |
| 材料判断 | \`outcome="pass"\` 必须有 \`data_feasibility="pass"\`；方法路径启用时重新评估三条路径并选择 ready 路径 |
| 研究情境 | 若启用 reality_first，pass/missing_data 仍须提供与 question 一致的 research_case、context 和非空命题/子问题 |
| 不允许的捷径 | \`academic_pass\` 不能用于 final；仅凭文献数量或技术回执不能放行 |
| 通过结果 | \`outcome="pass"\` 通过路由后进入 \`s08_ready\`；不直接等同正式生产资格 |
| 其他结果 | academic failure 进入 S02/S03/S06/S05 或 eliminated；materials_pending 暂停；missing_data 在满足全路径缺失与归档合同后归档；technical 只允许技术重试 |

## 3. 审查报告的实际字段合同（不是正式 JSON Schema）

原 v009 的 review 报告没有独立的 \`review.schema.json\`。下表是从 \`review()\`、\`select_method()\`、\`verify_material_review()\` 的直接读取和条件判断还原的运行时字段合同。字段要求按结果分支生效，不应误读为每一项都在所有审查阶段必填。

| 字段 | 必需条件 | 当前校验/用途 | 限制或未覆盖 |
|---|---|---|---|
| \`model\` | 每次 review | 必须严格等于 \`gpt-6.2-sol\` | 是报告自报值，不是已认证模型身份 |
| \`invocation_id\` | 每次 review | 非空；与 history 中既有值不得重复 | 没有验证它对应独立会话、真实调用或外部签名 |
| \`evidence_sha256\` | 每次 review | 必须等于当前 \`evidence_hash()\` | 证明绑定的文件版本一致，不证明内容真实/正确 |
| \`reason\` | 每次 review | 非空字符串 | 未强制结构化的论证步骤、反证或证据定位 |
| \`question\` | 每次 review | 非空；后续写入 state.question | pass/missing_data 还受 research_case 和 freeze 一致性约束 |
| \`outcome\` | 每次 review | 由分支和 \`route()\` 解释 | 没有独立 schema enum；缺失/未知值会在运行中报错 |
| \`academic_value\` | pass、academic_pass、missing_data、materials_pending | 必须等于 \`pass\` | 学术失败类别由 outcome 路由；代码未要求这些失败结果再提供一个显式 academic_value 状态 |
| \`data_feasibility\` | pass、missing_data | pass 必须为 \`pass\`；missing_data 必须为 \`blocked\` | 其他 outcome 没有统一枚举校验 |
| \`research_case\` | reality_first 且 outcome 为 pass/missing_data | core_question、context、hypotheses_or_propositions 按条件校验 | 不是所有早期 academic_pass 都需要该对象 |
| \`method_assessment\` | method_paths=true 且 outcome 为 pass/missing_data/materials_pending | 必须覆盖三条路径、状态和理由；按结果校验 selected | 由运行时代码检查，没有独立报告 JSON Schema |
| \`archive\` | missing_data | run、question 与当前研究一致；archive() 另要求 core/question/value/literature/missing/access/run/review 八项非空字符串 | 归档只记录确认不可行的潜在选题，不代表学术通过 |
| \`design\` | S08 freeze | 非空字符串 | 在 review() 本身不强制；在 freeze() 才强制 |

**schema 检索结论：**
- 在原 v009 目录未发现 review 报告专用 JSON Schema。
- \`10_共享证据与契约/v002_第2版/schemas/records.schema.json\` 的标题是“定量社会学核心交换记录”；它定义 source/paper/evidence/hypothesis/claim 等记录，并在部分记录上使用 \`review_status\`。它没有定义上述 v009 review 报告对象，也不是 \`staged_topic.py\` 的 review() 验证器。
- 因而本文只能称为“代码实际执行的字段合同”，不能称为“已有正式 JSON Schema”。后续如需引入正式 schema，必须单独授权并与当前运行时合同对照，不能在本任务擅自补造 schema 文件。

## 4. 定性材料真实回执门禁

**源码：** \`method_paths.py:L26-L61\`。

当 \`qual_search_receipts=true\` 时，\`review()\` 对 \`secondary_interviews\` 和 \`online_qualitative\` 的方法判断调用 \`verify_material_review()\`。只有 status 为 ready 或 missing 才进入实际回执校验；unknown/not_applicable 不会伪装成已验证。

| 核验项 | 必需条件 |
|---|---|
| 搜索批次 | \`search_attempt\` 必须匹配 \`attempt_NNN\` |
| 原始回执 | 存在 \`qualitative/attempt_NNN/material_receipt.json\` 与 \`conversion.json\` |
| 回执身份 | receipt.run_id 等于当前运行目录名 |
| 回执状态 | receipt.status 必须是 \`pending_independent_review\` |
| 工具证据 | receipt.tool_events 非空 |
| 哈希 | receipt 原始字节哈希等于 decision.receipt_sha256；conversion 规范化哈希一致；events.jsonl、response.json 哈希分别与 receipt 中记录一致 |
| 问题复用 | conversion.new_question 必须与当前 question 一致；否则需明确 \`reviewed_reuse\` |
| missing 判断 | 必须提供 \`search_assessment="reasonable_but_insufficient"\`，说明是合理搜索后材料不足 |
| ready 判断 | decision.materials 中每个 material_id 必须属于该路径的真实 receipt.materials |

该合同提高了材料判断的可追溯性，但 receipt.status 明确仍为 pending_independent_review；它是搜索/材料收集回执，不是最终独立审查者身份凭证。不能将工具事件存在等同于学术审查完成。

## 5. 证据哈希绑定合同

**源码：** \`staged_topic.py:L420-L435\`；审查调用位置：\`L317-L325\`。

\`evidence_hash(work,state,source,theory)\` 对以下当前文件内容组成对象后计算 digest：

| 证据组成 | 纳入条件 | 校验 |
|---|---|---|
| papers | 始终纳入；初审/设计阶段为 initial/literature_matrix.json，final 为 merged_literature.json | 读取当前文件内容 |
| theories | 始终纳入 initial/theories.json | 读取当前文件内容 |
| reality | \`reality_first=true\` | load_reality() 核验 reality.json 与 state.reality_sha256 |
| explanation_exchange | \`explanation_first=true\` | 重新计算 explanation_exchange.json digest，必须等于 state.exchange_sha256 |
| issue_plan | \`issue_search=true\` | issue_plan() 核验 issue_plan.json 与 state.issue_plan_sha256 |
| event_comparison | \`issue_search=true\` | 重新计算 event_comparison.json digest，必须等于 state.event_comparison_sha256 |

报告的 evidence_sha256 必须等于该组合证据的当前 digest。final freeze 再次重算 evidence hash，并要求 history 最后一条报告的 evidence_sha256 与当前值一致、question 与 state.question 一致；成功后写入 s08_topic.json 的 evidence_sha256 和 review_sha256（最终报告 digest）。

**解释边界：** 哈希只回答“审查时绑定的文件是否与当前文件一致”。它不证明文件中每条事实真实、不证明文献解释正确、不证明材料充分，也不证明生成报告的主体独立。

## 6. 审查结果与状态路由

**源码：** \`staged_topic.py:L66-L78、L340-L373\`。

| 报告 outcome | 代码路由/处理 | 顶层状态或结果 | 是否学术通过 |
|---|---|---|---|
| academic_pass | 仅限非 final 且当前状态不是 design_review；追加 history、更新 question | design_review | 只通过初步学术价值门槛；不代表材料可行 |
| pass（初审/设计阶段） | academic_value=pass、data_feasibility=pass；方法门禁通过 | supplemental；记录 initial_sha256 | 通过当前学术与材料门槛，可补查 |
| pass（最终审查） | 同上；最终材料和方法门禁通过 | s08_ready | 通过最终审查，仍需 freeze |
| concept | route() 映射 | S02；既有学术失败次数达到阈值时 eliminated | 学术退回 |
| value | route() 映射 | S03；既有学术失败次数达到阈值时 eliminated | 学术退回 |
| depth | route() 映射 | S06；既有学术失败次数达到阈值时 eliminated | 学术退回 |
| increment | route() 映射 | S05；既有学术失败次数达到阈值时 eliminated | 学术退回 |
| materials_pending | 方法评估须至少一条 unknown，selected 为空 | materials_pending | 未通过；等待核验 |
| missing_data | data_feasibility=blocked、所有适用方法路径 missing、archive 合同完整 | archived | 不是学术通过；确认材料不可行后归档 |
| technical | route() 返回 retry_technical | 顶层状态保持原审查状态；但报告仍追加 history、更新 review_phase/question | 不是学术结论，不计入 ACADEMIC 失败次数 |
| 其他未知 outcome | route() 抛出 Unknown outcome | 不应推进 | 不接受 |

\`route()\` 对 academic failure 的阈值统计的是**当前报告之前** history 中已有的 concept/value/depth/increment 记录；若此前已至少两次，本次学术失败进入 eliminated。technical、materials_pending、missing_data 不计入该学术失败计数。

### 6.1 missing_data 的归档附加合同

\`archive()\` 要求以下八项均为非空字符串：\`core\`、\`question\`、\`value\`、\`literature\`、\`missing\`、\`access\`、\`run\`、\`review\`。其中 run/question 必须分别与当前 state.run_id、报告 question 一致。去重 key 由 normalize(core) 与 normalize(question) 的 SHA-256 前 20 位生成；重复记录幂等返回，否则追加到潜在研究选题库。
