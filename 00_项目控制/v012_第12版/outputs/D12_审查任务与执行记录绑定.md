## 合同

[review_result.schema.json](../schemas/review_result.schema.json) 升为 schema_version=3，保留 D10/D11 裁决与证据要求，明确拒绝旧版本。新增 reviewer（executor、reviewer_id、model、invocation_id）与 execution_id；非 unable_to_review 均须明确填写，无法获得身份时 unable_to_review 可同时为 null。两者均只是声明，不证明真实身份。

独立选定的 execution_binding（同 schema 的 $defs）由接收方在实际执行后保存为独立文件：schema_version=1、execution_id、task_snapshot、reviewer、report（实际文件 path/sha256）、status（completed/failed）、records（角色、实际原文件 path/sha256）。报告只引用执行 ID，而非事后回执哈希，避免循环哈希；回执从外部绑定报告与原始记录。不得由模型自行构造独立绑定或用模板冒充真实记录。D14–D20 负责实际派发、身份及原事件验真。

## 接收核对

[review_binding.audit_review_binding](../tools/review_binding.py)：

1. 调用原 C04 task_packet.verify_snapshot，由其核当前 research_id、stage_id、task_id、snapshot_sha256、冻结输入、依赖及原研究/政策；报告必须精确对应接收方独立选定的快照。
2. 从当前 run 读取实际报告，核对 schema；只允许读取独立指定且已在 input_files 冻结的 D09 context，核对问题与所有 artifact 文件引用，调用 D11 evidence audit。
3. 调用者独立传入 expected_execution_ref（回执路径+SHA），重算回执、报告及各原文件字节，核 reviewer、execution_id、任务快照与报告引用完全一致；相对路径/命名空间、文件重复和自引用检查；Codex events/response 须同 attempt。completed 的 Codex 需 events/response，Chat 需 session_record，manual 需 manual_record。仅失败/无法审查情形可保留不完整记录。
4. 无独立选定回执时非 unable_to_review 拒绝；unable_to_review 可返回 pending_missing_execution_binding。失败执行不能提交完成裁决；所有返回 formal_eligible=false、independent_review_verified=false。即使文件与身份声明一致也只为 review_records_hash_bound_pending_independence，不证明实际会话、真实模型、独立性或语义正确，更不调用原 review/写作放行。

保留 C15 记录与模型自报隔离原则；原 C result_bundle 用于检索结果，不能用其来源候选计数代替审查结果。原 v009 review 的 model/invocation/evidence hash 约束继续存在，本项不擅自替换原报告或状态机。
