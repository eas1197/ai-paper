## 一、各类证据的单位、可成立的主张与不可越界处

| 单位/路径 | 实际数据/回执 | 代码所能支持的结论 | 禁止直接升级的判断 |
|---|---|---|---|
| **现实来源**（reality） | `autopilot_v3.source_proof()` 对来源 URL 校验 HTTPS 和 `url_event`，后交原 v009 reality 入口 | 本轮 Codex 原生搜索事件中可以关联该 URL | 不能仅凭 URL 出现就推定已打开/读完，也不能把政策描述等同真实行动（详 B09） |
| **事件**（event） | `event_protocol.compare_events()` 要求事件 `identity` 非空且互不重复；每个事件包含多个 `facts` | 有去重的“事件身份”及其逐条归属陈述，可供比较 | 同一事件的不同转述不能算多个独立事件；同一报道中的两个段落不能自动视为两个独立事实来源 |
| **事实陈述**（fact） | 每条有 `source_id`、`statement`、`use`、`key` 和 `status`；source_id 指向 HTTPS URL；状态枚举 `corroborated/single_account/unverified/contradicted/inference` | 逐条标记该说法声称的可信度和拟支持的研究用途；只有声明为 `corroborated` 的条目进入 `retained_facts` | `corroborated` 是报告提供的标签，函数本身**不核实**是否有相互独立的佐证来源；即使进入 retained 也不是“独立学术确认事实” |
| **事件缺口**（critical_gaps） | 对不属 `corroborated` 且 `key=true` 的事实陈述汇成缺口清单；`interpretation_status=pending_independent_review` | 单方叙述、未核、矛盾和推论可被保留为不确定证据与关键待核点 | 不得把 `uncertain_facts`、`inference` 或反驳未决直接转写成确定性因果解释 |
| **06 检索材料**（material） | 06/v005 `response.json.materials[]` 必须具有 `url,date,subject,context,kind,path,locator,relation,limits,access`；`read_materials()` 增加 `event_id`、`material_id=digest(row)[:16]`，保存搜索 events/response SHA 与 gaps | 有与本次原生搜索回执关联的资料记录；可在框架维度中明确引用材料 | URL 命中不保证真实打开或文中行为得到验证；材料 ID 是**记录哈希**，不是天然的独立事件 ID；来源互相转述或重复事件不能据此视为独立案例 |
| **矩阵维度**（dimension） | `framework.dimensions[]` 的 `id,name,deduction,proposition,needed_material,relationship`；`analysis_matrix()` 以 `dimension_id` 逐一覆盖全部维度 | 可在稳定框架内逐维度组织分析和所需证据 | 维度是理论问题/分析单位，不等于发生的行动事件或实际取样单元 |
| **矩阵证据关系**（evidence） | 每项须引用当前 receipt 内的 `material_id`，关系类型为 `support/counterexample/competing/context`，有非空 reason，并回填原材料 URL、locator、kind | 保留支持、反例、竞争解释和语境资料的不同分析角色 | 标成 `support` 也只代表矩阵里*主张*该材料支持，程序没有按语义核实原始材料实际能证成该命题 |
| **矩阵结论**（finding） | 每个维度有 `conclusion,boundary,unresolved,alternatives` 与 `status=tentative/unresolved`，最终矩阵 `theoretical_increment_status=proposed`、`status=pending_independent_review` | 允许有界的探索性结论或明确悬置 | 不得把暂定结论、理论增量 proposed 或 pending 矩阵当作已经实证证实/正式学术通过 |

## 二、06 材料类型、访问范围与来源核验

`qual_materials.KINDS` 定义五类：`actor_statement`（行动者自述）、`reporter_account`（记者转述）、`official_rule`（制度/官方规则）、`documented_action`（有记录的行动）以及 `researcher_inference`（研究者推断）。**采集 schema 明确排除 `researcher_inference` 作为可采事实材料**，`read_materials()` 同样排除该类。两条允许的经验路径为 `secondary_interviews` 和 `online_qualitative`。

**来源核验已实现：** `read_materials()` 读取 `events.jsonl` 并调用 `url_event()`，要求每项来源在本次原生搜索事件中可关联；每个必填字段需非空，路径与材料种类需处于枚举内。返回 `status=pending_independent_review`，连同原始事件/响应 SHA、有效/排除材料、`search_notes`、`gaps` 持久化。框架定向采集另要求初查回执及 conversion/framework 等哈希链匹配。

**仍是弱校验：** `date`、`locator`、`limits`、`access`、`relation` 等字段当前只检查非空，未在 `read_materials()` 中验证其语义是否可信、所述行动是否发生、资料是否真正可用于研究或许可是否获准；`url_event()` 可由搜索结果命中支持（参见 B09）。题录、规则文本、记者转述、公开自述必须保留其不同证据强度。

原采集 prompt 明确要求：优先找行动过程、互动/决策及反例；区分行动者陈述、记者转述、官方规则与实际行为；不要把制度文本当作行动、不要把网页检索冒充民族志；记录访问边界、未命中及不符合预期。开启 `--event-focus` 时强调亲历事件、矛盾与缺失、相同事件转述合并，并把官方材料原则上用于背景核实。**这属于对采集模型的明确指令，不等于程序已经逐条执行上述语义审查。**

## 三、反例、竞争机制和“未知”的硬约束

`framework.analysis_matrix()` 的**代码强制**：
- 框架包含非空 `core_question`、`core_concept`、现有解释、局限和增量等上下文字段；各维度 ID 唯一、字段完整；
- 使用且只使用该次 `framework_collection` receipt，要求 `receipt.status=pending_independent_review`、`framework_sha256=digest(framework)`；
- 每个维度必须恰好出现一行；行的每条证据都必须来自该 receipt 的 material_id，关系仅允许 `support`、`counterexample`、`competing`、`context`，并要求非空理由；同一维度内不能重复引用同一 material_id；
- 每行强制具备 `conclusion,boundary,unresolved,alternatives` 文本；若没有可用证据，只能 `status=unresolved`，不能直接输出 `tentative`；矩阵始终标 `pending_independent_review` 且理论增量始终为 `proposed`。

**注意三个重要缺口：**
1. `analysis_matrix()` 不强制每个维度至少有一条 `counterexample` 或 `competing`，也未核实为什么某项被标成支持/反例；要求寻找反例来自 prompt、理论与审查原则，**不是完整的可执行覆盖门槛**。
2. 对**有材料但全部是 `context`** 的维度，源码仍允许 `status=tentative`：它检查“证据列表非空”而不是“至少存在能够支持或反驳命题的实证关系”。不能把背景规则直接提升成核心论点证据。
3. `material_id` 由整条材料字典的 digest 截断生成，不按事件实体去重。某些重复转载可产生不同 ID；源码没有全局“独立事件数/行动数”强制核验。对一份材料的多条记录或相同事件多源转载，不可当作多独立事件。

## 四、独立评审、材料适足性及冻结问题的接续

- **方法可行性不是论证适足性。** `method_paths.verify_material_review()` 会检查定性选择报告中的 `search_attempt`、`receipt_sha256`、原 events/response、conversion 和当前路径上的材料 ID；`select_method()` 的 `ready` 还要求非空材料及 `access=verified`（在线民族志另须 `observation=verified`）。这些主要是字段/哈希/路径约束，不能替代真实访谈或观察。
- **矩阵通过还须审查与适足性判断。** `resume_writing.resume()` 调 `question_binding.binding()` 锁定 S08 与来源，拒绝 receipt/framework/矩阵哈希不符。审查报告若非 `pass` 则停止；若没有 `material_adequacy` 返回 `awaiting_material_adequacy`。调用 `writing_material_status()` 时，`eligible_event_ids` 必须是当前 receipt 中互不重复且存在的 material_id，`support` 仅可 `sufficient/insufficient/unknown`，且必须有理由；`sufficient` 需至少一个 ID 才能 `ready`。其他结果停在 `insufficient_core_material` 或 `awaiting_material_adequacy`。
- **还不能将材料 ID 等同已验证独立事件。** `eligible_event_ids` 的代码只检查字符串、列表唯一性和其作为材料 ID 的成员资格，未从原始事实独立验证事件身份、重复转述、证据与冻结问题的实质回答关系。审查主体自报 `model`/调用号不自动证明独立身份。
- **反例与修复不允许改题。** `resume_writing` 的矩阵整改要求保留 `unresolved` 与 `alternatives` 并使用既有材料/定向补材，`question_binding.binding()` 要求 S08 frozen question、conversion new_question、框架核心问题和原始凭证一致。核心研究问题或研究设计必须变更时，不能在矩阵/写作阶段自行覆盖 S08；须回原阶段审查、形成新冻结版本。
