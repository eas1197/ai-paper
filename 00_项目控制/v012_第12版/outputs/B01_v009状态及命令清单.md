## 1. 状态字段与判读口径

研究运行状态保存在运行目录的 `staged_topic.json` 的顶层 `status` 字段。新运行由 `init()` 创建，初始值为 `reality`，并初始化空的 `history`；源码没有集中式状态枚举，状态需要从赋值、判断和路由函数中归纳（`staged_topic.py:L79-L97`）。

下表只列**顶层研究状态**。文献批次的 `batch.status`、采集结果的 `bundle.status`、以及控制器返回的 `action` 均不是该顶层状态字段。

| 顶层状态 | 作用与进入条件 | 后续处理 / 边界 |
|---|---|---|
| `reality` | 新运行初始状态；等待记录现实观察 | `record_reality()` 完成后转入 `explanation_exchange`（当前初始化默认） |
| `explanation_exchange` | 现实观察后，等待解释与反诘材料 | `exchange` 分支验证并保存材料后转入 `issue_positioning`（当前初始化默认） |
| `issue_positioning` | 等待社会学议题定位方案 | `record_issue_plan()` 完成后转入 `initial` |
| `initial` | 初查阶段；也是部分前置标志关闭时的回退入口 | 初查达到有效摘要目标且理论材料非空后转入 `preliminary_review`；否则保持当前状态或进入预算停止 |
| `preliminary_review` | 初查后的初步学术审查 | 审查可进入 `design_review`、`supplemental` 或相应退回/等待状态 |
| `design_review` | `academic_pass` 后的研究设计审查 | 再次提交审查；通过后进入 `supplemental` |
| `supplemental` | 补充检索阶段 | 合并后的有效文献达到初查与补查目标总和后转入 `final_review` |
| `final_review` | 补查后的最终学术审查 | 正向通过后转入 `s08_ready` |
| `literature_budget_exhausted` | 文献目标未达成且批次/搜索预算耗尽，或采集器报告实验预算超限 | 只有开发模式且原检查点、文献集合哈希吻合并仍有批次额度时，才可恢复到原检索阶段；否则保持停止 |
| `materials_pending` | 审查判定材料仍待补充 | 属于可再次提交审查的状态，不等于通过 |
| `S02` / `S03` / `S06` / `S05` | 学术审查退回状态，分别对应概念、价值、深度、增量问题 | 均在审查允许状态集合中，可再次提交审查 |
| `archived` | 审查判定数据不可得并完成选题归档 | 当前控制器不再允许该状态进入学术审查或检索推进 |
| `eliminated` | 学术失败累计达到淘汰阈值 | 当前控制器不再允许该状态进入学术审查或检索推进 |
| `s08_ready` | 最终审查正向通过，具备执行 S08 冻结的前置条件 | 仍需调用 `freeze()` 并重新核对证据、问题、设计及方法 |
| `frozen` | S08 冻结文件已写入，顶层状态更新为冻结 | 本源码写入的 `formal_eligible` 仍为 `False`；不能将状态冻结解释为生产资格或端到端验收通过 |

状态来源：初始化与状态字段（`L79-L97`）；审查路由及学术退回映射（`L27-L30`、`L64-L76`）；检索与预算（`L145-L220`、`L223-L311`）；审查（`L314-L373`）；冻结（`L375-L398`）。

## 2. 状态转移表

| 当前状态 | 触发位置 / 函数 | 条件与动作 | 转移结果 |
|---|---|---|---|
| 新运行 | `init()` | 创建 `staged_topic.json` | `reality` |
| `reality` | `record_reality()` | 现实材料含现象、检索焦点和可追溯来源；写入材料及哈希 | 默认 `explanation_exchange`；若 `explanation_first` 关闭则为 `initial` |
| `explanation_exchange` | `main()` 的 `exchange` 分支 | 校验反诘材料；启用议题检索时还核验事件比较 | 默认 `issue_positioning`；若 `issue_search` 关闭则为 `initial` |
| `issue_positioning` | `record_issue_plan()` | 议题、理由及对象/议题/理论三层检索字段齐备，保存方案与哈希 | `initial` |
| `initial` | `search()` | 初查有效记录达到本阶段目标、理论材料非空，且采集器未报告实验预算超限 | `preliminary_review`；条件未满足则不因本次检索自动转审 |
| `supplemental` | `search()` | 合并文献达到初查与补查目标总和，且采集器未报告实验预算超限 | `final_review`；条件未满足则不因本次检索自动转审 |
| `initial` / `supplemental` | `advance()` | 目标未达成且批次/搜索动作预算耗尽，或采集器报告实验预算超限 | `literature_budget_exhausted` |
| `literature_budget_exhausted` | `advance()` | 仅开发模式；检查点和集合哈希与停止记录一致；当前批次上限仍低于开发配置上限 | 恢复到停止前的 `initial` 或 `supplemental`，并记录 `budget_resume`；否则返回 `already_stopped`，状态不变 |
| `preliminary_review` 或可审查退回状态 | `review()` | 审查结果为 `academic_pass`，且不是最终审查/重复设计审查 | `design_review` |
| 初步审查上下文 | `review()` | 审查结果为 `pass`，且数据可行性通过；完成初查审查记录 | `supplemental` |
| 最终审查上下文 | `review()` | 审查结果为 `pass`，且数据可行性通过；完成最终审查记录 | `s08_ready` |
| 任一允许审查状态 | `review()` → `route()` | 结果为 `materials_pending` | `materials_pending` |
| 任一允许审查状态 | `review()` → `route()` | 结果为 `missing_data`；数据可行性为 blocked，归档字段与本次研究/问题一致并成功归档 | `archived` |
| 任一允许审查状态 | `review()` → `route()` | 结果为 `concept` / `value` / `depth` / `increment` | 分别转入 `S02` / `S03` / `S06` / `S05`；当前失败前历史中已有至少两次学术失败时，本次转为 `eliminated` |
| 任一允许审查状态 | `review()` → `route()` | 结果为 `technical` | 返回 `retry_technical` 动作，但不改写顶层 `status`；状态留在原审查阶段 |
| `s08_ready` | `freeze()` | 最终正向独立审查、证据哈希、问题、研究设计及方法交接均匹配 | `frozen` |

关键代码定位：

- 现实观察：`record_reality()`，`L407-L417`。
- 解释反诘、议题定位：`main()` 的 `exchange` 分支，`L527-L540`；议题方案转初查：`record_issue_plan()`，`L112-L127`。
- 初查/补查转审：`search()`，`L145-L220`。
- 预算停止、恢复与续跑：`literature_next()` / `advance()`，`L223-L311`。
- 审查入口、审查结果和退回：`review()`，`L314-L373`；结果映射：`route()`，`L64-L76`。
- S08 冻结：`freeze()`，`L375-L398`。

## 3. 非持久状态与容易混淆的返回值

以下字符串会出现在函数返回值或采集器结果中，但**不是顶层 `staged_topic.json["status"]` 的状态**：

- `passed`：`route()` 对审查通过的内部路由结果；随后由 `review()` 转成 `supplemental` 或 `s08_ready`。
- `retry_technical`：技术失败时的返回动作；`review()` 不将其写入顶层状态。
- `verify`、`stop`、`resume_deficit`、`wait_for_theory_evidence`、`already_stopped`、`wait_for_stage_input`：`literature_next()` / `advance()` 的调度动作。
- `experimental_budget_exceeded`：采集器的 `bundle.status`；控制器据此将顶层状态改为 `literature_budget_exhausted`。
- 文献批次的 `completed` / `failed`：批次状态，不是研究阶段状态。

因此，不能把返回动作、采集器状态或批次状态直接补入顶层状态表。

## 4. 状态读取与持久化

`main()` 在运行锁内读取 `staged_topic.json`，并核对策略哈希、运行模式和 run_id（`L486-L513`）。`status` 命令没有独立修改分支：`result` 保持为空，最终通过 `json.dumps(result or state)` 输出当前状态；同时 `status` 与 `prepare` 被排除在状态文件回写之外（`L547-L549`）。其他非初始化命令在锁内处理后写回状态文件。

`prepare()` 只根据当前状态组织任务输入，不推进状态；状态推进由对应记录、检索、审查、预算恢复和冻结函数完成（`L438-L483`）。

## 5. 未确定处与范围边界

1. 源码没有集中式状态枚举或独立状态图；本表是对当前文件中赋值、判断和路由的静态归纳，不代表额外的 schema 约束。
2. `init()` 当前把 `reality_first`、`explanation_first`、`issue_search` 等流程开关初始化为 `True`；表中标注的 `initial` 回退分支是函数保留的条件路径，不是本轮默认路径。
3. `archived`、`eliminated` 在当前文件中没有后续恢复分支；依据现有审查入口与 `advance()` 的阶段限制，将其视为当前控制器中的停止状态。源码没有单独声明名为 terminal 的状态属性。
4. `frozen` 表示 S08 冻结文件写入成功，不表示 `formal_eligible=True`，也不表示材料、写作或端到端研究已经验收。
5. CLI 命令、参数、入口分发和完整调用表不属于 B01a，留给 B01b；本节只引用 `main()` 中读取和持久化状态所必需的代码。
