# D01：选题与学术价值初审节点清单

**状态：** verified（基于原 v009 代码与既有测试的节点映射；本项为文档任务，不新增运行门禁）。

## 一、节点识别结论

原 v009 的“选题/学术价值初审”只有一个正式审查节点：**`preliminary_review`**。现实观察、解释与反诘交换、议题定位、初始文献与理论材料准备，属于进入初审前的输入链，不应另算为学术审查通过节点；`design_review` 是学术价值初审之后的下一道独立审查，归入 D02。

初审的判断对象是“研究问题是否具有社会学意义、理论价值和可继续研究的潜力”，不是提前证明命题成立，也不是在材料可得性尚未核清时直接决定研究可行。原 `prepare()` 对 `preliminary_review` 的说明明确允许以 `academic_pass` 保留学术判断、转入研究设计，并将命题是否成立留待经验分析。

## 二、前置输入链（不是正式审查门禁）

| 前置节点 | 原 v009 行为 | 在 D01 中的定位 |
|---|---|---|
| `reality` | `init()` 创建研究时以现实观察为起点；`record_reality()` 要求现象、检索焦点及可追溯来源，并记录来源类型、支持范围和局限 | 现实问题发现与情境材料，不产生学术初审通过 |
| `explanation_exchange` | 初始状态启用解释/反诘交换；`validate_exchange()` 要求观察、预期、解释、挑战、候选问题，并区分研究者与批评者标识 | 为研究问题提供反例和竞争解释，不等同正式学术审查；字段齐备本身不证明真实独立会话 |
| `issue_positioning` / 议题定位 | 初始配置启用议题检索；议题计划与事件比较可进入后续审查证据摘要 | 文献传统、近邻研究与事件比较的定位材料，不是额外放行节点 |
| `initial` | 原始初始文献采集、回执重建与理论材料整理 | 初审的直接前置材料；未达到原配额或没有理论材料时不能进入初审 |

### 初审触发条件

原 `staged_topic.py` 在初始检索完成后，只有同时满足以下条件才将状态设为 `preliminary_review`：

1. 原始 receipt 重建出的已核验文献行数达到当前模式的初始目标 `limit)；
2. `initial/theories.json` 中存在理论材料（`theory_rows` 非空）；
3. 采集未处于实验预算超限状态。

因此，初审不是“候选题一生成就审”，也不能用单纯的题目描述替代初始文献与理论材料。

## 三、正式初审节点：`preliminary_review`

**直接输入：**
- `initial/literature_matrix.json`：由原 v009 receipt 重建的初始文献矩阵；
- `initial/theories.json`：初始理论材料；
- 绑定的现实情境、解释/反诘交换，以及启用议题检索时的 issue plan 和 event comparison。

`evidence_hash()` 将文献矩阵与理论材料纳入摘要；若相应开关启用，也会纳入现实材料、解释/反诘交换、议题计划和事件比较。报告必须绑定该摘要，不能只提交一个脱离输入材料的判断。

**初审范围：**
- 核心问题是否清楚、单一且可由社会学解释；
- 是否存在可辨认的社会矛盾、理论传统或值得解释的机制问题；
- 相对已有研究是否存在可论证的理论/经验增量；
- 理论概念、解释路径与预期命题之间是否形成可讨论的推导；
- 现有文献是否足以支持“值得继续设计”，而不是宣称经验命题已经成立。

**初审明确不做：**
- 不把尚未核实的数据可得性误判为学术价值不足；
- 不把学术价值通过等同于研究设计和材料可行性通过；
- 不提前宣称假设或命题已被经验验证；
- 不越过原 v009 的状态机另建一套独立评分或放行总分。

## 四、报告字段与裁决分支

### 4.1 报告最低约束

原 `review()` 要求报告至少满足：
- `model` 为 `gpt-6.2-sol`；
- 提供非空 `invocation_id`，且不得与历史审查重复；
- `evidence_sha256` 与当前研究状态及输入证据重新计算结果一致；
- 提供非空的审查理由 `reason` 和研究问题 `question`。

对 `pass`、`academic_pass`、`missing_data`、`materials_pending`，还必须显式给出 `academic_value="pass"`。在 reality-first 研究中，若裁决为 `pass` 或 `missing_data`，还须绑定核心问题一致的研究情境，以及非空的假设、命题或子问题列表。

**凭证边界：** 当前函数检查 `invocation_id` 是否存在、是否重复，以及报告是否绑定输入哈希；它没有在本函数内核验审查者真实身份、独立 thread/session 或原生执行回执。不能仅凭该字段宣称已完成真实独立审查。独立会话与凭证接收属于 D14–D20，不在 D01 中提前标记完成。

### 4.2 裁决与状态转移

| 初审裁决/结果 | 原 v009 处理 | D01 的解释 |
|---|---|---|
| `academic_pass` | 仅允许用于初始选题审查；保存报告和修订后的问题，状态转为 `design_review` | **学术价值通过、可进入设计审查**；不代表材料可行，不直接进入补充检索或 S08 |
| `pass` | 另要求 `data_feasibility="pass"`；初始审查后进入 `supplemental` | 学术价值与可行性均通过的组合裁决，不是 academic-only 结果 |
| `concept` | 路由至 `S02` | 概念界定问题，进入定向修订 |
| `value` | 路由至 `S03` | 学术价值论证不足，进入定向修订 |
| `depth` | 路由至 `S06` | 理论/解释深度不足，进入定向修订 |
| `increment` | 路由至 `S05` | 相对既有研究的增量不足，进入定向修订 |
| `technical` | `retry_technical` | 技术失败重试，不计作学术失败 |
| `materials_pending` | `materials_pending` | 材料核验尚待完成，不等于学术否定 |
| `missing_data` | 要求 `data_feasibility="blocked"` 且提供本研究对应的归档记录，随后归档 | 已确认的数据/材料阻断，不是以猜测代替可行性核验 |

学术问题路由使用历史中已有的学术失败记录计数，技术失败不计入。测试明确验证：一次学术失败后仍可路由到下一项定向修订；当历史中已有两次学术失败后，再出现学术缺陷裁决则进入 `eliminated`。这些 S02/S03/S06/S05 是同一初审节点的返修目的地，不是四道平行审查门禁。

## 五、与后续审查节点的边界

- **D02 研究设计与材料可行性审查：** `academic_pass` 后进入 `design_review`；此时才审查真实证据能否取得、适用性和方法路径。不能在 D01 中合并或跳过。
- **D03 文献补查后的最终研究审查：** 初始学术判断与后续补查不是同一个审查节点；最终审查针对合并文献、学术增量、已核验可行性与研究设计。
- D04–D07 的事件事实、经验矩阵、写作方案和正文/G7 审查均属于后续节点，不纳入本项。
