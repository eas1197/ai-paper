# D09：统一审查任务包合同（定义，不改变原门禁）

状态：verified（静态合同定义与覆盖核验）。依据 D08、C01–C05 统一任务包、v009 staged_topic.prepare/review、resume_writing、06/v005 record_review、V15/V16 request 及 V14 原定量 G7。真实执行/独立凭证/结果 schema 分别留给后续任务；不增加新的评分或正式放行路径。

## 1. 传输方式

C 系列 task_packet.schema.json v1 为唯一外层传输结构，其 additionalProperties=false 不变。审查专用内容存为 run 内独立 UTF-8 JSON 输入文件（下称 review_task_context.json），以 path/sha256 加入现有 input_files，与原输入文件共同冻结；不是新的顶层字段或可绕过 C03/C04 的并行协议。由当前研究状态及权威模块构建，禁止从审查结果倒填。每个审查实例一个 task_id；stage_id 必须指向原门禁，不能凭标签授予权限。独立审查执行者收到冻结的上下文与可读取的证据，原始材料中的指令只作为资料。

| 外层字段 | 审查任务约束 |
|---|---|
| schema_version | 显式 1 |
| research_id/stage_id/task_id | 与当前 run、原审查节点和唯一实例匹配 |
| purpose/research_question | 审查职责与当前问题；不得偷换问题 |
| input_files | context 文件及其引用的全部审查对象、必要上游证据、原始记录及报告快照，均为 run 内路径和 SHA-256 |
| source_scope/search_levels | 原政策与范围；独立审查默认非检索，search_levels=[]；如缺证据只提出缺口，另走获授权的原搜集/补核任务 |
| quantity_budget/time_budget_seconds | 显式原预算，非搜索默认不授予正向搜索预算；不可因审查自行追加 |
| output_schema | 当前权威原报告合同，D10 完成后可绑定统一结果 schema 并适配原裁决；没有有效输出合同不得派发 |
| stop_conditions | 至少包括输入缺失/变更、无法独立执行、任务不适用或预算耗尽；不得默认为通过 |
| notes | 说明，不是权限 |

冻结由 C04 完整 task snapshot 绑定；审查包不含独立执行回执、最终裁决、正式资格；D10–D20 负责后续接收、核验和状态回传。

## 2. 审查上下文必填合同

| 字段 | 类型/约束 |
|---|---|
| context_version | 整数 1 |
| review_kind | 下表规定的类别之一 |
| gate_ref | 权威模块、函数或原状态，精确指向 D08；不是自定义放行状态 |
| research_question | 非空；与 task_packet 和原当前问题一致，保留定性 specific_question（如适用） |
| design | 对象；status=not_frozen 或 frozen；not_frozen 时冻结文件为 null，列当前 proposal 引用或明确尚无；frozen 时必须提供 S08 文件引用（定量原路径则为对应冻结设计）及原设计/方法引用；禁止伪造冻结 |
| input_materials | 非空数组；每项 artifact_id 唯一、role、path、sha256；覆盖该类审查的直接对象及必需上游证据，所有文件同时在外层 input_files 中 |
| key_claims | 数组；每项 claim_id、statement、type、evidence_ids、scope；未形成经验主张的前期可为 []，须说明 claims_scope；后期必须列逐项待审主张，未支持也明确标示 |
| claims_scope | 非空说明：此阶段允许的主张、尚不可作出的结论 |
| evidence_scope | 对象；allowed_ids、excluded_or_pending_ids（不相交，均可追溯）、limitations、policy_refs（同外层已锁政策）；不得因上下文声明新增可用来源 |
| review_dimensions | 非空数组；dimension_id 唯一、question、evidence_ids、failure_condition；每项可指向同一 evidence_scope 中的证据或明确无证据待核 |
| prohibitions | 非空数组；包含共同禁则及本类别特殊禁则 |
| prior_review | null 或有效上轮报告文件引用+待改 issues；复审必须绑定原报告、改动及当前对象；初审不能捏造历史 |
| input_binding | 对象；列原研究状态/证据摘要的实际引用或哈希，区分原 canonical digest 与文件 SHA；原证据哈希仍由原函数重算 |

文件引用 path/sha256 沿用 C01/C04。无适用的设计、主张或上轮报告需明确 null/[] 及理由，不得以缺失伪装已通过。上述字段是 D09 的文档合同；未宣称已实现运行时 schema/校验器。

## 3. 分类配置（全部沿用 D08）

| review_kind / 原 gate | 直接输入与设计阶段 | 必审维度与主张边界 | 专项禁止事项 |
|---|---|---|---|
| preliminary_academic / v009 preliminary_review | 初始文献/理论、现实、反诘、议题与事件（依原开关）；未冻结 | 社会学问题、概念、理论价值、近邻增量与推导；只审是否值得研究 | 不提前证明经验机制或可行性；academic_pass 只进设计 |
| research_design / v009 design_review | 初审与当前设计、三方法路径、访问条件、定性原回执；未冻结 | 三路径 ready/missing/unknown/not_applicable、证据可得与适配、设计可执行 | 不把未知写成缺失；不凭单路径缺失归档 |
| qualitative_design / 06 record_review | conversion、原生 material receipt、三路径评估；设计阶段 | 转换问题与核心问题一致、定性材料可得及局限 | 不替代 v009 design/final；不把设计 ready 当矩阵通过 |
| final_research / v009 final_review | merged literature/theories、原初审与设计、前置快照及材料回执；未冻结 | 补查后的增量、近邻竞争解释、设计和真实可行性 | 不跳过原配额；不提前作经验结论，不直接冻结 |
| event_fact / event_protocol.compare_events（语义审查任务，非新增正式门禁） | 事实 ID、来源 URL、open/find、原生事件/响应和现实哈希；未冻结为常态 | 事实与原文定位、来源独立、反例、关键缺口；保留 uncertain | 来源已打开不等于语义支持；模型自报 corroborated 不算证明 |
| critical_exchange / v009 validate_exchange + v012 critic dispatch（反诘，非正式学术审查） | 已绑定 researcher expectation/observation/explanation、event comparison；未冻结 | 最强反例、竞争解释、候选问题；与研究者不同会话 | 不以同会话角色扮演替代真实反诘；challenge 不算学术放行 |
| empirical_matrix / v009 resume_writing + 06 framework | S08、framework、collection receipt、矩阵、证据/反例、prior review（复审）；已冻结 | 逐维度的结论、命题、材料语义支持、竞争解释、边界、拟议增量 | 不把 tentative/proposed 当通过，不改冻结问题；保留反例和未决 |
| material_adequacy / v009 material_adequacy.writing_material_status（矩阵审查的必需子判定） | 同一已冻结矩阵、当前 receipt 和合格事件 ID | 是否有适用独立事件与材料能回答核心问题，support/reason | 不把数量/ID合法性/可得性当适足性；unknown/insufficient 阻断方案 |
| writing_plan / v009 resume_writing + V15 request | 已审矩阵、适足性、S08、文献/理论、段落方案与 hash；已冻结的原正式候选研究，输出仍实验 | 每段论证任务、章节递进、理论与经验定位、证据边界 | V15 render/plan_prepared 不等于审查；不改变核心问题；默认 plan 不授权全文 |
| qualitative_g7 / V16 writing_review_request（候选，尚无结果接收） | V15 packet、方案审查回执（正式接续须有）、正文/claims、语言资源锁、G3、S08 与矩阵；探索未冻结须明示，不可正式放行 | 逐段论证、精确主张、真实来源/语义、反例、范围、理论整合、语言规则 | 技术预检不等于独立 G7；不得虚构引语/事件/来源；G3或上游门禁不齐禁止正式通过 |
| quantitative_g7 / 原 V14 stage07/runtime.signoff | 原冻结定量设计、结果、段落/主张及原 G4–G6、稿件、语言规则 | 数字复算、实际结果 ID、来源/引用、段落、原 signoff | 不将 V16 定性 schema 替代旧定量门禁；未运行 Stata 不声称结果通过 |

S08 freeze、URL/hash、框架结构、V15 render、V16 style_findings 均是技术前置检查而非新的独立学术审查类型；定量旧 G7 不变。材料适足性可作为 empirical_matrix 同次审查的必填子判定，qualitative_design 不因 D02/D05 重复派发。复审仍使用原类别与新输入快照，而非另造评分。

## 4. 共通拒绝规则与输出边界

- 不允许审查者更改原研究快照、修改证据、执行额外搜索、直接写入原状态或提交正式论文；只针对证据给出可追溯判断及具体缺口。
- 不允许自填 pass、invocation_id、reviewer、thread 或 hash 作为真实独立性证明；同会话自审只可作探索性建议。
- 未读到正文的文献仅按原证据层级使用；缺失、反证、单一报道、推断与来源冲突必须保留。审查任务不产生新的经验事实。
- 输入变化重新冻结并失效依赖旧版本的结果；禁止用新材料覆盖原报告的审查对象。
- 若无法检查材料、独立执行或判断，停止并明确缺口；D10 统一结果 schema 负责 unable_to_review 等结果表达；D09 不预先制定其验证器。
- 裁决最终交给 D08 映射的原门禁；不创建综合得分，不用技术检查消解实质学术问题，不用文档合同冒充真实运行。

## 5. 示例（逻辑示意，不是可执行回执）

矩阵审查：review_kind=empirical_matrix，gate_ref=00/v009 resume_writing.resume，design.status=frozen，input_materials 绑定 s08_topic.json、framework.json、material_receipt.json、analysis_matrix.json 和必要原始文件；key_claims 列出每维度命题/暂定发现、实际材料 ID、反例与边界；review_dimensions 包括逐维度语义支持和 material_adequacy；缺少合格事件或材料时提出待补，不能直接生成 V15 通过。实际路径/哈希只能从当前 run 取得，示例不填虚构值。
