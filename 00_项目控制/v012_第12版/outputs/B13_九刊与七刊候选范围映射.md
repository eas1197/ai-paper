# B13｜v009 九刊搜索政策与 04/v012 七刊候选注册表范围映射

**状态：verified（静态配置、源码调用与入口映射；未运行真实检索/CLI）。**  
**分支：** `dev/v3.1-abstract-acquisition`。  
**范围：** 只核对 v009 `search_policy.json`、04/v012 七刊 Codex 原生检索注册表、其直接调用入口，以及 v012 strict/autopilot 对原 3.x 搜索路径的转发。依据 B08 的期刊/去重基线；不重做配额或去重审计，不修改期刊名单、搜索配置、模块注册或生产入口；不执行 B14/B15。

## 一、结论

1. **名单关系：七刊是九刊的严格子集。** 七刊包含九刊中的全部七本中文期刊；九刊另外包含 `American Sociological Review`（ASR）和 `American Journal of Sociology`（AJS）。不存在七刊替代九刊的证据。
2. **运行合同：两套名单服务不同入口。** 九刊是原 v009/v3.2 选题研究引擎的基础准入范围；七刊是 04/v012 `paper_codex_native` 独立、默认关闭的摘要检索候选配置。七刊入口要求配置名单与注册表名单完全相同。
3. **交叉依赖不等于名单继承。** v009 的 `staged_topic.py` 会导入 04/v012 的 `native_library.registry()`，并借其返回的模块路径定位摘要 schema；但 v009 实际检索白名单来自自己的 `POLICY["journals"]`（九刊），并未读取七刊的 `profile["journals"]`。因此不能因 v009 导入了七刊模块，就把原 v3.2 搜索误判为七刊。
4. **配置指针存在弱耦合。** v009 `search_policy.json` 有 `candidate_registry` 字段指向七刊注册表，但本轮检查的 `staged_topic.py` 和 v012 strict 入口没有直接读取该字段；`native_library.registry()` 内部另行硬编码读取同一候选注册表路径。当前两个位置一致，但不是通过一个动态引用/相等性校验形成的单一来源。
5. **不代表正式期刊准入。** 七刊注册表标记为 candidate、`enabled_by_default=false`、`native_search_abstract_only`；它只是检索入口配置，不是独立期刊质量认证，也不等于论文已通过原 3.x 正式准入。

**B13 判断：** 七刊是一个独立、可显式启动的 Codex 原生摘要检索候选入口；其当前期刊名单恰为九刊基础名单中的七刊中文子集。九刊仍是 v009 主研究流程和 v012 strict 原 3.x 路径的基础政策。七刊既不是九刊的替换版，也不是运行时自动从九刊计算出来的动态子集。

## 三、两个配置各自的真实含义

### 1. 原 v009 九刊政策

文件：`00_项目控制/v009_第9版/search_policy.json`。

- `profile="topic_v32_staged"`；
- `enabled_by_default=false`（该策略文件作为候选流程配置，不代表全项目默认启用）；
- `journals` 为九刊；
- `formal` 初查 5、补查 35；`dev` 初查 5、补查 5；
- `candidate_registry` 指向 `00_项目控制/v006_第6版/v3.1_Codex检索候选注册表.json`；
- `preferred_platforms` 中的 ASR/AJS 链接是推荐检索平台，不等于已对每一条检索结果完成出版商认证。

`00_项目控制/v009_第9版/tools/staged_topic.py` 的实际行为：
- `POLICY` 从 v009 自己的 `search_policy.json` 加载；
- `receipt()` 默认以 `POLICY["journals"]` 调用 `receive()`；
- `search()` 以 `POLICY["journals"]` 作为基础名单；存在议题定位方案时，再追加该方案中单独登记的 specialist journals；
- 生成检索 config 时把该名单显式写入 `config["journals"]`，随后交给 11/v007 `collect()`；
- 定性/专业刊分组的 `core_nine` 仍按 `POLICY["journals"]` 判断。

因此 v009 的九刊是原始基础白名单。专业刊只能在 issue plan 中另行提供 name、publisher_url、standing、fit 等字段后追加；这些字段校验的局限已在 B08 记录，本轮不重复审计或提高其资质。

### 2. 04/v012 七刊原生候选注册表

文件：`00_项目控制/v006_第6版/v3.1_Codex检索候选注册表.json`。

- `profile="paper_codex_native"`；
- `enabled_by_default=false`；
- `scope="native_search_abstract_only"`；
- 当前模块：04/v012、11/v007；身份模块：11/v006；
- `journals` 为上述七本中文期刊；
- `previous_registry` 指向旧的 AI/adaptive 候选注册链。

04/v012 `manifest.json` 将模块标为 `status="candidate"`、`scope="native_search_abstract_only"`、`profile="paper_codex_native"`。模块说明明确称其为“七刊 Codex 原生检索”，并给出独立命令：

```powershell
python -B -X utf8 .\04_议题文献与现实\v012_第12版\tools\native_library.py --profile paper_codex_native --work <独立作业目录> --theme <主题>
```

`native_library.py` 的关键限制：
- `registry()` 固定读取 Codex 候选注册表，检查 profile 名称、默认关闭状态及 04 模块路径；
- CLI 的 `--profile` 只允许 `paper_codex_native`；
- 读取配置后要求 `config["journals"] == profile["journals"]`，不匹配即报错 `Require the seven registered journals`；
- 默认 `native_request.json` 与 `native_100_request.json` 都配置同一七刊名单；
- 100 篇扩展需从同主题且经过 `accepted_20` 审查的 20 篇 pilot 扩展；这属于该候选入口自己的验收约束，不等于 v009 的 9 刊正式准入。

### 3. 候选注册链的含义

当前 Codex 注册表的链条为：

`v3.1_Codex检索候选注册表`
→ `v3.1_AI检索候选注册表`
→ `v3.1_多来源候选注册表`
→ `v3.1_摘要候选注册表`
→ `v005/module_registry.json`。

链条中记录了不同版本的 04/11 模块路径。04/v012 `native_library.registry()` 沿 `previous_registry`、`phase2_registry`、`base_registry` 读取这些配置，主要用于建立兼容的工具模块 `sys.path`；其当前七刊名单则直接来自最外层 Codex 注册表的 `journals` 字段。

这条链说明七刊入口是建立在既有模块/身份解析依赖上的新候选路径；**它不能证明七刊期刊名单继承自 v009 九刊政策**。九刊与七刊的集合关系是当前配置内容的包含关系，不是注册链自动推导关系。

## 五、已发现的配置/测试边界

### 1. candidate_registry 指针没有成为统一动态来源

v009 `search_policy.json` 声明 `candidate_registry` 指向 Codex 七刊注册表，但 v009 `staged_topic.py` 当前只使用 `POLICY` 的 journals/dev/formal 等字段；没有直接读取 `POLICY["candidate_registry"]`。与此同时，`native_library.registry()` 在代码中固定读取同一注册表路径。

当前两处路径一致，未发现实际名单错配；但若未来只改动 search_policy 的 candidate_registry 字段，原生 registry 导入不会自动跟随。该字段目前不是 v009 九刊白名单的动态来源，也没有跨配置一致性校验。**本轮只记录风险，不修改配置或增加校验。**

### 2. 九刊完整性检查较弱

v012 strict `doctor()` 只检查 `len(policy["journals"]) == 9`，不逐项核对九个期刊名称，也不检查与七刊的包含关系。v009 `staged_topic` 本身按加载到的 policy 名单执行精确字符串匹配。当前文件中的九刊名单正确，但如果以后误替换为另一组九刊，doctor 的数量检查不会发现。

### 3. 七刊测试未覆盖九刊边界

04/v012 现有 `tests/test_native_library.py`：
- 通过 `PROFILE = registry()` 读取 profile journals；
- 测试原生工具回执、身份去重/冲突、非白名单期刊拒绝；
- 使用“社会科学”作为 out-of-scope 例子。

该测试没有显式断言七刊名单恰好等于九刊中的七本中文期刊，也没有专门断言 ASR/AJS 在七刊 profile 中被拒绝、在 v009 九刊 policy 中被允许。本轮仅检查测试源码，未运行测试。

### 4. 不应从名单范围推导期刊质量或生产资格

- 七刊是当前 Codex 原生候选的配置范围，不代表七刊均已独立验证出版商、学术等级或主题适配。
- 九刊是原 v3.2 的基础搜索白名单，不代表每条命中文献都自动合格；仍需按 B08 的题录/摘要来源、相关性、去重及冲突规则接收。
- v009 的专业刊扩展与 04/v012 固定七刊名单是不同合同；不能将 specialist journals 自动注入七刊 standalone config。
- 本文不判断正式生产应采用哪套入口，也不改变 04/v012 candidate 状态；更深入的生产候选、实验候选、正式准入路由留给后续授权任务。
