## 2. 原生搜索回执强度：最重要的断点

1. `codex_literature.evidence()` 读取 `events.jsonl` 中完成的 `web_search`，遇 `command_execution`、`mcp_tool_call`、`file_change` 则拒绝本次原生采集。搜索事件可证明动作发生，却不能凭搜索结果反推页面已打开。
2. `proof(url,event_id,trace)` 有 **OR 条件**：该 URL 出现在 `results` 中即可返回 true，**或**是 `open_page/find_in_page` 的目标 URL 且有结果。结果：`observation.metadata_event_id` 与 `abstract_event_id` 对 L0 检索命中也可成立，不能直接提升成 L1 打开凭证。
3. `observation()` 要求摘要字段、相关性和两个 URL 事件；无回执会排除，失败候选在 `rejected/unverified` 中留痕。成功后记 `valid_abstract`，但那是摘要来源/结构层级，**不是全文阅读状态**。
4. `native_receiving.receive()` 会再次验证 CLI 登录状态、事件与响应文件 SHA、观察/去重结果；`excerpt_visible_in_logged_result` 和 `excerpt_visible_count` 记录短摘是否真的出现在保存的 snippet 中，**并非 `verified_rows` 的强制门槛**。`analysis_status=not_analyzed` 说明该矩阵不等于已完成文献分析。
5. `native_receiving.receive_direct()` 对另行接收的 direct search 要求 excerpt 出现在同 URL snippet 中，结果 `automated_count=0` 且 `intake=manual_supplement`。这条额外强度**只属于显式 direct intake**，不能反说普通 `receive()` 已应用同样的 snippet 硬门槛。
6. `staged_topic.search()` 以 `verified_rows` 达到目标并有理论记录推进初审，补查后以唯一数推进最终审查。**其通过是“摘要级检索任务及审查前置资料完成”，不是“所有论文已读全文/正式纳入”**。

## 3. 旧生产 04/v008 的更强阅读与纳入流程（仅作边界对照）

- **联网来源资格：** `literature_sources.online_record()` 要求六刊内、来源 `origin=online_search`、可访问 URL、`search_id` 匹配有效检索记录（搜索 provider/query/time）；`eligible_papers()` 还要求来源与论文的刊物及摘要一致。
- **摘要审读与决定：** `stage04.validate()` 不能仅看 paper.abstract 非空，还核 `review.abstract.status=abstract_read`、`reader`、`read_at`、`notes`、`relevance`、`authority_basis`、摘要 SHA、`inclusion_status=included`；冲突身份和不合格来源不能算入 `abstracts_read`。
- **核心 25 的选择与正式证据：** `pipeline04.rank_core()` 将仅依关键词的候选标为 `lexical_proposal_only`，只有有 `decision=included`、`review_status=verified`、读者/日期/理由及各项打分的候选为 `abstract_reviewed`；其输出仍为 `proposal_requires_fulltext_review`、`confirmed_core_count=0`。最终 `stage04.validate()` 还要求核心池来自被纳入摘要、PDF 全文完整阅读、相关直接引证及 `dialogue`，并检查研究关系的 `read_basis` 与证据。
- **获取不等于阅读：** `pipeline04.bridge()` 即使已有 `downloaded_verified` 的 PDF，也默认写 `status=not_read`、`complete=false`、空 `page_spans`；引文候选为 `fulltext_read_and_claim_check_pending`，不是已核实引用。
- **不擅自连线：** 生产 G4 在 v005 注册表中指向 04/v008，原 v009 的候选 04/v012 摘要矩阵另行运行。B09 仅说明两个证据合同的差异，不声称 v012 已经自动将 abstract-only 记录迁入 v005 的正式 G4。
