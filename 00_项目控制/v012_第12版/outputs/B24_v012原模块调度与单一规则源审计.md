## 二、权威状态机与规则来源

- v009 staged_topic.py 自己拥有 init、record_reality、exchange、issue、search、advance、review、freeze、prepare 等状态推进与学术门禁；它调用 codex_literature、native_receiving、method_paths 和 event_protocol。
- v012 ai_paper5_strict.py 的 original_command、original_material_command、original_writing_command 分别转发至 v009/v005 原始 CLI；doctor() 校验原政策、九刊、数量配置和 schema 哈希。
- v012 autopilot_v3.py 只负责 Codex CLI 调用、原始事件/响应留存、attempt/hash/thread 回执和阶段派发；研究状态仍由原 v009 CLI 写入。
- 04 native_library.registry() 负责候选模块身份、九刊和生产注册边界；11/v007 collector 与 native_receiving 仍是文献来源及准入的原始实现。
- 06/v005 qual_materials.py 仍负责材料搜索、原始 events/response 凭证和材料矩阵；v009 material_adequacy.py 仍独立决定材料是否足以进入写作。
- v009 resume_writing.py 通过原 v005 framework/repair、v009 material_adequacy 和 v015 writing_plan.produce 完成矩阵修复与写作方案审查。

## 三、本轮发现并处理的接口缺口

原 v009 resume_writing.py 会调用 V15 生成并审查段落级写作方案，但它并不直接调用 V16 ai_writer4.py。此前 v012 只在 REQUIRED/status 中列出 V16 路径，缺少明确可执行的转发入口。

本轮新增：
- original_writer4_command(action, packet, workspace, mode, manuscript, claims)：仅组装原 V16 CLI 命令，不复制写作逻辑。
- ai_paper5_strict.py 新增 writer4 CLI 子命令，直接调用原 V16 route/prepare/submit。
- frozen 状态输出明确的 V16 exploratory handoff 命令；formal 仍由原 V16 formal_gates 阻断，不能凭标志绕过独立上游凭证。

**边界：** V16 现在有明确的原模块调用入口，但仍是 V15 reviewed plan 之后的显式 handoff；本轮没有声称 autopilot_v3 已自动串联材料、V15、V16 全部后续阶段。

## 四、Chat 专用预审边界

ai_paper5_strict.chat_task/audit_chat 使用原 v3.2 policy、prompt、schema 的 SHA 作为合同；audit_chat 对 Chat-native 结果做结构性预筛，但明确返回：
- source_mode=chat_native_web
- native_cli_receipt=false
- formal_eligible=false

这部分有少量 Chat 专用结构检查，与原 native receiver 的字段约束存在重叠；它只能筛除明显不合格候选，不能成为第二套正式文献准入器。正式来源真实性和准入仍由 11/v007 原始事件与 04 native_receiving 控制。B23 测试已锁定 Chat 不能冒充 Codex CLI 或独立审查。
