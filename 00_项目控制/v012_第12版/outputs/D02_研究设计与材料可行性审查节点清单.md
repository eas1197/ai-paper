# D02：研究设计与材料可行性审查节点清单

**状态：** verified（原模块节点映射与边界核对；本项为文档任务，不新增运行门禁）。

## 一、节点识别结论

D02 的主审查节点是原 v009 `staged_topic.py` 中的 **`design_review`**：它承接 D01 的 `academic_pass`，判断研究设计是否能取得真实、可核验且适用的证据，并要求对定量、二手访谈、网络定性三条方法路径逐一给出有理由的材料状态。

该节点内部有两个不同性质的子合同：
1. `method_paths.select_method()`：确定性校验三条方法路径的评估字段和裁决条件，不是独立学术审查本身。
2. `method_paths.verify_material_review()`：对定性材料的真实搜索回执、问题版本、来源 ID 和原始文件哈希作技术核验，不是学术裁决。

此外，06/v005 的 `qual_materials.py` 还存在一个更窄的定性材料审查记录函数 **`record_review()`**。它在定性问题转换与实际材料搜索后生成独立的 `review.json`，但在本次核对的 v009 `staged_topic.py` 中，没有发现对该函数或该 `review.json` 的调用/读取。因此不能把它写出的 `qualitative_design_ready` 自动等同于 v009 状态机已经通过 `design_review`。

## 二、主节点：v009 `design_review`

### 2.1 进入条件与审查范围

- D01 的 `academic_pass` 保存初审报告和研究问题，将状态设为 `design_review`；这一步只证明学术问题值得进入设计审查。
- `prepare()` 对 `design_review` 的范围说明是：审查能否取得真实、可核验且适用的证据，并区分“待查证据”与“确认不可得”。
- 在 `review()` 中，`pass` 还必须提供 `data_feasibility="pass"`；`missing_data` 必须提供 `data_feasibility="blocked"` 及本研究对应的归档记录。
- 设计审查通过后，初始阶段状态转为 `supplemental`，即允许进入文献补查；不会直接冻结为 S08，也不会开始经验矩阵写作。

### 2.2 三条方法路径

`method_paths.PATHS` 固定要求对三条路径逐一评估，不能只报告最偏好的路径：

| 路径 | 原有下游映射 | 设计审查需回答的问题 |
|---|---|---|
| `quantitative` | 06 与 07 均映射到 `existing_quantitative` | 理论、研究假设、数据与统计设计是否有真实可用的数据支持 |
| `secondary_interviews` | 06 与 07 映射为 `planned` | 理论分析框架、研究命题、案例选择及二手访谈来源是否适配 |
| `online_qualitative` | 06 与 07 映射为 `planned` | 理论分析框架、研究命题、网络场域与文本/观察设计是否适配 |

每条路径必须提供 `status` 与证据性 `reason`。状态只能是 `ready`、`missing`、`unknown`、`not_applicable`：
- `ready` 必须有非空材料 ID 列表，并明确 `access="verified"`；
- `online_qualitative` 还必须区分 `public_text` 与 `ethnography`；选择民族志时须有 `observation="verified"`；
- `not_applicable` 也要说明为什么不适用，不能留空。

### 2.3 裁决与状态转移

| 裁决 | 原 v009 约束 | 状态/含义 |
|---|---|---|
| `pass` | `data_feasibility="pass"`；三条路径完整评估；必须选中一条 `ready` 路径 | 保存 `research_method`，初始阶段进入 `supplemental`，等待补充文献；不是 S08 冻结 |
| `missing_data` | `data_feasibility="blocked"`；所有适用路径都必须为 `missing`，不得选中路径；还需本研究对应的归档信息 | 进入 `archived`；单一路径缺数据不足以归档 |
| `materials_pending` | 不得选中路径；至少一条路径仍为 `unknown` | 保持待核，不得将未知当成缺失或通过 |
| `technical` | 走原技术重试分支 | 技术问题不应被写成材料不足或学术否定 |
| 学术问题裁决 | 仍走原 `ACADEMIC` 返修路由 | 不是材料可行性结果，不应以材料状态覆盖学术判断 |

`select_method()` 对 `missing_data` 的规则尤其重要：只有所有适用路径均确认 `missing` 才能归档；如果定量路径缺失、访谈路径仍为 `unknown`，结果只能是 `materials_pending`。这防止把“尚未检查”误写成“确认没有”。

## 三、定性路径的真实材料回执核验

### 3.1 搜索与材料接收：06/v005 `qual_materials.py`

`read_materials()` 读取原生 `events.jsonl` 与响应文件，要求有真实搜索事件且未超过预算；每条材料须能匹配到 URL 对应的原生事件，并满足材料类型、路径和上下文字段。生成的回执状态为 `pending_independent_review`，同时绑定 events/response 哈希、工具事件数、材料、排除项和缺口。

### 3.2 回执技术核验：v009 `verify_material_review()`

对 `ready` 或 `missing` 的定性路径，必须：
- 提供 `attempt_NNN`，且存在对应 `material_receipt.json` 和 `conversion.json`；
- 回执属于当前 run，状态为 `pending_independent_review)，并含原生工具事件；
- receipt、conversion、events.jsonl、response.json 的哈希全部匹配；
- 转换后的问题与当前审查问题不一致时，明确说明 `reviewed_reuse`；
- 声称 `missing` 时，必须证明搜索过程合理但材料不足（`reasonable_but_insufficient`）；
- 声称 `ready` 时，材料 ID 必须确实存在于该路径的回执中。

`unknown` 与 `not_applicable` 不要求伪造搜索回执；它们分别表示尚待核验与有理由的不适用。

## 四、06/v005 的窄范围定性审查记录：`qual_materials.record_review()`

该函数处理的是“定性问题转换后，针对二手访谈/网络定性路径完成材料搜索，再对转换问题与材料适用性作审查”的局部节点：

1. 报告需绑定 `conversion.json` 的哈希，提供模型、`invocation_id`、理由，并明确 `academic_value="pass"`。
2. 允许的结果仅为 `pass`、`missing_data`、`materials_pending`；学术性修改退回 S07，不在这里改写。
3. 复用 `select_method()` 校验三条路径；对定性路径核验当前 attempt 的原始搜索回执。
4. `pass` 必须选中二手访谈或网络定性路径，并提供被审查的问题和 `review_scope`。
5. 写入当前 attempt 的 `review.json`，状态分别映射为 `qualitative_design_ready`、`materials_insufficient`、`materials_pending`；所有结果均保持 `formal_eligible=False)。

**与主节点的关系：** 这是定性路径上的专项审查记录，不是 v009 `design_review` 的替代品。v009 当前直接调用的是 `select_method()` 和 `verify_material_review()`，未调用 `qual_materials.record_review()`，也未读取其 `review.json`。因此两套状态之间的自动接续仍需后续任务核实，D02 不擅自补接或宣称已经接通。

**凭证边界：** `record_review()` 与 v009 `review()` 一样检查模型标识、`invocation_id` 和输入哈希，但函数本身没有验证独立审查者的真实 thread/session、原始 events.jsonl 或会话身份。真实独立执行凭证仍归 D14–D20。
