## 1. 九刊、顶尖专业刊与候选七刊的边界

原 v009 基准九刊：**中国社会科学、社会学研究、社会、探索与争鸣、中国青年研究、经济研究、管理世界、American Sociological Review、American Journal of Sociology**。政策文件同时为 ASR/AJS 写有推荐出版平台链接，但这些链接只是搜索优先渠道，并非对所有检索返回结果已做出版商认证。\
`staged_topic.search()` 用 `POLICY["journals"]` 为基础；若议题定位报告存在 `specialist_journals`，则形成九刊加专业刊的允许列表，并交给 `collect()`、`receive()` 做期刊过滤。

| 类别 | 原有准入/排除条件 | 当前实际校验与限制 |
|---|---|---|
| 九刊 | 文章 `journal` 须在九刊基准表，且符合主题相关性、题录与摘要的真实来源校验 | `observation()` 用 `row["journal"] in journals` **精确字符串**比较，不在表内即 `out_of_scope`；不进行同义刊名/简称规范映射的自动认可 |
| 新增顶尖专业刊 | `record_issue_plan()` 接收 `specialist_journals` 中的非空 `name`、`publisher_url`、`standing`、`fit`；名称不得与九刊或其他新刊重复；链接须以 `https://` 开头 | **只做结构/去重及 HTTPS 前缀检查**。没有从原生搜索事件验证出版商链接、期刊实际学术地位、顶尖级别或与问题的实质匹配；这些字段是待审查的声明，不能当成已认证的专业刊 |
| 期刊层级记录 | 存在 `issue_plan` 时，`search()` 依据期刊名称生成 `journal_tiers.json` 的 `core_nine` 与 `specialist` 两组文章 ID | 只是**事后分组标签**，不构成独立学术质量复审；代码中未发现额外的“九刊最低占比”或“专业刊最高占比”阈值。已批准列表中的专业刊有效论文也可能计入初查/补查总体配额 |
| 旧七刊候选 | `v3.1_Codex检索候选注册表.json` 列七本中文期刊、`enabled_by_default=false` | 该七刊注册表属于另一候选入口，**不是 v009 九刊政策的替代**。七刊/九刊启动和依赖关系细审属于 B13–B16，不在本轮修改 |

**拒绝边界：** 不在本次运行的允许期刊列表，或没有真实相关性说明、可信题录/摘要事件回执的论文，不得作为 `valid_abstract` 计数。新增刊物提供了 `standing`、`fit` 字符串，也不能因此声称已经通过独立期刊资质审查。

## 2. 单条论文的准入与排除

`11/v007 codex_literature.observation()` 执行的直接条件：

1. `journal` 在本次 `journals` 白名单内，`title` 规范化后非空；否则 `out_of_scope`。
2. 作者列表有至少一个非空姓名，年份在 1900–2100；否则 `bibliography_incomplete`。
3. `relevance` 为 `direct` 或 `substantive`，且 `relevance_reason` 非空；否则 `relevance_unconfirmed`。
4. `abstract_summary` 能经 `abstract_text()` 接受、`abstract_excerpt` 长度在 8–90 且 `abstract_locator` 非空；否则 `abstract_not_verified`。
5. 题录 `metadata_url` 与摘要 `abstract_url` 必须能分别对应本次原生 `web_search` 事件；否则 `missing_native_tool_receipt`。
6. `native_receiving.receive()` 复查批次原始事件/响应文件哈希、登录状态、每条 `observation` 的重建结果、聚合后的论文和冲突列表，随后形成 `literature_matrix.json`，只把有效论文计入 `verified_rows`。

**不能推出：** 此类技术校验证明题录/摘要有指定回执，但不等于全文已读、期刊实质质量经过学术独立审查或文献已被正式引用。尤其 `native_receiving` 的 `excerpt_visible_in_logged_result` 记录是另一证据强度字段；其更细的“发现/打开/摘要/全文/正式纳入”等级留给 B09。

## 3. 理论文献单列的现有实现

- `v009/search_prompt.txt` 要求初查在 `search_notes` 里按 `THEORY|题名|URL|理论命题及适用条件` 记载经典理论或权威解释。理论来源**不限九刊**，也必须能对应原生工具事件；明确写有“理论资料不计入 papers”。
- `staged_topic.theories()` 只从已完成批次的 notes 解析四段 `THEORY` 记录，核验 `url_event()`、非空题名与命题，输出 `initial/theories.json`；该列表**不加入 `observation()/group()` 的普通论文合并池**，因而不计入“初查 5 篇”的有效论文数量。
- `staged_topic.search(phase="initial")` 只有 `verified_rows >= 5` **且** `theories.json` 非空时才进入 `preliminary_review`；补查保留初查理论线索。
- **缺口：** `theories()` 没有针对 THEORY 项的单独身份去重、作者/原文证据层级与理论学术质量审查，也未要求理论项数量超过非空门槛；因此“理论已单列”不能写成“理论已独立验证或完成质量评审”。

## 4. 去重、身份冲突与跨阶段合并

| 流程 | 代码行为 | 不得冒充的结论 |
|---|---|---|
| 批次内/批次间候选 | `codex_literature.group(rows)` 逐行查同 DOI 或同刊物+规范化标题+年份的潜在重复候选，然后由 `verified_identity.resolve()` 复核刊物、DOI、一致的年份、作者、标题及允许的题名细差 | 同 DOI **不自动**合并；作者、年份、刊物或题名不一致会产生 `doi_conflict` / `year_conflict` / `author_conflict` / `ambiguous_bridge` 等 |
| 识别为同一论文 | `MATCH` 包括 `doi`、`bibliographic`、`linked_detail`，成功归并时保留 `provenance` 来源观察列表，产生稳定 `article_id` | 多条观察归并后只计一篇有效文章；原始来源不会因计数合并而消失 |
| 不可化解冲突 | 若桥接链内部有不相容身份或与 DOI/来源身份相冲突，产生 `conflicts` 并隔离相关组；这些组不进入 `papers` | 不把冲突记录强制计入有效数量；也不能自动推定真实论文不存在 |
| 补充检索 | `staged_topic.search(supplemental)` 校验初查哈希、传入 `excluded_titles` 仅用于提示避免重复；复用初查有效来源，对补查观察 ID 加 `supplemental:` 命名空间后重新执行 `group()` | 仅靠排除题名不足以防重；最终以跨阶段身份合并和冲突结果为准 |
| 原生接收器 | `native_receiving.receive()` 重新运行 `observation` 与 `group`，对照 bundle 的 articles/conflicts/count，并输出 `verified_rows` | 模型口头报告的篇数、未经回执的 URL、重复观察，均不能替代最终有效论文数 |

**有限保留：** 现有 `group()` 使用身份启发式与冲突隔离，已明确优于单纯按 DOI/标题直接去重；但本文未进行跨语言刊名、作者变体、误合并/漏合并的真实样本验收，不能声称身份匹配在所有期刊上无误。
