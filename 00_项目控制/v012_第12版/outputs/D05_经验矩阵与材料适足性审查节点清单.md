# D05：经验矩阵与材料适足性审查节点清单

**状态：** verified（依据 06/v005 原模块、v009 方法/材料合同、v012 当前调用边界及既有测试完成节点映射；本项为文档任务，不新增审查门禁）。

## 一、节点地图：矩阵、材料审查与返修是不同产物

当前 06/v005 的定性经验材料路径可分为五个节点：

1. **问题转换与初始材料搜索**：将定量问题转换为定性问题，记录原生搜索结果与材料回执，用于初步判断可行性。
2. **理论框架与定向材料收集**：在同一核心问题、同一研究 run 和有效初查回执基础上，锁定理论框架并按各维度需要收集材料。
3. **经验矩阵生成**：将每个理论维度与支持、反例、竞争解释或情境证据绑定，明确结论边界与未解决事项。
4. **定性设计/材料适配审查**：由 `qual_materials.record_review()` 审查问题转换、三条方法路径及材料状态，生成 `review.json`。
5. **独立审查缺口后的材料返修**：`repair_materials.py` 提供有上限的追加搜索和材料替换辅助函数。

**核心结论：** 现有 `record_review()` 审查的是问题转换与方法/材料适配，不直接审查 `analysis_matrix`。经验矩阵自身只输出 `pending_independent_review`；当前 06/v005 没有与之对应的矩阵独立审查接收函数。因此，不能把 `qualitative_design_ready` 当作经验矩阵通过，也不能把矩阵生成当作材料适足性独立审查完成。

## 二、问题转换与材料初查：`qual_materials.py`

### 2.1 问题转换输入

`validate_conversion()` 要求记录：
- 核心问题、转换前问题、转换后定性问题；
- 理论关切与转换理由；
- 理论框架、已有文献和研究情境。

转换前后问题不能完全相同。其目标是保留核心学术问题与理论关切，同时明确具体的定性问题，而不是把“缺少定量数据”直接当作定性研究设计。

### 2.2 原生材料采集与回执

`qual_materials.py` 复用原 Codex CLI、实验运行清单和 11/v007 搜索预算。材料必须包含 URL、日期、对象、情境、类别、方法路径、定位、关系、局限和访问条件。类别区分行动者陈述、记者叙述、制度规则、已记录行动；研究者推断不能伪装成原始材料。

`read_materials()`：
- 要求当前 attempt 存在原生 events trace，且工具事件数不超过预算；
- 只有 URL 能匹配本批原生搜索事件、类别和路径合法、字段齐全的材料才进入候选集合；
- 为材料生成 `material_id`，并保留 event ID、排除项、搜索备注和材料缺口；
- 回执状态为 `pending_independent_review`，保存 events/response SHA-256、工具事件数和材料列表。

**边界：** 当前 `read_materials()` 通过 `url_event()` 证明 URL 与本批搜索 trace 有关，但没有像 D04 的事件协议那样逐条要求 `open_page/find_in_page` 事件；回执也没有独立记录审查者 thread。搜索命中不等于页面内容已核读，材料记录不等于其内容已获独立语义验证。

### 2.3 框架收集的前置条件

附加 `--framework` 执行定向材料收集前，程序要求初查 attempt 的回执：
- 状态为 `pending_independent_review`；
- events 与 response 原始文件哈希仍一致；
- 有非零工具事件与材料；
- run ID 与当前实验一致；
- 转换问题哈希一致；
- 框架的核心问题与转换记录一致。

定向收集写入独立的 `qualitative_framework/attempt_NNN`，记录 `phase="framework_collection"`、`framework_sha256` 和 `preliminary_sha256`。这使框架收集与一般初查分开记账，不覆盖初查记录。

## 三、理论框架与经验矩阵：`framework.py`

### 3.1 框架结构

`validate_framework()` 要求框架明确：
- 核心问题与核心概念；
- 概念含义及其解释选择；
- 最近邻研究、既有解释及其局限；
- 拟提出的理论增量与整合方式；
- 至少一个维度；每个维度需有唯一 ID、名称、理论推导、命题、所需材料和维度关系。

只按事件流程、手续或资料来源分类，不能替代从核心概念推导分析维度。

### 3.2 矩阵生成条件

`analysis_matrix(framework, receipt, findings)` 要求：
1. 收据阶段是 `framework_collection`；
2. 收据中的框架 SHA 与当前框架一致；
3. 收据状态仍是 `pending_independent_review`；
4. 每个理论维度恰好有一条发现记录，不能漏项或重复；
5. 每条发现必须包含结论、边界、未解决事项和替代解释；
6. evidence 必须是显式列表；每项引用当前回执中的真实 material ID，不能重复，并说明其关系为 `support`、`counterexample`、`competing` 或 `context)，且提供理由；
7. 没有可用证据的维度只能标为 `unresolved`；所有维度的状态只能是 `tentative` 或 `unresolved`。

矩阵输出补入材料 URL、定位和类别，记录 `framework_sha256`、`collection_sha256`，并固定为：

- `status="pending_independent_review"`
- `theoretical_increment_status="proposed"`

因此它是一份有证据绑定、保留负向材料和未解决问题的探索性矩阵；“拟议增量”不是已证实的理论贡献，`pending_independent_review` 也不是通过状态。

### 3.3 框架修订

`--framework-revision` 要求：
- 原收据中的框架哈希与 `prior_framework_sha256` 一致；
- 修订理由非空；
- 新旧框架的核心问题相同；
- 使用同批材料和原矩阵重新生成矩阵；
- 另存带新框架哈希后缀的文件，不覆盖旧框架、旧矩阵或旧收据；
- 最多两次框架修订。

修订结果保留 prior framework hash、revision reason 和 collection hash。该功能允许材料推动理论框架的有限修订，但不等于独立审查已经接受修订。

## 四、定性设计/材料适配审查：`record_review()`

### 4.1 报告输入与校验

`record_review(work, folder, report)` 读取当前 attempt 的 `conversion.json`，要求报告：
- 模型标识 `gpt-6.2-sol`；
- 非空 `invocation_id` 与理由；
- `conversion_sha256` 与当前转换记录一致；
- `academic_value="pass"`；
- 裁决仅能为 `pass`、`missing_data` 或 `materials_pending`。

理论/学术问题需要修改时，函数明确要求回到 S07，不在材料审查中偷改研究问题。

### 4.2 三条路径与材料状态

函数复用 v009 `method_paths.select_method()`，要求定量、二手访谈、网络定性三条路径全部给出状态和理由。状态为 `ready`、`missing`、`unknown` 或 `not_applicable`：
- `ready` 必须列出材料 ID 并证明访问权限 `verified`；
- 网络定性还须区分公开文本分析与民族志；民族志必须有已核实的观察条件；
- `missing_data` 只有所有适用路径都确认缺失时才能归档；
- `materials_pending` 至少要有一条路径仍为 `unknown`，不能把未知写成缺失。

对二手访谈与网络定性路径，若状态为 ready/missing，审查报告必须绑定当前搜索 attempt，并调用 v009 `verify_material_review()`。

### 4.3 材料回执复核

v009 `verify_material_review()` 对定性路径核验：
- attempt 编号、当前研究 run ID；
- `material_receipt.json` 原始文件 SHA 与审查报告所给 receipt SHA；
- receipt 状态仍为 `pending_independent_review`；
- 原生工具事件数非零；
- conversion 哈希一致；
- events/response 原始文件哈希未变；
- 搜索问题与当前问题一致，或明确说明 `reviewed_reuse`；
- `missing` 必须说明 `reasonable_but_insufficient`；
- `ready` 的材料 ID 必须确实属于该路径回执。

这证明材料状态与原始搜索回执相绑定，不允许只凭审查者口头声称“有材料”或“材料不可得”。

### 4.4 裁决与输出

| 裁决 | `review.json` 状态 | 含义 |
|---|---|---|
| `pass` | `qualitative_design_ready` | 问题转换和定性方法/材料适配达到设计准备状态 |
| `missing_data` | `materials_insufficient` | 所有适用路径确实材料不足 |
| `materials_pending` | `materials_pending` | 仍有材料状态未知，保持待核 |

`pass` 还必须选中二手访谈或网络定性路径，并提供被审查问题和 `review_scope`。输出写入当前 attempt 的 `review.json`，保留所选方法与核心问题，并明确 `formal_eligible=False`。

**范围限制：** 该报告只证明问题转换和方法/材料设计审查结果；函数没有读取 `analysis_matrix.json`，没有检查矩阵的每个理论维度、反例、竞争解释、未解决项，也没有输出矩阵的独立审查状态。因此不能把 `qualitative_design_ready` 解释为经验矩阵已经通过独立审查。

## 五、独立审查后的材料返修：`repair_materials.py`

### 5.1 需求版本修订

`rebind_requirements()` 允许只调整各维度的 `needed_material`，但要求理论框架其他字段和维度理论推导保持不变。它复制原 conversion、response、events，生成新框架版本，并在收据中记录 parent attempt、parent receipt SHA 和 `revision_kind="evidence_requirements_only"`，不覆盖原始采集历史。

### 5.2 定向返修

`repair()`：
- 以 parent receipt SHA、framework SHA 和审查指定事项构成请求指纹；
- 相同请求可复用既有 repair 目录，避免重复采集；
- 每个研究 run 最多两个 repair 批次；
- 返修任务只处理独立审查指出的缺口，要求打开原始来源并定位段落，区分来源主张与推断、保留未知、禁止把转载当独立事件；
- 每条新增材料绑定原审查 issue index，并可用 `supersedes` 指定要退役的旧材料 ID；
- 新增材料必须属于审查批准的 issue index，supersedes 只能引用父回执中已有材料；
- 合并旧材料（剔除被退役项）与新材料，记录 parent attempt/receipt SHA、新增/退役 ID、覆盖的 issue index 和 `review_key`。

**当前限制：** `repair_materials.py` 是函数辅助模块，没有独立 CLI 入口或自动审查接续；`review_key` 被写入回执，但函数没有在自身内部解析并验证它对应的独立审查报告哈希。返修后也没有在该文件中自动重建 `analysis_matrix`、重跑矩阵独立审查或自动恢复 v009/V15 阶段。

## 六、v009/v012 接续边界

### 6.1 已有的有限接续

原 v009 `staged_topic.py` 在 `design_review` 与 `final_review` 中复用 `method_paths.select_method()` 和 `verify_material_review()`：
- 审查者必须对三条路径作出状态与理由判断；
- ready/missing 定性路径须绑定真实 attempt 与原始材料回执；
- 最终冻结前还会重新核验被选中的定性路径回执。

这条接续验证的是“所选方法路径的材料可得性声明是否绑定原始搜索回执”，不是 06 经验矩阵已被独立审查。

### 6.2 尚未接通的部分

- 06 `qual_materials.record_review()` 写出的 `review.json` 没有被原 v009 `staged_topic.py` 读取或纳入其阶段状态；v009 自己调用的是 `method_paths.verify_material_review()`。
- 06 `analysis_matrix` 目前没有独立审查报告接收函数，也没有矩阵 SHA、审查者身份和审查执行回执的统一接收门禁。
- 当前 v012 `ai_paper5_strict.py` 只声明 `MATERIAL` 与 `MATERIAL_REPAIR` 文件路径常量，未见相应调用；`autopilot_v3.py` 在正式独立学术/材料审查处停止，没有自动调用 06 的矩阵审查或返修函数。
- 当前已核对的 06/v005 CLI 与 v012 控制器路径中，未见 `repair_materials.repair()` 的实际调用，也未见返修后矩阵重建与复审的端到端连接。
- 因此 06 的材料审查、经验矩阵审查、返修及 V15/V16 接收仍是分离的能力片段，不能宣称已形成自动闭环。

## 七、独立性与真实性边界

- `record_review()` 检查模型、非空 `invocation_id`、理由和转换哈希，但不核验 invocation 是否对应真实独立 thread/session、events.jsonl、response 或审查者身份，也不检查 invocation_id 是否重复。
- `verify_material_review()` 验证材料搜索 attempt 与原始文件哈希，但不能证明审查报告本身由独立会话真实生成。
- `analysis_matrix()` 不接收审查报告，因此当前矩阵没有可核验的独立审查凭证。
- `repair_materials.repair()` 接受调用者传入的 `items` 和 `review_key`，但没有自行验证审查者身份、报告哈希或独立执行记录。

这些缺口应由 D09–D20 的审查任务包与真实独立凭证接收工作处理；D05 不新增平行评分或自填字段放行。
