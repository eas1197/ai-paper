# I06 阶段输入、输出及检查点定义

状态：verified（定义与只读映射），基线 6fc303ec21e210f4c81d068201198286177e8770。不新建原学术状态机；本合同定义观测索引，原控制器、原收据和原门禁仍权威。实际全阶段自动生成索引与汇总由I18/I20另验，真实执行缺口不变。

## 统一记录字段

| 字段 | 定义 |
|---|---|
| research_id / stage_id / task_id | 原run身份、原阶段/对象、独立选择的任务身份；旧定量命名空间需原运行身份，不得仅按同名合并 |
| input_snapshot | C04已冻结任务用research_id/stage_id/task_id/snapshot_sha256指向原versions；未接C04的原阶段引用原冻结输入/配置/上游manifest及其哈希，不伪造C04版本 |
| input_files / output_files | 明确来源命名空间、相对路径、原文件SHA-256；拒绝越界、跨run及缺失。保留原canonical digest的类型和作用，不把它误称文件SHA |
| original_status / execution_status / runtime_status | 原状态、执行结果、v012观测分开；缺原记录为unknown，候选/等待/技术成功不是学术通过；正式资格只由原门禁判定 |
| started_at / finished_at | 仅原执行记录的时区明确RFC3339时间；未执行、旧记录缺字段或只有不可认证自报时间则为null并注明unknown/unverified，绝不用文件mtime、当前时间或提交时间补造 |
| time_evidence | 有真实时间时指向原记录路径及哈希，声明时间来源；观察时间与完成时间分列 |
| supersedes / dependencies | 引用旧版本及上游记录；C04递归核验与原失效规则，保留历史，不覆盖原产物 |

## 验收边界

依据B02阶段表、C04 freeze_packet/verify_snapshot、result_bundle schema的task_snapshot、execution_time（nullable RFC3339）及execution_status、E15原阶段产物后验、D21、F06、G25、H04原manifest及锁。原结果包自报时间尚需独立执行记录复核；未全面接通自动记录生成。原stage状态与观察均不可由本表授予学术通过。此项验收的是定义，不宣称每个阶段真实运行或其历史完成时间已补齐。转I07。
