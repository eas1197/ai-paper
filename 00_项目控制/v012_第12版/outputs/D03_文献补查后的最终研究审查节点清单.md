# D03：文献补查后的最终研究审查节点清单

**状态：** verified（依据原 v009 函数、策略配置和既有自动化测试完成节点映射；本项为文档任务，不新增审查门禁或改变原有配额）。

## 一、节点定位

D03 对应原 v009 `staged_topic.py` 的正式状态 **`final_review`**。它发生在：

1. D01 的 `preliminary_review` 完成学术价值初审；
2. D02 的 `design_review` 完成研究设计与材料可行性审查；
3. 设计审查通过，状态进入 `supplemental`；
4. 补充文献采集、原始回执重建、与初始文献去重合并并达到原定总配额；
5. 控制器才把状态推进到 `final_review`。

因此，D03 不是重复初审，也不是经验结论审查。它检查在新增文献纳入后，原研究问题是否仍有学术增量、材料是否经核实可得、研究设计是否与证据相匹配。

## 二、补充检索完成条件

### 2.1 检索授权

- `search(work, state, "supplemental", ...)` 只允许在 `state["status"] == "supplemental"` 时执行；初审或设计审查尚未通过时，不能直接补查。
- 补查前，原 v009 重新调用初始阶段 `receipt()` 重建初始文献矩阵，并核对其摘要哈希与 D02 通过时保存的 `state["initial_sha256"]` 一致；初始证据变化会拒绝继续。
- 补查检索配置排除初始矩阵中已有的题名；补充观察记录另加 `supplemental:` 前缀，避免两个独立采集器复用批次名造成 ID 混淆。
- 只有原接收器重建出的已核验来源参与合并；随后由 `group()` 合并初始来源与补充来源，按原有规则处理重复与冲突。

### 2.2 配额与合并门槛

原 `search_policy.json` 明确规定：

| 模式 | 初始检索 | 补充检索 | 合并后的最低总量 |
|---|---:|---:|---:|
| dev 开发模式 | 5 | 5 | 10 |
| formal 正式候选模式 | 5 | 35 | 40 |

完成判断不是“补充阶段单独达到目标”，而是去重后的初始与补充来源合并数达到两阶段目标之和。原始集合不足、重复合并后不足，或采集返回 `experimental_budget_exceeded`，都不能进入最终审查。

当合并达到配额且没有实验预算超限时，原 v009 写入 `merged_literature.json`，其中保留 `initial_sha256` 与 `supplemental_sha256`；随后状态由 `supplemental` 转为 `final_review`。若未达标，原 `advance()` 按批次与搜索动作预算决定继续补查或停止，不得把未核验来源补算为完成。

## 三、最终审查的输入与证据绑定

### 3.1 直接输入

- `merged_literature.json`：初始与补充文献合并后的来源矩阵；
- `initial/theories.json`：初始理论材料；
- `reality.json`：启用 reality-first 时的现实观察材料；
- `explanation_exchange.json`：启用 explanation-first 时的解释与反诘记录；
- `issue_plan.json` 与 `event_comparison.json)：启用 issue-search 时的议题定位与事件比较材料；
- 当前研究问题、前序审查历史，以及方法路径评估和对应材料回执。

### 3.2 evidence_sha256

最终审查的 `prepare()` 使用 `merged_literature.json` 而不是初始文献矩阵计算 `evidence_sha256`。原 `evidence_hash()` 将文献矩阵和理论材料纳入哈希；按配置启用时，还纳入现实材料、解释/反诘、议题计划与事件比较，并重新核对这些前置材料的保存哈希。

`review()` 接收最终报告时，会重新计算当前输入的哈希并与报告中的 `evidence_sha256` 比较。文献矩阵、理论材料、现实观察、解释/反诘或事件比较发生变化，均不能继续沿用旧报告。

## 四、最终审查范围

原 `prepare()` 对 `final_review` 的范围说明是：**审查学术增量、经核实的可行性与设计，不要求经验解释已成立。**

| 审查维度 | 需要判断 | 不得越界 |
|---|---|---|
| 学术增量 | 补查后相对既有研究是否仍有可说明的理论、机制或经验增量；近邻研究是否削弱或取代原问题 | 不得以“搜不到完全相同题目”单独证明创新 |
| 核心问题 | 研究问题是否仍然清楚、集中，新增文献是否要求缩小、改写或放弃原问题 | 不得为了保留原题而忽略直接近邻研究 |
| 经核实的可行性 | 所选路径所需数据、访谈、网络文本或观察材料是否有真实来源、可访问且适用；未知与确认不可得必须区分 | 不得把待核材料写成已取得，也不得仅因一条路径缺失就宣告所有方法不可行 |
| 研究设计 | 理论概念、机制、命题/假设、案例范围、材料和方法是否互相对应；能否形成可执行的经验检验或解释方案 | 不得提前宣称经验机制或因果解释已获支持 |
| 方法路径 | 复核 quantitative、secondary_interviews、online_qualitative 三条路径评估及选定路径；定性材料需按原回执合同核验 | 不得因最终审查而绕过 D02 的路径和材料规则 |

若启用了 `reality_first`，对 `pass` 或 `missing_data` 的报告还须将研究情境绑定到同一核心问题，并给出非空的假设、命题或子问题。启用了 `method_paths` 时，`pass`、`missing_data`、`materials_pending` 均按原 `select_method()` 规则校验路径；启用定性材料回执时，原函数继续核验访谈与网络定性路径的材料状态。

## 五、报告约束与裁决

### 5.1 报告必须绑定

- `model="gpt-6.2-sol"`；
- 非空且未在本研究审查历史中重复的 `invocation_id`；
- 当前最终证据包的 `evidence_sha256`；
- 非空的 `reason` 与 `question`；
- 对 `pass`、`missing_data`、`materials_pending`，明确 `academic_value="pass"`；
- 对 `pass`，明确 `data_feasibility="pass"`；
- 对 `missing_data`，明确 `data_feasibility="blocked"`，并提交本研究、本问题对应的归档信息。

最终阶段不接受 `academic_pass`：学术价值单独通过只适用于初始选题审查，不能用它跳过设计审查或补查后的最终审查。

### 5.2 原有裁决与状态

| 最终审查结果 | 原 v009 路由 | 处理含义 |
|---|---|---|
| `pass` | `route()` 返回 `passed`；最终阶段将状态设为 `s08_ready` | 学术增量、可行性和设计均通过，进入 S08 冻结前置状态；不是直接冻结 |
| `concept` | `S02` | 概念界定不足，定向返修 |
| `value` | `S03` | 学术价值不足，定向返修 |
| `depth` | `S06` | 理论/解释深度不足，定向返修 |
| `increment` | `S05` | 相对已有研究的增量不足，定向返修 |
| `materials_pending` | `materials_pending` | 材料仍待核实，不能进入 S08 |
| `missing_data` | `archived` | 所有适用路径确实不可得且有归档记录时归档；不是单一路径缺失即归档 |
| `technical` | `retry_technical` | 技术失败可重试，不计作学术失败 |
| `academic_pass` | 最终审查明确拒绝 | 不允许以学术单项通过跳过最终审查 |

学术缺陷使用原历史记录计算返修预算；技术失败不计作学术失败。原路由在已有两次学术失败后再出现学术缺陷时转为 `eliminated`。D03 不新造返修次数或并列总分。

## 六、S08 不是自动冻结：二次冻结门槛

最终审查 `pass` 只把状态改为 `s08_ready`。随后必须显式调用原 `freeze()`，并逐项通过：

1. 当前状态必须是 `s08_ready`，否则拒绝；
2. 使用当前 `merged_literature.json` 和理论材料重新计算证据哈希，必须与最终报告中的 `evidence_sha256` 一致；
3. 最终报告的问题必须与当前研究问题一致；
4. 最终报告必须包含非空的研究设计 `design`；
5. 若启用方法路径，最终报告中的方法评估必须与最终选定的 `research_method` 一致；
6. 若启用定性材料回执，冻结前还会对最终选定的定性路径再次核验材料回执。

全部通过后才写入 `s08_topic.json`，记录 S08、问题、设计、研究案例、研究方法、证据哈希、审查报告哈希及模式，并将研究状态设为 `frozen`。

**冻结边界：** `s08_topic.json` 明确写入 `formal_eligible=False`；dev 模式的 scope 是 `experimental`，formal 模式也只是 `formal_candidate`。因此 S08 冻结不是正式资格放行，更不是经验命题已经成立。经验解释是否成立仍须在后续材料与分析阶段检验。

## 七、独立性凭证缺口

当前 `review()` 检查模型标识、`invocation_id` 非空/不重复、证据哈希和实质理由，但没有在该函数中验证真实独立审查者身份、独立 thread/session、原始事件文件或执行回执。故本报告只映射原状态机与报告字段，不宣称当前代码已证明独立审查真实发生。

D14–D20 才负责独立会话启动、真实 thread/session 和原始事件/响应哈希绑定、研究者与审查者会话区分、接收器核验及无法独立执行时的拒绝策略。未完成这些任务前，不能把字段自填的 `invocation_id` 当作独立性证明，也不能以 D03 文档代替真实独立审查。
