# D11：审查证据定位、支持范围、反例与未决问题

状态：verified（实际离线结构与定位测试 19/19；不代表独立学术审查、事实语义核验或原门禁通过）。

## 变更

- [review_result.schema.json](../schemas/review_result.schema.json)：D10 草案升级为显式 schema_version=2，新增必填 evidence_findings。版本1报告保留原历史，不静默升级或继续接受；C 系列 task_snapshot 传输版本不变。
- 每条 finding 绑定 dimension_id、claim_id（前期无具体主张可为 null）、status（supported/limited/contradicted/unresolved）、blocking、reason、scope_limit、evidence、counterexample_review、unresolved_questions。每条未决问题有具体内容、阻断标记及理由。
- 每条 evidence 绑定 evidence_id、artifact_id、run 内文件 path、实际字节 SHA-256、行范围或 JSON Pointer、relation（support/counterexample/competing/context）、support_scope。没有原始文本定位时只能指向可追溯的实际记录；不得将记录存在推定为原文实读或语义支持。
- supported/limited 须存在支持关系；contradicted 须有反例；unresolved 须指出未决问题。pass 必须覆盖至少一个有支持的判断且不得有阻断性发现/未决问题；原 D10 裁决约束全部保留。非阻断的未决命题仅可在明确缩小审查范围后保留，原门禁决定其是否可接受。need_evidence 须有阻断性具体未决问题；unable_to_review 允许空 findings，不制造证据。

## 位置和文件技术校验

[review_evidence.audit_review_evidence](../tools/review_evidence.py) 接收调用方独立选定的 D09 context、run 与报告，执行 schema 验证、类别匹配、重复/未知维度、主张及 issue ID 检查；pass 必须覆盖 context 的全部维度与关键主张。issue 可提及待核 ID，但 evidence 不得引用待核或排除 ID 作为证据。逐条检查 artifact 绑定、相对路径边界（含符号链接解析）、原始字节 SHA-256、定位是否存在，以及所定位对象是否包含相应 ID（文件级证据允许 evidence_id=artifact_id）。

这是技术检查，不验证来源是否真正支持解释、审查者独立身份或当前 task snapshot 的真实性。D12 后续绑定当前任务与执行身份；D16–D20 核验真实原始凭证并接回原门禁。该函数不调用搜索、状态机、写作器或任何审查派发；仅返回 evidence_locations_checked，formal_eligible=false、independent_review_verified=false。严禁把它当学术通过。
