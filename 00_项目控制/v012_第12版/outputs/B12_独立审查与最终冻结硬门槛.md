## 一、结论速览

原 3.x 不是完全没有门禁：它把学术价值、材料可行性、材料适足性、证据哈希和 S08 冻结分成不同步骤；V16 还明确拒绝仅凭若干 `true` 标记进入正式写作。但**“代码要求独立审查”与“代码认证了真实独立审查”不是一回事**。

| 环节 | 已实现的硬约束 | 不能据此声称已通过的事项 |
|---|---|---|
| 检索前 researcher/critic 反诘 | v012 autopilot 两次真实 CLI 调用，提取 thread ID 并拒绝相同 ID | 不能替代最终学术审查；actor/receipt 仍没有外部身份签名 |
| v009 选题审查 | model 标签、非空且唯一 invocation_id、当前 evidence hash、reason/question | 报告字段由输入 JSON 自报，未核验真实 reviewer session |
| 定性方法可行性 | 三条方法路径、ready/access、搜索批次与原始回执及哈希 | 不证明材料实质上回答研究问题 |
| 矩阵审查 | resume_writing 的后续审查使用 fresh ephemeral Codex 调用并保存 thread_id、model、response hash | 初始 prior_review 只做自报字段校验；日志未形成完整的签名/防篡改凭证链 |
| 材料适足性 | pass 必须附 material_adequacy；ID 唯一且属于当前 receipt；理由与 support 状态必填 | 代码不验证 ID 对应不同真实事件，也不验证证据是否实质回答冻结问题 |
| S08 最终冻结 | s08_ready、最终报告哈希、问题、设计、方法与定性回执复核 | 不认证最终报告主体身份；frozen 不等于 formal eligible |
| V16 正式写作 | gate flags 和语言资源检查后仍要求外部独立凭证；当前直接拒绝正式模式 | 尚无可消费的可信外部凭证接口；只能安全地保持阻断 |

**总判断：** B12 的源码/调用链核对可以验收；独立审查主体真实性、适足性语义真实性和正式资格仍应标记 **not_verified / blocked**，不得将其写成真实审查通过。

## 二、独立审查主体与调用凭证

### 1. v009 选题审查：报告字段检查，不是身份认证

`00_项目控制/v009_第9版/tools/staged_topic.py:314-355` 的 `review(work,state,report)`：
- 只接受指定的审查状态；
- 要求 `report.model == "gpt-6.2-sol"`；
- 要求 `invocation_id` 非空且在当前 history 中不重复；
- 要求 `evidence_sha256` 等于按当前研究状态重新计算的 evidence hash；
- 要求非空 reason 和 question；正向结果还要通过 academic_value、data_feasibility、method assessment 等分支检查。

但 `staged_topic.py:486-548` 的 CLI 对 `review` 只接受 `--report` 文件，并直接 `review(work,state,load(args.report))`。没有在该入口调用独立 reviewer、核验 Codex/Chat thread、检查平台签名，或将 invocation_id 对应到真实调用回执。

所以这些字段能证明**报告格式与当前证据版本符合代码合同**，不能证明报告由真实独立主体生成。报告可由调用者提供；model 与 invocation_id 都是报告自报值。重复 ID 检查只作用于本 run 的 history。

### 2. v012 检索前反诘：有真实 session 分离，但不是最终学术审查

`00_项目控制/v012_第12版/tools/autopilot_v3.py` 的 `Executor.call()` 使用原生 Codex CLI `exec --ephemeral`，从原始 `events.jsonl` 提取 `thread.started` 的真实 thread ID，并将 session、response SHA、events SHA 写入本地调用 ledger。

在 `step()` 的 `explanation_exchange` 阶段：
- researcher 与 critic 分别执行两次 `engine.call()`；
- critic prompt 明确要求 fresh independent critic session；
- 比较两次返回的 session ID，若 `rs == cs` 则拒绝；
- exchange packet 保存 research_actor、critical_actor、critical_receipt 与 critic response SHA。

这比单一上下文自我扮演更强：在本地原始事件日志可信的前提下，可以证明两次调用使用不同 CLI thread。但它仍然只是**检索前解释反诘**，不是对最终研究问题、文献增量、材料适足性和研究设计的最终学术审查。两次调用也仍是同一 CLI/订阅体系下的模型会话，不是外部专家或不同机构的身份认证。

原 `event_protocol.validate_exchange()` 仅检查角色字段不同、critical_receipt 非空及 packet 字段；它不重新验证回执内部、签名或主体身份。不能把非空 receipt 字符串本身当作身份凭证。

### 3. 矩阵与写作方案审查：有 fresh CLI 调用记录，但入口强度不一致

`00_项目控制/v009_第9版/tools/resume_writing.py`：
- `dispatch(..., reviewer=True)` 为 reviewer 使用固定 `REVIEWER="gpt-6.2-sol"`，启动新的 `codex exec --ephemeral` 子进程；
- 从 `events.jsonl` 提取 `thread.started`，读取 `turn.completed` usage；
- reviewer 回答至少要有允许的 decision 与非空 reason；
- `validated.json` 保存 answer、thread_id、usage、response_sha256、model；request.json 保存本次 reviewer 的 instruction 和 inputs；
- 后续矩阵返修复审与写作方案复审确实调用该路径，写作方案通过时还把独立审查 record 写入 `writing_plan_review_request.json`。

这是可追溯的**独立新会话记录**，但其边界是：
1. reviewer 与 researcher 使用同一固定模型标签/CLI 体系，证明的是 session/context 分离，不是不同人员、不同组织或外部身份；
2. `validated.json` 保存 response SHA 和 thread ID，但没有将原始 `events.jsonl` 的 SHA 纳入该 validated record，也没有平台签名/可信第三方 attestation；
3. 对相同 request 复用已有 validated 记录时，不重新验证原始事件日志；
4. 最关键的是 `resume()` 初始输入 `matrix_independent_review.json` 只检查 `matrix_sha256`、`reviewer` 字符串、非空 `invocation_id` 和 decision。它没有要求该文件必须与某个真实 `validated.json`、thread.started、原始 events SHA 或 response SHA 对应。

因此，后续由程序实际派发的 reviewer 调用具备比自报 JSON 更强的 session 记录；但初始 prior_review 仍可仅凭自报字段通过入口检查。整体审查身份认证仍为 **not_verified**。

### 4. v012 总控没有自动生成最终学术审查

- `ai_paper5_strict.py` 的 `review` 命令只是把报告路径交给原 v009 `staged_topic.py review`；没有新的独立 reviewer dispatch。
- `autopilot_v3.step()` 在原 v3 阶段到达 review、materials_pending 等需要真实独立审查的状态时返回 `blocked_by_original_v3_gate`，明确不做同模型内部晋升。
- `ai_paper5_strict.audit_chat()` 对 Chat 搜索数据只返回 `pending_independent_url_and_abstract_provenance`、`native_cli_receipt=false`、`formal_eligible=false`，并明确自报 Chat 工具事件不能替代原生 CLI 来源或独立学术审查。

这是正确的保守行为：总控当前能运行检索前研究者/批评者分离，但没有声称已自动完成最终学术审查。

## 三、材料可行性与材料适足性必须分开

### 1. 方法可行性：证明“有可追溯的获取路径”，不是证明“足以回答问题”

`00_项目控制/v009_第9版/tools/method_paths.py`：
- `select_method()` 要求完整评估 quantitative、secondary_interviews、online_qualitative 三条路径；每条都必须有允许状态和非空理由。
- ready 路径必须有非空 materials、`access="verified"`；online_qualitative 还须区分 public_text/ethnography，民族志另要求 observation verified。
- pass 必须选择 ready 路径；materials_pending 必须保留 unknown；missing_data 只有所有适用路径均 missing 且无 selected 才可归档。
- `verify_material_review()` 核验真实 attempt 目录、receipt/conversion、run_id、pending_independent_review 状态、tool_events、receipt/conversion/events/response 哈希、问题一致或 reviewed_reuse，以及 ready 材料 ID 是否属于该路径回执。

这些校验能把方法判断绑定到某次实际搜索及其原始文件，防止只写“可以获得”却没有回执。但 receipt 状态本身仍是 `pending_independent_review`，它是材料采集回执，不是最终审查凭证，也不证明访问许可、事件发生或材料语义真实。

### 2. 写作前适足性：必须有独立判断，但程序只做 ID/字段门禁

`resume_writing.resume()` 在矩阵 reviewer 的 decision 不是 pass 时停止；decision 为 pass 但没有 `material_adequacy` 时返回 `awaiting_material_adequacy`。随后调用 `material_adequacy.writing_material_status()`：
- assessment 必须是对象；
- `eligible_event_ids` 必须为字符串列表、无重复，且全部属于当前 receipt 的 material_id；
- reason 必须非空；
- support 只能是 sufficient / insufficient / unknown；
- sufficient 至少需要一个 eligible ID；
- insufficient 返回 `insufficient_core_material`，unknown 返回 `awaiting_material_adequacy`，只有 sufficient 返回 ready。

**实际缺口：**
- 字段名叫 eligible_event_ids，但代码实际只把它与 receipt 的 material_id 集合比对；没有验证这些 ID 对应不同事件实体；
- 没有在代码层核验同一事件的转载/重复记录，也没有核验不同来源是否独立；
- 没有最低独立事件数量门槛；一个合法 material_id 即可满足“非空 sufficient”结构条件；
- 没有自动判断这些材料是否真正支持冻结问题中的机制、时间范围和研究对象；这一判断依赖 reviewer 的实质阅读与理由；
- `writing_material_status()` 本身不验证 reviewer 身份或调用凭证。

因此，**材料可行性 ready ≠ 材料适足性 sufficient；material ID 合法 ≠ 独立事件已核真；sufficient 字段 ≠ 程序已证明证据充分。** B10 已指出事件实体去重与反例覆盖的缺口，本轮不重复改造。

## 四、S08 最终冻结：证据一致性硬门槛，不是独立身份门禁

### 1. 最终 review 的放行条件

原 v009 `staged_topic.review()` 对最终阶段仍要求：
- model 标签、非空且唯一 invocation_id；
- evidence_sha256 与当前 merged_literature、theories 及启用的 reality/explanation_exchange/issue_plan/event_comparison 组合哈希一致；
- reason/question 非空，question 写入 state；
- outcome 为 pass 时 academic_value 必须 pass，data_feasibility 必须 pass；
- method_paths 启用时，三条路径须完整评估并选择 ready 路径；
- 启用 qual_search_receipts 时，相关定性材料回执必须通过原始文件及哈希核验。

通过后 state 进入 `s08_ready`。但这仍是报告字段和证据/方法合同，未认证最终报告主体。

### 2. freeze() 的独立释放检查

`staged_topic.freeze()` 只允许 `state.status == "s08_ready"`，并重新检查：
- 最后一条 final report 的 evidence_sha256 与当前证据 hash 相同；
- final.question 与 state.question 相同；
- final.design 非空；
- method_paths 启用时，state.research_method 与 final.method_assessment 重新选择出的标准方法一致；
- qual_search_receipts 启用且方法为定性时，再核所选路径的原始材料回执。

成功后写入 `s08_topic.json`，包含 question、design、research_method、evidence_sha256、review_sha256、mode、scope，并将 state 设为 frozen。

这能阻止冻结后悄悄更换问题、文献、理论、设计或方法；`question_binding.binding()` 又进一步检查 frozen state、最后一条 pass 报告、review hash、question、conversion、framework、receipt、events 与 response 哈希，阻止 06 写作材料链脱离 S08。

但 freeze 不验证 reviewer identity / session receipt。**哈希一致只能证明文件没变，不能证明审查者真实独立、材料真实或理论判断正确。**

### 3. frozen 不是正式生产资格

- `freeze()` 写入的 `formal_eligible` 固定为 false；dev 运行 scope 为 experimental，formal 候选 scope 为 formal_candidate。
- V15 writing plan 生成时也写 `formal_eligible=false`、`review_status=pending`。
- V16 `formal_gates()` 即使看到 gate_status 中所有五项为 true，且语言资源 snapshot 为 passed，仍无条件抛出“Formal writing still requires separately verified upstream receipts”。
- V16 的 draft review 只允许 exploratory；正式模式被列为结构错误，输出 `formal_pass=false`、`independent_review=pending`，并将其定义为单模型技术/风格检查，不是科学审批。

所以当前系统的正式写作阻断是明确的，不应通过伪造 gate flags、把 frozen 改写成 formal，或将单模型风格检查当作独立学术批准来绕过。

**B12：verified（静态源码、调用链和门禁映射完成）；下列实质状态仍 not_verified。**

| 状态 | 判定 | 依据 |
|---|---|---|
| 检索前双会话反诘 | 部分 verified | autopilot 两次 CLI session ID 不同；只证明不同 thread，不是外部身份认证 |
| v009 最终学术审查主体 | **not_verified** | review 报告自报 model/invocation_id；无真实调用凭证核验 |

**后续接通时不得降低的硬规则：**
1. v009 review 报告的 model、invocation_id、critical_receipt 只能作为声明字段；没有真实会话/主体凭证时不得认定独立审查通过。
2. 材料搜索 receipt 只能证明采集批次和文件完整性，不等于学术 review；材料可行性 ready 不等于论证适足性 sufficient。
3. material_adequacy 必须来自独立审查，且要能回查到具体材料和冻结问题；在事件实体去重、来源独立性、反例与机制支持尚未被实质核验时，不得只凭 ID 数量放行。
4. S08 freeze 只冻结实验研究问题/设计/证据版本；`formal_eligible=false` 必须保留，不能自动升级生产。
5. V16 formal gate 当前明确阻断；不得用手工 `true` 字段或单模型自审绕过。

**未做：** 未创建真实 reviewer 会话、未运行 Codex/Chat 审查、未验证身份凭证、未对真实材料作适足性判断、未触发 S08 freeze、未运行 V16 正式写作；未改任何代码/配置/生产登记。本文 verified 仅表示源码合同映射完成。
