## 本轮实现

1. **来源级 receipt 状态**
   - build_source_receipts() 不再因某一来源 URL 未出现在本次 trace、页面未打开、raw events 文件缺失、thread 缺失或 URL 无效而直接丢弃整个 event comparison。
   - 每个 source receipt 现在具有 verification_status=verified/pending 与 verification_reason。
   - verified 仍要求本次 trace、匹配页面打开事件、thread、events/response 路径和 SHA 完整；其余情况保存为 pending。

2. **事实级隔离**
   - 每条 fact 的 source_id 必须解析到 verified receipt 才可能保留原可信度状态。
   - 缺 source_id、缺 receipt、URL 错配、来源不在本次 trace、opened=false 等情况：原事实仍保留，模型原报 status 记录为 model_claimed_status，实际 status 改为 unverified，source_verification_status=pending，写入 uncertain_facts/critical_gaps。
   - 只有 verified receipt 且模型事实 status=corroborated 时，才进入 retained_facts。
   - event_comparison 顶层增加 pending_sources、pending_fact_count、source_verification_status，并始终保持 formal_eligible=false。

3. **下游解释边界**
   - v012 research_exchange prompt 明确规定：只有 retained_facts 且 source_verification_status=verified 的事实可以作为已核验经验支持；uncertain_facts/pending_sources 只能作为待核实缺口，不能被引用或升级为已证事实。
   - 原状态机仍可在有 pending 数据时继续进行探索性解释；但 pending 事实不进入 retained_facts，不获得正式事实资格。此项不是把整个研究流程一刀切停止。

## 测试覆盖

新增/更新测试覆盖：
- 缺失 source receipt → pending，不进入 retained_facts。
- URL 与 receipt 不一致 → pending。
- opened=false → pending。
- fact 缺 source_id 或 source_id 不在 source map → pending。
- URL 未出现在本次 trace → pending。
- 搜索结果存在但没有页面打开 → pending。
- 原始 events 文件缺失 → pending。
- 完整 opened receipt + corroborated fact → retained_facts。
- v012 research_exchange prompt 保留 pending/verified 证据边界。
