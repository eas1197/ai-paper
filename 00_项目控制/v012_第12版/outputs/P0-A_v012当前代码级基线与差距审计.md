### 2.2 autopilot_v3.py

实际自动执行入口：

    python 00_项目控制/v012_第12版/tools/autopilot_v3.py --run-id <id> --theme <主题>

可选参数：--model、--timeout、--max-steps。

它会在原 v009 状态机上执行：
1. 现实观察：调用 Codex CLI，要求真实搜索，并将现实来源 URL 与原生网页事件绑定。
2. 事件比较：调用原事件比较模块。
3. 解释与反诘：分别创建研究者和反方 Codex 会话，检查两者 thread_id 不同。
4. 三层议题定位：形成对象、议题、理论检索计划。
5. 初查与补查：直接调用原 v009 文献控制器及其原生采集器。
6. 到达 s08_ready 时调用原 S08 冻结。

**它不会自动处理 preliminary_review、design_review、final_review 等正式学术审查状态。** 遇到这些状态会返回 blocked_by_original_v3_gate，要求真实独立审查和材料回执。这个停止行为是有意保留原门槛，不是自动闭环已经完成。

## 4. Chat、Codex 与独立审查的实际连接状态

### 4.1 Codex 原生搜索

v012 的 autopilot 调用 11/v007 的 codex_literature.py，并使用 04/v012 的原生搜索 Schema/注册信息。v009 的 staged_topic.py 直接使用原 collect()、evidence()、group()、url_event()，因此没有另造一套宽松文献检索器。

**但目前只有代码路由和离线测试证据，没有 v012 从新研究 ID 启动并完成真实 Codex 搜索的归档记录。**

### 4.2 Chat 原生网页搜索

chat-task 会读取原 v3.2 九刊、三层议题定位和原摘要 Schema；chat-audit 能检查题录、作者、期刊、年份、摘要定位、摘要短摘、相关性和去重。

但 audit_chat() 固定返回：
- status=pending_independent_url_and_abstract_provenance
- native_cli_receipt=false
- formal_eligible=false

因此 Chat 搜索当前是**结构合格的待核候选**，不是原 3.x Codex 原生文献收据。它不能直接让原 v009 文献门禁放行。Chat 和 Codex 的统一交接仍是 P0-B。

### 4.3 独立审查

已有两种不同层次的能力：

1. **解释反诘会话隔离：** autopilot 为研究者和反方启动不同 Codex 会话，检查 thread_id 不同。这能支持反方反诘，不等于正式学术审查。
2. **正式学术审查：** 原 v009 的 review() 接收 gpt-6.2-sol、invocation_id、evidence_sha256、理由和问题，并校验审查结果与当前证据绑定。v012 autopilot 遇到初审、设计审查和终审时停止，不自动派发审查者。

另一个重要限制：v009 review() 只检查报告中声明的 model、非空 invocation_id 和证据哈希，没有在该函数内核对 invocation_id 是否对应真实 events.jsonl / thread.started 会话回执。06 record_review() 也主要校验报告字段及材料哈希。resume_writing.py 对它自己派发的矩阵和写作方案审查，会实际启动 Codex 并保存 thread_id、用量和响应哈希；但这不自动覆盖 v009 的初审、设计审查、终审及 06 转换审查。

因此，当前不是“所有独立审查均已真实调度并验证”，而是**局部有真实独立会话调用，核心学术门禁仍依赖外部报告提交，且报告身份与原始会话凭证尚未完全闭环**。

## 5. 06、V15、V16 与定量路径

### 5.1 06 定性材料

06/v005 提供：
- 定性问题转换；
- 二手访谈/公开网络材料的原生搜索；
- 材料来源、时间、对象、定位、相关性、边界和访问条件；
- 框架形成及定向材料收集；
- 经验矩阵、反例与竞争解释；
- 最多两批材料定向修复；
- 独立材料审查和矩阵返修接口。

v012 的 materials 命令直接调用 06/v005，但每次需要外部提供 conversion、review 或 matrix 之一。autopilot 不负责从冻结设计自动准备这些输入、按顺序调用全部阶段、判断回执并推进到写作。

06/v005 模块说明也明确：正式编码、完整经验分析和正文写作仍在其范围之外。它是材料获取、可行性复核和经验矩阵模块，不是独立完整的定性研究引擎。

### 5.2 V15

V15 writing_plan.py 将已审查的框架、维度、章节任务和来源 ID 渲染成写作方案，并核对冻结问题、矩阵和框架哈希。它生成的是**写作计划**，不是论文正文。

原 v009 resume_writing.py 调用 V15 produce()，并能对矩阵、返修及写作方案进行部分真实独立审查；其代码没有调用 V16。

### 5.3 V16 / ai-writer 4.0

V16 目前实际能力：
- route：定量返回原 V14；定性进入 V16；
- prepare：读取 V15 写作包和语言资源，生成逐节任务、来源绑定、ST 风格规则和论证审查提示；
- submit：接收实际稿件和主张证据台账，做章节、来源定位、哈希和确定性语言检查，并生成待审请求。

V16 **不会自己调用语言模型写正文**。正文必须由 Chat 或 Codex 根据逐段任务实际生成，再提交给 V16 检查。其 formal_gates() 即使看到 JSON 中的 gate 标志，也仍会因缺少独立验证器而阻止正式 G7 放行。

v007 run_mode.py 已有独立的 --writer4 route|prepare|submit 实验分派，但 v012 严格适配器没有调用这条分派；v012 的 resume-writing 仍指向原 v009 resume_writing.py。因而，V15 与 V16 分别存在，不代表 v012 已接通 V15→V16。

### 5.4 定量路径

原定量模块仍保留：
- 06/v004：定量数据、变量、分析计划、估计、诊断、独立复算和 G6；
- 07/v014：原定量写作、G7 和交付。

v009 method_paths.py 把 quantitative 标记为 existing_quantitative。但 v012 严格适配器冻结后的 materials 命令固定调用 06/v005 定性材料程序，resume-writing 固定调用原 v009 定性写作续接器。**目前没有在 v012 后半段看到 quantitative → 06/v004 → 07/v014 的统一调度实现。**

这意味着“定量原路径没有被修改”成立；“定量已经接入 v012 总控”尚不成立。
