# B17｜现实观察与跨事件比较来源核验差异

**状态：verified（只读差异审计；GAP-F01 仍未关闭）。**  
**分支：** dev/v3.1-abstract-acquisition  
**范围：** 对照 v009 reality 保存/校验、v009 event comparison 协议及 v012 autopilot 派发；未修改代码，未执行真实网页搜索。

## 一、结论

**现实观察阶段在 v012 autopilot 中有额外的原生搜索来源核验；跨事件比较阶段没有对应核验。** 但现实观察的核验结果也没有形成逐来源、可由接收器独立复验的持久化凭证。因此两阶段都尚未达到“每条关键事实可追溯到本次真实搜索/打开事件”的要求，GAP-F01 仍然打开。

## 二、现实观察阶段（reality）

### v009 原生接收函数

- `record_reality()` 只要求 packet 有 `phenomenon`、`search_focus`、`sources`。
- 每个 source 只检查 `url`、`kind`、`supports`、`limits` 四个字段非空。
- 随后保存 `reality.json`，并把整个 packet 的 digest 写入 `staged_topic.json`。
- `load_reality()` 只核对文件 digest 是否变化。

**缺口：** v009 直接调用 reality CLI 时，`record_reality()` 本身不检查 HTTPS/netloc，不检查 URL 是否出现在本次真实网页事件中，也不要求 source_id、event_id、thread/session 或原始日志哈希。

### v012 autopilot 外层增强

`autopilot_v3.step()` 的 reality 分支：

1. 调用 `engine.call(..., must_search=True)`，要求本次会话存在原生网页搜索 trace。
2. 调用 `source_proof(packet, trace, url_event)`。
3. 对每个 source 检查 `heritage.valid_https(url)`，并要求 `url_event(url, trace)` 能找到匹配事件。
4. 通过后才把 response.json 交给原 v009 `reality` 命令。

这比 v009 直接接收更严格，但仍有边界：

- `source_proof()` 的证明只在 autopilot 当前调用中完成；没有把每个 source 对应的 event_id 写回 reality packet 或独立 receipt。
- `v5_native_calls.json` 会记录该次调用的 thread、events/response SHA，但记录粒度是 attempt，不是 source_id→URL→event_id。
- 11/v007 `url_event()` 的 `proof()` 接受 URL 出现在 web_search 结果列表；也接受 open_page/find_in_page action。当前调用没有要求每个来源必须有独立的页面打开凭证。因此“搜索结果中出现”可能满足，不等于已核读页面。

## 三、跨事件比较阶段（event comparison）

### v012 autopilot 派发

`autopilot_v3.step()` 在 `explanation_exchange` 阶段派发 `events` 任务时：

- 调用 `engine.call(work, "events", task)`，没有传 `must_search=True`。
- `engine.call()` 虽然返回 trace、url_event、session 和 folder，但事件分支没有消费 trace/url_event，也没有对 packet.sources 运行 source_proof。
- 随后只把 response.json 交给原 v009 `event_protocol.py --dev-run ... --input ...`。

因此：事件阶段即使没有任何原生网页搜索事件，也不会因为缺少 trace 而在 autopilot 派发层被拦截。

### v009 event_protocol 接收

`compare_events(packet)` 当前做了这些检查：

- event identity 非空，且同一 identity 不重复；
- fact 的 statement、use、key 字段有效；
- fact.source_id 必须存在于 packet.sources；
- 对应 URL 的 `urlsplit(url).scheme` 必须等于 `https`；
- fact.status 必须属于既定可信度枚举；
- 把 corroborated 与其他状态分入 retained/uncertain，并保留关键不确定项。

**缺口：**

- 不验证 URL 是否有有效 hostname/netloc、是否可访问。
- 不验证 URL 是否出现在本次 Codex web_search/open 事件。
- 不验证 source_id 是否绑定具体 event_id、thread_id 或原始事件文件。
- 不验证两个事件是否由独立来源支持；不同 event identity 可以引用同一 source_id/URL。
- `event_protocol.main()` 只把 `input_sha256`、`exchange_sha256`、`reality_sha256` 和 `formal_eligible=false` 写入 event_comparison.json；没有绑定 events.jsonl SHA、response SHA、thread/session ID 或 source→event 映射。
- 输出的 event_comparison.json 保留事实中的 source_id，但不保留原 sources URL map；URL 仍在输入 response.json，只有 input_sha256 可间接绑定输入，缺少显式的原始事件凭证路径。

### 进入原状态机的门槛

原 v009 `exchange` 分支会检查：

- event_comparison.event_count 至少为2；
- event_comparison.reality_sha256 与当前 reality_sha256 相同；
- explanation_exchange packet 符合字段合同。

随后把 event_comparison 的 digest 写入 state。**这里没有再次核验 source_id→URL→真实网页事件的关系。** 因而只要事件数量与 reality hash 满足，来源仅通过 HTTPS/字段检查的比较结果就可能进入后续解释交换。

## 四、两阶段差异表

| 核验维度 | Reality（v012 autopilot） | Event comparison（v012 autopilot + v009） |
|---|---|---|
| 必须有本次 web_search trace | 是，must_search=True | 否，未传 must_search |
| URL 格式 | HTTPS + URL 可在 trace 中匹配 | 只检查 scheme=https |
| URL 与本次事件绑定 | 调用时用 url_event 临时核验 | 无 |
| 是否要求实际打开 | 不要求；搜索结果出现也可匹配 | 不要求 |
| source_id / event_id | reality packet 没有持久化映射 | source_id 仅指向 URL map，无 event_id |
| 原始日志 SHA | attempt ledger 有 events SHA，但 packet 不引用 | event output 不保存 events SHA |
| thread/session | attempt ledger 有 thread；source 不绑定 thread | output 不保存 thread/session |
| 进入下一阶段 | reality packet digest + v012 临时来源核验 | event_count≥2 + reality_sha256 + packet schema |

## 五、B18–B21 的最小修复方向

本项只审计，不实施下列修复；后续按 B18、B19、B20、B21 分开完成。

1. **B18：** 为事件来源定义可验证的 source receipt；至少绑定 source_id、canonical URL、真实 Codex item/event ID、原始 events 文件路径与 SHA、thread/session、必要的打开状态。每条关键 fact 必须引用有效 source_id。
2. **B19：** 事件派发必须要求真实搜索 trace，并在接收端验证 source URL 与当前 attempt 的真实 search/open event 对应；不能只检查 HTTPS 或模型自报 ID。
3. **B20：** 缺少原始事件、来源错配、未打开/无法核实的关键来源应进入 pending/unverified，不得以 corroborated 身份进入正式事实矩阵或 exchange 的有效事实集。
4. **B21：** 增加负向测试：伪造 HTTPS URL、无 hostname、旧 attempt URL 冒用、source_id 不存在、event_id 错配、缺少 events.jsonl、缺少打开凭证、同一来源被伪装为两个独立事件。

**验收边界：** 只有真实原始日志能证明来源来自本次执行，且每条关键事实与来源事件绑定后，GAP-F01 才能关闭。不能以本报告或离线 mock 代替真实来源核验。
