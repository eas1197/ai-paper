## 本轮防护与验证

1. **当前执行上下文绑定**
   - compare_events 只有在显式提供 current execution receipt 时才可能将事实标为 verified。
   - receipt 的 thread_id、events_path、events_sha256、response_path、response_sha256 必须逐项与当前执行上下文一致；缺少上下文时一律 pending。
   - event_protocol CLI 要求 events.jsonl 与 response.json 位于同一个 native attempt 目录，避免拿旧 attempt 的日志配当前 response。
   - 原始 events/response 路径必须位于当前研究 run 内；越界路径直接拒绝。

2. **负向场景**
   - 伪造/无 hostname HTTPS URL。
   - 缺少 source receipt 或 fact 缺 source_id。
   - source_id 与 receipt.source_id 错配。
   - event_id 与 open_event_id 错配。
   - source URL 与 receipt URL 错配。
   - 旧 attempt 的路径被用于当前 execution。
   - thread_id 错配。
   - events.jsonl SHA 错配。
   - response.json SHA 错配。
   - events 与 response 位于不同 attempt 目录。
   - receipt 文件路径越出当前 run。
   - 搜索结果命中但没有页面打开。
   - open_page action 的 URL 与来源 URL 不一致。
   - 缺少 raw events 文件。

3. **状态语义**
   - 来源/事实的字段缺失、错配或未打开：pending/unverified，保留原始陈述与 model_claimed_status，不进入 retained_facts。
   - 运行路径越界、events/response 跨 attempt 等执行上下文结构错误：明确拒绝。
   - 合法的同 attempt、同 thread、同 URL、真实打开事件和一致 SHA 的 receipt 正向测试仍可进入 retained_facts（前提是 fact 原始 status 为 corroborated）。
