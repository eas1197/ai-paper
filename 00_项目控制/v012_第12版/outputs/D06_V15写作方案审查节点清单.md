# D06：V15 写作方案审查节点清单

**状态：** verified（依据 V15 原模块、输入/输出合同、上游快照绑定函数与既有测试完成节点映射；本项为文档任务，不新增写作门禁）。

## 一、节点定位：V15 是方案生成器，不是完整写作审查器

V15 的正式产物是 `writing/论文写作方案.md` 与 `writing/writing_plan_review_request.json`。它将研究问题、方法路径、章节任务和来源索引整理为可审查的写作方案，并为审查者提供审查要点和输入指纹。

**当前实现只完成“生成方案 + 生成待审请求”。** `writing_plan.py` 没有审查结果接收、review 状态更新、返修或正式放行函数；CLI 也只有 `--dev-run` 和 `--input`。因此 `review_status="pending"` 是真实当前状态，不是审查通过。

## 二、输入合同与结构检查

### 2.1 研究问题与方法

输入必须提供：
- `method`：`secondary_interviews`、`online_qualitative` 或 `quantitative`；
- 非空核心问题 `core_question`；
- 非空回答策略 `answer_strategy`；
- 章节数组 `chapters` 与来源映射 `sources`。

若当前 run 已有 `s08_topic.json`，V15 会核对冻结问题和研究方法与输入一致；**若 S08 文件不存在，当前函数并不会拒绝生成方案**。因此方案可作为实验性草案提前生成，但不能因此被视为已通过 S08 或获得正式研究资格。

### 2.2 来源索引

每个来源必须提供：
- 非空证据 ID；
- `kind`：`theory`、`literature` 或 `empirical`；
- 非空 `label` 与 `locator`。

每节必须提供非空的 `source_ids`，且每个 ID 必须存在于来源映射中；同时提供章节/分节任务、拟论证内容和材料用途。输出会生成材料索引，方便审查者回查定位。

**限制：** V15 对来源的确定性检查主要是 ID、类别、标签和定位字段，不会自动打开来源、核验正文内容或证明来源支持拟论证主张；来源真实性和推论范围仍需审查者判断。它也没有强制每个章节 source ID 必须与 06 经验矩阵中的 evidence ID 完全相同。

### 2.3 定性框架与章节顺序

定性路径必须给出：
- 已有文献及解释、已有解释不足；
- 理论选择理由、结合问题的理论推演；
- 相对已有解释的增量、各维度如何合答问题并与理论对话；
- 案例背景、案例选择、资料来源和研究方法；
- 至少一个分析维度，每个维度包含唯一 ID、标题和理论推演。

章节顺序固定为：

`problem → framework → case → 各理论维度（按输入顺序） → conclusion`

每个维度形成独立分析章节，不能被通用的“经验分析/理论讨论”标题替代。每个分析维度章节必须同时引用理论类与经验类来源，避免只有材料描述或只有理论复述。

### 2.4 方案输出

`render()` 生成：
- 核心问题与回答路径；
- 分析框架形成过程；
- 案例与材料设计；
- 正文章节及分节任务；
- 各节材料用途与来源 ID；
- 材料索引。

可选的段落任务列表必须非空。V15 只生成方案结构，不生成正文论证，不替代 V16 的逐段写作与审查。

## 三、06 经验矩阵接入与快照绑定

### 3.1 当前检查

若输入提供 `analysis_matrix` 路径，V15 会：
1. 将路径解析到当前 run 内，并要求位于 `qualitative_framework` 目录；
2. 读取矩阵，若输入提供 `question_binding`，调用 v009 `question_binding.binding()` 重新核对绑定；
3. 要求矩阵维度 ID 顺序与写作框架维度顺序完全一致；
4. 读取对应框架文件，核对矩阵 `framework_sha256)、核心问题和核心概念；
5. 在审查请求中记录矩阵文件 SHA-256。

若没有 `question_binding`，仍会核对矩阵路径、维度顺序、框架哈希、核心问题和核心概念；但不会执行 question-binding 分支中的完整问题/收据绑定检查。

### 3.2 question_binding 分支的强绑定

v009 `question_binding.binding()` 要求：
- 当前研究已冻结为 S08；
- v009 状态为 frozen，最后审查结果为 pass；
- 最终审查问题、证据哈希、review hash 与冻结文件一致；
- 定性转换问题、核心问题和框架一致；
- 当前 run、框架收据、原始 events/response 哈希一致；
- 若有返修父收据，递归验证父回执哈希及新增/退役材料 ID 的谱系。

返回值包含 question ID、semantic version、freeze SHA、framework SHA 与 receipt SHA。

**接口边界：** V15 将 `question_binding` 设计为可选输入；V15 自身不会生成它。06/v005 `framework.analysis_matrix()` 的当前输出也没有 `question_binding` 字段。因此，若使用强绑定分支，上游必须先提供与当前矩阵完全匹配的绑定对象及矩阵字段；目前没有在 V15 内自动补齐该字段的函数。不能把可选强绑定描述成默认已执行。

### 3.3 未覆盖的矩阵审查状态

V15 当前核对矩阵与框架的哈希、维度和问题关系，但没有要求 `matrix.status` 必须已经通过独立审查，也没有要求 `theoretical_increment_status` 从 `proposed` 变为已审查状态。结合 D05 的结果，06/v005 矩阵仍为 `pending_independent_review` 时，V15 仍可能生成实验性方案。

这不是矩阵已经通过，而是 V15 当前没有把矩阵独立审查作为确定性前置门槛。正式写作前必须补上矩阵审查接续，不能依靠方案结构检查替代。

## 四、审查请求与审查标准

V15 写入 `writing_plan_review_request.json`，记录：

| 字段 | 作用 |
|---|---|
| `run_id`、`run_mode` | 绑定当前实验 run |
| `method` | 写作方法路径 |
| `requested_deliverable` | plan 或 full |
| `status` | 固定为 `plan_prepared` |
| `input_sha256` | 输入任务包哈希 |
| `plan_sha256` | 生成方案文件哈希 |
| `topic_sha256` | 有 S08 时记录冻结主题文件哈希，否则为 null |
| `analysis_matrix_sha256` | 提供矩阵时记录矩阵文件哈希，否则为 null |
| `review_criteria` | 四项审查标准 |
| `review_status` | 固定为 `pending` |
| `question_binding` | 输入提供时保留 |
| `full_draft_entry` | 标记完整稿件入口状态 |

四项审查标准：
1. 各章和各节承担可执行的论证任务，材料定位可回查；
2. 证据范围与计划主张相符，跨章节衔接能回答核心问题；
3. 定性维度由理论推演，逐章结合经验材料与理论解释，结论整合各维度并回应既有理论；
4. 定量方案遵循正式设计和结果口径，结构检查不构成正式稿件验收。

**缺少的审查合同：** 当前请求没有定义审查结果 schema、审查者身份、实际 invocation/thread、审查报告哈希、具体证据 ID 的逐项评语、返修任务 ID 或状态转移规则。V15 没有 `--review` 参数，也没有消费审查报告的函数。审查请求只是供后续独立审查使用的任务材料。

## 五、实验写作政策与完整稿件边界

v007 `run_mode.py` 将实验写作政策绑定到 run manifest：
- 默认 `deliverable="plan"`；
- 只有新建实验时显式启用 `--full-paper`，才记录 `deliverable="full"`；
- 策略写入 manifest 并保存 SHA-256，后续校验策略未变化。

V15 对完整稿件入口的记录：
- 定量且显式授权 full：`existing_quantitative_with_upstream_gates`，沿用既有定量正式路径；
- 定性且显式授权 full：`planned`，仅标记计划中的入口；
- 默认 plan：`not_requested`。

因此，V15 并没有实现定性全文写作。模块说明也明确将定性全文入口、材料采集、编码、分析和逐段写作细则列为待实现；不能把 `--full-paper` 的配置标记当作定性正文已经可运行。

## 六、状态、返修与正式放行边界

当前 V15 的唯一输出状态是：
- 方案文件已生成；
- review request 的 `status="plan_prepared"`；
- `review_status="pending"`；
- `formal_eligible=False`。

在 V15 中未发现以下函数或接口：
- 独立审查结果接收；
- pass/revise/need_evidence/reject/unable_to_review 状态机；
- 审查者身份与真实执行凭证核验；
- 方案返修和版本比较；
- 返修后输入/方案/矩阵哈希失效处理；
- 通过后正式稿件入口授权。

所以不能把 `plan_prepared` 当成审查通过，也不能把方案生成器的结构校验当成独立学术审查。D09–D20 的审查任务包、结果 schema 和真实凭证接收应另行完成；D06 只映射现有节点，不提前补造放行状态。
