# ai-paper 5.0：严格继承 3.x 的兼容入口（00/v012）

这版不是另写一个缩水研究流水线。原 v3.2 控制器、学术审查、来源采集、材料适足性、返修与正式研究问题冻结仍是权威。过去 v010/v011 的 14 个阶段只作历史探索，不能用它们的少量 JSON 字段替代旧学术关卡。定量程序和 main 未改动，当前不运行 Stata。

## 原始依赖

- 00/v009：v3.2 分阶段选题、独立学术审查、5+35（正式）/5+5（实验）、九刊加核验专业刊、三层议题检索、补查时机、S08 冻结与学术退回。
- 04/v012 与 11/v007：Codex 原生 --search、真实题录与摘要 URL 的工具事件、作者年份与期刊身份、逐篇摘要、跨阶段去重、批次预算、缺额恢复。直接调用原 v009 入口，不用 V11 宽松接收器。
- 06/v005 与 00/v009：定性材料收据、独立材料适足性、定向查证、矩阵与返修，仍保留。
- 07/v015 与 v016：定性写作计划、证据与学术语言；尚需上游真实审查，不假称正式 G7 已通过。

## CLI 真实 3.x 路径

在完整仓库、Python 3.11+ 和已登录的 Codex CLI 环境：

    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py doctor
    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py init --run-id topic_001 --theme 社区治理
    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py status --run-id topic_001

根据原 3.x 的 prepare 指令生成并提交现实/独立反诘/议题计划和真正独立学术审查材料，命令为 reality/exchange/issue/review 并指定 --report。进入 initial 或 supplemental 后：

    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py advance --run-id topic_001

此命令会执行原 v009 控制器，由其调用原 Codex 文献采集和全部预算、来源与去重检查。没有实际旧学术门槛通过时，绝不跳过材料和写作门槛。不要使用早期 v011 run 声称完整继承。

## ChatGPT 按同一套规则检索

ChatGPT 当前对话有内置网页检索，但独立 Python 进程不能直接激活本对话。供 Chat 对话使用的任务和审计：

    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py chat-task --run-id topic_001 --phase initial --output chat_task.json
    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py chat-audit --task chat_task.json --response chat_papers.json --output chat_audit.json

chat-task 会读取真实 v3.2 九刊和三层定位、原 v012 学术摘要提示词与原 Schema，要求 Chat 逐篇打开题录、摘要、核对作者年份期刊、短摘与去重。chat-audit 保留已符合原要求的结构候选，却标明 pending_independent_url_and_abstract_provenance：这些材料的 Chat 网页工具记录不能伪装为原 Codex events.jsonl。尚未实现将 Chat 回执自动作为旧原生收据放行的可信转换，所以不能称 Chat 已完整自动接入原 3.x 正式流水线。

## 尚需验证

原 3.x 各模块离线回归以及真实联网实验必须独立验收。真正的无人值守单 AI 完整研究，仍须为现实观察、独立学术审查、06 材料分析与 07 写作增加非降级的自动调度；缺独立回执时应停止。本版主要是把准确的源版本重新接回入口并阻止功能退化，不谎称已产出正式合格论文。
