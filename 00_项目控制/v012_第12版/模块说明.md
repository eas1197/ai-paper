# ai-paper 5.0：严格继承 3.x 的兼容入口（00/v012）

这版不是另写一个缩水研究流水线。原 v3.2 控制器、学术审查、来源采集、材料适足性、返修与正式研究问题冻结仍是权威。过去 v010/v011 的 14 个阶段只作历史探索，不能用它们的少量 JSON 字段替代旧学术关卡。定量程序和 main 未改动，当前不运行 Stata。

## 实际调用图与权威归属

```text
strict CLI（唯一5.0开发入口）
 ├─ doctor：静态合同；--probe-executor 仅原CLI登录诊断，不证明搜索
 ├─ init / prepare / status / advance / reality / exchange / issue / review
 │   └─ 00/v009 staged_topic.py：原阶段、证据、预算、审查、S08冻结
 │       ├─ 00/v009 event_protocol.py：跨事件事实与来源回执
 │       └─ 原11/v007 + 04/v012：九刊、摘要、工具事件、去重、批次
 ├─ autopilot_v3：有限步调度，调用原3.x和原Codex执行器
 │   └─ 原审查待办 → review_task / review_wait（缺真实独立回执即等待）
 ├─ chat-task / codex-task → C04冻结同一任务 → 各自真实宿主
 │   └─ chat/codex-receive / literature-receive / merge-results
 │       （来源、执行绑定、原回执核验；候选/合并不自动推进）
 ├─ 已核验原S08 → frozen_route
 │   ├─ secondary_interviews / online_qualitative
 │   │   └─ 06/v005材料、原v009适足性/返修 → V15计划及原独立复核
 │   │       └─ writer4 route / prepare / submit → V16（探索性待审）
 │   └─ quantitative → 原06/v004 plan → 原06分析及07/v014写作
 │       （当前strict仅准备计划，真实分析和正式G6/G7未运行）
 └─ runtime_log / advance_trace / run-summary：观察、追溯，不授予学术通过
```

原研究状态存于00/v007/runs_dev/<run_id>内的原 run_manifest/staged_topic；v012只路由、冻结任务合同、接收和记录观察，不建立平行学术状态机。Chat当前对话和本地Codex是不同宿主，不能互相伪造工具事件或独立会话；任务包、执行绑定、真实来源及审查记录分别核验。候选结构成功、命令退出0、观察日志和正式学术通过须分别判断。

## 唯一用户 CLI（开发候选）

生产注册仍为00/v005（`00_项目控制/v005_第5版/module_registry.json`）；v012不是已启用生产版本。切换必须先完成真实端到端验收并由用户另行明确授权。

在完整仓库、Python 3.11+ 环境；真实 Codex 调用另需已授权并登录的本地 CLI。默认 doctor 仅静态，登录诊断需显式 --probe-executor，不验证真实搜索：

    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py doctor
    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py init --run-id topic_001 --theme 社区治理
    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py status --run-id topic_001

根据原 3.x 的 prepare 指令生成并提交现实/独立反诘/议题计划和真正独立学术审查材料，命令为 reality/exchange/issue/review 并指定 --report。进入 initial 或 supplemental 后：

    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py advance --run-id topic_001

此命令会执行原 v009 控制器，由其调用原 Codex 文献采集和全部预算、来源与去重检查。没有实际旧学术门槛通过时，绝不跳过材料和写作门槛。不要使用早期 v011 run 声称完整继承。

## ChatGPT 按同一套规则检索

ChatGPT 当前对话有内置网页检索，但独立 Python 进程不能直接激活本对话。供 Chat 对话使用的任务和审计：

    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py chat-task --run-id topic_001 --phase initial --output chat_task.json
    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py chat-audit --task chat_task.json --response chat_papers.json --output chat_audit.json

chat-task 会读取真实 v3.2 九刊和三层定位、原 v012 学术摘要提示词与原 Schema，要求 Chat 逐篇打开题录、摘要、核对作者年份期刊、短摘与去重。chat-audit 保留已符合原要求的结构候选，却标明 pending_independent_url_and_abstract_provenance：这些材料的 Chat 网页工具记录不能伪装为原 Codex events.jsonl。尚未实现将 Chat 回执自动作为旧原生收据放行的可信转换，所以不能称 Chat 已完整自动接入原 3.x 正式流水线。

## 尚需验证

原3.x离线回归与真实联网实验分别验收；I22基线已有457项去重离线回归、4项归档测试通过。现实、事件、反诘、议题与文献的有限步调度以及冻结后显式候选接口已有离线合同；真实宿主、独立审查、真实材料分析和写作正式放行仍未完成，无人值守全流程不宣称已验收。缺真实回执时停止。本版主要是把准确的源版本重新接回入口并阻止功能退化，不谎称已产出正式合格论文。


## 内部调度实现（用户经 strict autopilot 子命令调用）

内部实现 tools/autopilot_v3.py；用户仅经统一 strict CLI 的 autopilot 子命令显式启动。先检查原3.x组件，自动初始化真实00/v009运行，然后使用旧11/v007的 Codex 登录、只读沙箱、--search与结构化回执工具处理现实观察、跨事件比较、隔离反诘和三层定位。到文献阶段直接调用旧staged_topic.py原生采集，包含批次、原九刊、逐篇核验、预算和去重；绝不写一个简化版检索器。原03/06/07业务门槛保持。

    python 00_项目控制/v012_第12版/tools/ai_paper5_strict.py autopilot --run-id real_study_001 --theme 社会生活

单AI的研究与反诘必须分开启动真实Codex执行会话，记录真实thread_id和工具事件。全球研究调用预算来自原00/v007/dev_profile.json；搜索批次预算仍由旧3.x掌管。到preliminary_review、design_review、final_review会准备独立审查候选和等待记录，缺真实授权时不自动晋级，不能让同模型角色扮演补造 gpt-6.2-sol 独立审查凭证；审核后重新启动可继续。冻结后的定性、定量显式接续入口已实现离线合同；autopilot不会自动完成冻结后真实取证、独立适足性和正文正式审查。

ChatGPT不能被独立Python直接唤起为本对话的内置工具；可使用上述chat-task/chat-audit路径按完全相同来源、摘要和期刊合同检索，仍不伪造旧CLI回执。


## 原版06、07及事实比较的完整调用入口

严格兼容适配器还提供 event-compare --report <事件原始输入.json>，materials --attempt attempt_001 --conversion <转换记录.json>（或 --framework <框架.json>、--matrix <分析发现.json>、--review <独立评审.json>），resume-writing --attempt attempt_001。它们直接执行旧00/v009/event_protocol.py、06/v005/qual_materials.py、00/v009/resume_writing.py，保留旧验证器和全部预算与来源哈希，不采用新5.0的较宽松合格判断。没有独立审查和真实材料时会被旧程序拦截。

用户 CLI 实际命令以 `commands` 和子命令 `--help` 为准；历史 E01 命令索引见 [E01](outputs/E01_唯一用户入口与命令索引.md)。`review-task`/`review-counts` 是候选准备及观测，不代表真实派发或独立认证。

`commands` 只读返回实际 parser 的子命令列表，`prepare --run-id` 读取原 v009 阶段任务。`autopilot` 是显式执行入口，不自动授予真实独立审查权限。

## H03 定量计划接续

`quantitative-plan --run-id <原冻结run> --input <同run的06输入JSON> --output <同run的cli_outputs中新计划.json>` 只调用原06/v004 `plan`，仅接受冻结方法 quantitative 与 prepare phase。不会执行估计、Stata、approve 或推进 G6，不能将计划作为正式结果。真实原G5/06输入仍须另行满足。当前 CLI 共26个子命令，以 `commands` 实际枚举为准。
