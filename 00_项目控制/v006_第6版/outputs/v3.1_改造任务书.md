## 二、阶段和任务顺序

延续 S01 发现机会、S02/S03 生成和具象化问题、S04-A/S05-A/S06-A 初查→解释→反诘、S04-B 及正式复核、S07 反方审查、S08/G5 裁决冻结。每个阶段沿用现有执行主体和进度回执。`READY` 在候选流程明确显示为“可投入正式查证”，无新增通过等级替代 G4 或 G5。

| 批次 | 只在该批获授权后执行 | 交付与放行 |
|---|---|---|
| 开发准备 | A01、A02、A03 | 学术检查、S07 覆盖与失效规则、原始委托锁定。交用户和独立审查确认。 |
| 第一批 | P0-01 → P0-02 | 问题角色、方法适配、稳定版本与演化；消费现有 `evidence_id` 和来源引用，缺口显式标待核。本批锁定引用形状，无新增定位验证实现。 |
| 第二批 | P1-02 基础接口 → P0-03 | 读取并核对当前 G4 原文身份、哈希、既有定位与复核状态，建立正式审查覆盖及冻结凭证；重用 04 校验。 |
| 第三批 | P1-01、P1-02 完整实现、P1-03 | 完成推断链、跨格式与人工定位复核的必要子集后开展正式全文对话验收。计量与内容分别验收。 |
| 第四批 | P2-01、SYS-01 | 正向与兼容验收。各批随手保留输入版本、快照及兼容断言，第四批统一签收。 |
| 最后 | 独立审查 | 汇总技术与真实业务证据，另行决定是否启用。 |

## 三、工程任务及建议契约

以下字段、文件名为开发任务中的建议规格。交换记录使用现有项目的 UTF-8 JSON 和哈希工具；对新增对象发布独立版本，不给旧字段换义。任务级条件与用例编号见矩阵。

### P0-01 · 问题分类与候选池

**对象**。新版本 00 的 `topic_evidence.py`、`topic_run.py`、`topic_tasks.py` 和候选 Schema；05 读入映射。沿用 `opportunity_id`、`question_id` 和阶段记录。独立版本的选题 bundle 增加 `question_type` 枚举 `primary / subquestion / measurement_diagnostic / feasibility_task / robustness_task`。共同字段 `run_id, question_id, revision, opportunity_id, text, population, comparison, scope, concepts, answer_value, lifecycle_status`。仅 `primary` 可进入 `primary_candidate_ids`；其 `parent_ref` 为空，并声明独立的理论或现实用途。其他四类须有 `(question_id, revision, revision_sha256)` 父引用。辅助项可挂在主问题或其子问题下，最终必须回到一个主问题。诊断、数据、稳健性项不得以仅变更类型的方式继承主候选资格。

**校验及交付**。引用同 run、存在、无环，辅助项无父级或直接出现在候选选择中必退回。研究对象、作用过程和解释目标相同的测量方案挂同一主问题。语义是否同题交现有审查者一次判断，程序强制记录 `duplicate_of`、`merged_into` 或实质差异理由。主问题按 `draft → under_review → candidate → selected_for_g4 → formal_reviewed → frozen` 或 `parked / rejected / withdrawn`；辅助项独立为 `pending / resolved / blocked / obsolete`。通过的机会和主问题在进入下一阶段前必须有去向（纳入、并入、暂缓、退回、淘汰），可整批关闭并逐 ID 给原因。无合格主问题可返回或停止。诊断可触发主问题新版本、降级或撤回。描述性主问题如果有独立现实或学术价值仍可成立。默认新增模型派发 **0**。

### P0-02 · 问题演化、贡献识别和 READY

**对象**。00 新版 `topic_evidence.py`、`topic_review.py`、`topic_run.py`、`topic_formal.py`，05 候选映射。稳定 `question_id` 表示同一研究主线，实质改写追加 `revision`；真正新分支用新 ID 和 `derived_from`。`question_revision_sha256` 对锁定的语义载荷做版本化规范序列化，包含题句、对象和分母、时间与地域、结局、比较、关键概念、解释目标；排除时间戳、展示用字段和状态。原文题句仍保留。修改父子关系、作用对象、人群、结局、观察窗或方向须重新验收；只改展示字段时语义哈希稳定。题句机械格式等价按 A02 规则核对，保存原始字节及差异，不用模糊归一化吞掉语义改动。相同 `(run_id, question_id, revision)` 与不同内容冲突拒收。保留 Q→X→C→Q 的既有解释和反诘结构。

**演化记录**。一条 `change` 至少包括 `from_ref, to_ref, made_at, reason, old_proposition, old_scope, retained, changed, resolved_gap, new_knowledge, competing_explanations, evidence_ids, answer_delta, standalone_value, disposition`。`from/to_ref` 可读回原始和新题全文，原命题／范围也随记录锁定。`answer_delta` 写旧题典型答案、新题可能出现的不同答案、对原来理论或现实判断的实际变化、结果不能区分时该怎样降级。贡献枚举为 `theory / mechanism / design / measurement / empirical_context / replication`，允许主次类型，并逐类给 `claimed / supported / unconfirmed / rejected` 和证据。新样本、更具体措辞、可估模型默认只记设计、测量或情境变化，只有独立证据支持才能上调。竞争解释记录可区分预期，证据不足显式记未知及核验动作。没有可说明的知识差异或独立价值时，回退、降级或转任务。

**放行**。重用 `READY` 并附最近似文献的比较表、支持层级、可核验的新比较、待查命题和停止条件。对关键主张只有摘要的项目，可在有明确查证目标及预算时进入 G4，同时显示“贡献待证”；无法给出待区分判断或只是测量变化的项，先留作诊断或暂缓。禁止把上一次裁决自动继承给不同版本。`READY` 的完成标志改为 `formal_search_eligible`。单轮问题准备和复审可合并工作包，无固定加轮。默认 **0** 次额外派发，有明确可能改变去留的缺口才使用条件追加额度。

### P0-03 · S07 凭证与 G5 强制冻结检查

**对象**。候选控制模块正式交接、05 新版 `stage05.py`（`plan/validate/execute` 和冻结出口）、04 manifest 兼容适配。维持既有 G4/G5 `quality_review` 和 05 的硬条件。S07 可承担既有研究复核的同一轮学术工作，分别需要的内容签核结构可由同一结果派生，禁止以凭证替掉任何标准。

**分离审查报告和 attempt 凭证**。`S07_review` 由独立审查流程保存，含 `review_id, run_id, stage=S07, review_mode=formal, question_ref, g4_attempt, g4_manifest_sha256, g4_bundle_sha256, decision, reviewed_at, reviewer, invocation_ref, evidence_ids, objections, verdict_basis`；稳定报告不能含它自己的哈希。控制器以 run 锁绑定 G5 计划目标，生成只追加的 `s07_receipt`，字段为 `receipt_id, schema_version, workflow_profile, run_id, stage=05, g5_attempt, g5_plan_identity, g4_attempt, g4_manifest_sha256, g4_bundle_sha256, question_id, question_revision, question_revision_sha256, review_report_sha256, decision, reviewed_at, issued_at, issuer_ref`。`g5_plan_identity` 锁科学输入和预分配 attempt 标识，不含本凭证及其哈希，避免循环；现有完整计划另锁凭证文件哈希。回执只由受控入口根据已归档的 formal PASS 产生，手填状态和自报回执不能取得放行资格。复核文件本身及发布事件在锁定清单中有明确生产者、归属和输入依据。

**核验次序**。初始化锁定 v3.1 profile；G5 所有调用入口使用同一门禁。按 A02 比较拟冻结的结构化载荷与审查覆盖。G5 要求当前 G4 `passed`、当前 run 与 attempt、manifest/bundle、拟冻结科学载荷和正式审查覆盖全匹配；验正式报告或有效复用／定向复核链、当前 G5 attempt/计划、审查时间和撤销状态。在运行锁下临冻结重验。旧回执遇绑定变化一律拒用，依 A02 决定重新绑定、定向复核或完整审查。探索只输出 `frozen=false`。过期依据配置声明的有效期和明确的失效事件，无默认任意天数。

**续跑**。同 attempt 中断且输入不变时复用回执；新 attempt 均签发当前回执并保留前序关系。变更处理以 A02 为准；原来“G4 或问题版本变化一概完整重审”的做法由 A02 四级规则替换。旧 profile 继续原 G5 契约。门禁新增固定派发 **0**；真实 S07 沿用原本计划的一次独立审查。变更按边际收益和影响范围复核，缺材料、超预算或无实质收益时暂缓或停题，保留阻塞和恢复点。

### P1-01 · 让全文解释进入问题形成

**对象**。04 的 `relations/dialogue`、05 的 `literature_dialogue/route_assessments/significance_reviews` 和 00 的解释与审查输入，新增字段由独立候选版本映射回旧契约。初查解释卡增加 `target_phenomenon, theoretical_proposition, mechanism_steps, enabling_conditions, alternatives_examined, alternative_result, applicable_scope, remaining_puzzle, discriminating_predictions`。每字段有事实依据或 `unknown_reason`。作者排除了什么要区分未检验、检验但未排除、按何设计排除；结果、作者解释、系统推断分别注明证据等级。来自摘要的说法仍是作者报告。整理近似研究时逐项比命题、单位、时间、分母、结局、设计和边界；地理、样本、用词差异只有改变理论预期或实质问题时才计入。相同命题在可比范围内有证据才记分歧，样本或口径不同先核可比性。

**交付与验收**。在已有 25 篇对话矩阵的结构上登记最接近若干篇的实质对话，说明沿用、反驳或调整什么、哪种结果会改变判断，绑定实际已读核心全文页段。未找到反例或分歧时写搜索边界和未知。05 的四路、意义、答案用途、目标量和冻结检查继续用现行实现。先用结构化提取合并一次阅读和审查输入；固定新增派发 **0**，真正缺决定性来源才列追加请求及预期收益。

### P1-02 · 原文定位和推断链

**对象**。00 新版证据／审查校验、10 共享契约的新可选表述、04/05 适配。沿用 `paper_id / source_id / document_id / evidence_id` 和 `direct / synthesis / inference`。直接证据保存原文身份与文件哈希，定位同时保留 PDF 文件页序与显示页（适用时）、章节、表／图／段或 HTML 锚点、短摘及提取方式。页文本须能追到原文件、原页序和派生哈希，网页须有发布页、采集时间和快照。审查引用的定位由证据对象派生，提交不同文本时需匹配规范化页段或标记待复核。笔记可作检索线索，缺原来源不能作为已核直接证据。推断和综合必须链到一个或多个已核原始依据、写清推断步骤，图上无缺失、无循环。

**验收**。程序核身份、哈希、页段、短摘和强度，扫描件、无层级定位或布局不可靠进入 `needs_manual_verification`，人工复核需保存原件位置、复核人、日期、理由并绑定哈希。关键支持待核不得进入正式审查通过，辅助线索可保留。现有 G4 直接证据校验能用就调用，避免另写两套门槛。默认新增模型派发 **0**，额外人工工作集中在程序无法验证的关键来源。

### P1-03 · 模型回执、用量与去重

**对象**。00 新版 `topic_run.py / topic_review.py` 的事件口与模型提供方接入，TRACE 运行记录。追加三类记录 `dispatch`（`dispatch_id, run_id, stage, intended_model, prompt_version, input_sha256, provider, budget_reservation, timestamp`）、`attempt_usage`（`provider_request_id, dispatch_id, attempt_no, retry_of, outcome, actual_model, model_version, input_tokens, output_tokens, actual_fee, currency, usage_source, receipt_ref/hash, timestamp`）、`stage_decision`（`decision_id, dispatch_id, stage, review_hash`）。手工记录单列 `reported_by`、口径、理由。模型、Token、费用凭提供方原始回执填真实值；缺失统一 `null + unknown_reason`，人工值标 `manual`，不视作提供方实测。检索也区分批次、实际请求、人工报告和估计。两次派发三份裁决不得报成三次模型调用。

**预算**。沿用现有调用计数和阶段预算的意图，前置额度预留并在失败、重试、未知状态下对账；未知使用量不自动归零或释放确认中的预留。支持显式独立的探索与正式预算。按候选／证据／审查标准和输入哈希生成去重键；相同任务优先复用有权限且仍有效的证据、阅读或回执。模型失败的真实请求保留，重试加新 attempt。仅在相同口径和原始证据可比时评估成本变化。新增模型派发 **0**。

### P2-01 · 真实正向验收与继续条件

**对象和交付**。候选注册表、真实运行检查点和独立验收报告，经 00→04→S07→05→06→07 验真实输入、正式冻结、06 按锁定方案输出可复现结果，07 读取有效上游并产出可核写作交接包。07 不以写出整稿或投稿作为本改造的通过条件；仍须具备现行 G2/G3 与 G6 依赖。实跑课题须得到独立学术允许，教育双窗口题可作校准和负向回归，只有证据充分时才用作正向试题。所有六刊、约 100 有效摘要、25 核心全文、正式阅读及质量条件按现行规则验收。访问受限、资料不足、无合格主问题等分别记录阻塞及恢复点。[真实和对照测试](v3.1_测试设计.md)

## 五、成本预算和开工判定

- **工作量估计**，按单人等效工程人日，P0-01 约 1–2，P0-02 约 2–3，P0-03 约 2–4；P1-01 约 1–2，P1-02 约 1–3，P1-03 约 1–2；技术回归及真实运行准备 P2-01 约 2–4，总计约 **10–20 人日**。真实文献获取、有效摘要阅读、25 篇精读和访问等待另计，未估总历时。不能根据这些估计推出 API 费用。
- **常规模型开销**。既有独立审查角色继续用，常规探索新增派发目标为 **0**，全程真实正向路径包含原计划正式 S07 的 **1 次**。一级试跑预算提案为常规正式审查最多一次派发、一次受控补查后复审作为条件项；超出要记录决定性证据、预算和边际效益，再进下一轮。这个提案是试跑约束，质量不足可停。底层请求数、Token、费用以可核回执为准。
- **如何证明改好**。教育案例在同材料盲审、同角色、同预算环境复跑；候选池不计诊断及变体、每次改问保留语义差异、无法判别的机制标未知、G5 拦所有缺凭证或错快照的路径。对原 v3.0 实测取齐同口径回执前，成本只列可比部分，未知单列。另一真实课题完整跑通才记正向业务通过。
- **准备结论**。建议用户与独立审查确认后单独授权第一批 P0-01、P0-02。本轮状态为设计准备待确认。其余批次、真实试跑及启用各自等待后续授权和验收。[开发准备验收](v3.1-A_开发准备验收报告.md)

## 六、A01 · S01—S03 学术质量规格

来源为 v3.1-A 委托第三节。控制模块候选沿用当前 `opportunity / question / deepening` 接口。S03 是进入初查前及实质修题后复用的检查点，沿用同一提交及复核机制。后续由 P0-01、P0-02 实现。[阶段映射与验收证据](v3.1_任务追踪矩阵.md) · [R01、R05 与 A01 用例](v3.1_测试设计.md)

| 阶段 | 拟交付的数据与检查 | 通过及退回条件 |
|---|---|---|
| S01 发现机会 | 为每个断言存 `claim_id, kind, text, source_refs, observed_period, applicable_scope, evidence_status`。`observed_fact` 要有对应材料及范围；`phenomenon_to_explain` 要引用已观察事实并给出待解释维度，未观察到的疑问留作线索；`policy_goal` 保存发文主体、目标期和政策文本；`research_conjecture` 保存假定机制、待查证点和依据。 | 机会卡记录各类的角色和证据强度。政策材料支持“目标被提出”，不支持当地短缺、历史期状况或因果，单一政策可作待查动机。证据薄弱留 `unverified_lead` 或 `unknown`。政策意义单列，学术创新独立判定。 |
| S02 形成候选 | 分开 `theme`、`phenomenon_ref`、问题文本、`knowledge_goal` 和类型。区分描述、解释、机制、诊断或可行性，标探索或理论取向时仍给可回答、可反驳或可比较的知识目标。沿 P0-01 的角色记录主问题、子问题、诊断、可行性、稳健性及父版本。 | 主候选需明确对象、未知、可能答案与知识价值。描述、探索和理论类可成为主问题；单一主题、现象复述、仅换测量且知识问题相同均不能充作独立候选。记录系谱及取舍。 |
| S03 题句和口径 | 保存 `research_type, question_ref, scope_checks[]`，每个检查项保留题句对应片段、实际口径、证据引用、状态与理由。状态为 `aligned / mismatch / unknown / not_applicable`，后两项必须有理由；未知需给核验动作，必需项不得以 N/A 跳过。 | 校验字段及引用；同口径或不一致的学术判断由现有阶段审查给有据结论。人群、时期或证据强度不一致就缩限、修题或暂缓。决定结论边界的未知挡住对应主张，允许以明确查证目标继续探索。无统计式的研究仍可得到完整的适用性判断。 |

**S03 方法适配。** 类型和检查项按候选合同版本记录。复用 G5 的成果及现行 05 测量审查，S03 只确认提问含义和可能可比性，G5 仍负责正式条件。

- **定量**核题句、总体、单位、时间、同口径样本与分母、比较、主要结果及其操作化、数据覆盖与推断等级。固定队列明确入组键、观察窗与分母规则；“曾确认就读”与各波“已访／缺访”分开保存，较早已确认者即使后波失访也留在累计确认记录。未知和未确认按不同证据状态记，不补为未入学。
- **定性**核研究对象、田野或案例范围、访谈对象和选择逻辑、时间、现象和概念、过程及机制、材料与结论边界；分母和模型标 N/A 并说明理由。
- **历史**核时期、地区、档案形成与覆盖、概念跨期等值及史料缺口；**比较**核案例选择、共同口径及制度和时间可比性；**混合**按各子设计检查，并说明证据如何整合、冲突如何处理。理论型问题核命题、假设、竞争论证与适用边界。
- **现行范围**仍按根规范限定定量社会学正式业务；其他类型供本轮选题检查契约设计及未来获授权适配。受现行范围限制的候选明确标注，不能借适配取得生产准入。

A01 默认固定新增模型派发 **0**。复用断言引用、结构检查和现有评审反馈，只有影响去留的新事实才考虑追加有预算的查证。

## 七、A02 · S07 审查边界与变更失效

来源为 v3.1-A 委托第四节。由 P0-02 提供问题版本与语义差异，P1-02 基础接口提供可靠证据身份，P0-03 实现判定、记录与 G5 硬检查。审查角色维持独立，默认候选为 6.2 Sol，模型通过意见必须由受控的审查流程记录与验证。

| 覆盖块 | 审批在当时锁定的内容 |
|---|---|
| 问题 | 完整题句、对象、单位、时期、地域／范围和核心现象。 |
| 实际含义 | 核心概念、题意、比较对象、选样／选案逻辑、分母和主要结局／现象定义、题句和证据覆盖一致性。 |
| 理论与文献 | 理论命题、机制、最相近研究及解释范围、竞争解释、仍未解释处、预期贡献和可核依据。 |
| 设计 | 定量给估计目标、测量、主要统计设计、适用的识别策略和推断限制；定性给案例选择、来源、分析逻辑及机制证据；历史、比较等给类型适配内容，必需项未知则暂缓。 |
| 证据快照 | G4 attempt、manifest 与 bundle 哈希、合格核心全文清单和文件版本、问题引用版本、审查意见与结论、审查人和时间。 |

正式报告在原 P0-03 字段上扩充 `review_schema_version, scope_snapshot_ref/sha256, method_profile, covered_items[]`，每项含 `item_id, field_refs, evidence_refs, status, finding, reason`。适用项必须覆盖，N/A 包含理由；未解决的实质异议、关键待核依据、缺复核链和失效权限都不能形成正式 PASS。G5 对受审科学载荷和实际冻结输入逐项比对。沿用 05 已有现场学术和工程复核。

| 级别 | 判定依据 | 处理与凭证 |
|---|---|---|
| A | 展示排版、空白和经核对无歧义的文字修正，结构化受审内容和实质证据完全一致。 | 保存原文及前后原始哈希、变更理由；同 attempt 仍须匹配当前计划。原正式报告可复用，若绑定变化由控制器重新签发回执，完整 S07 不重跑。 |
| B | 常规清理或非实质实施调整未影响样本、分母、含义、目标或主要分析。也可附加明确分离的探索性分析。 | G5 记录自有检查，证明与批准研究一致后才能复用报告；回执按当前输入绑定。若改变选入样本或调整主要分析，升为 C/D。 |
| C | 局部重要证据、非核心概念操作化或非决定性竞争解释改变，核心问题和设计保持一致。 | 旧 PASS 禁止直接放行；独立 S07 只复核受影响项及其依赖。列明继承项、定位、结论和新快照。新合成覆盖完整且通过，受控签发当前回执。无法划清影响范围则 D。 |
| D | 对象、影响结论的时期、分母、比较、主结局、核心测量、估计目标、核心设计或识别策略、核心理论或决定性竞争解释实质变化。 | 追加原审批失效事件，完整独立 S07。原报告与回执留档，继续放行必须有针对当前版本的正式 PASS。 |

**谁判与如何判。** 由控制器和 G5 用受审字段清单、版本化规范序列化、证据清单及引用影响图比较新旧真实输入，取涉及类别中的最高级。执行者可说明原因，无权指定最终类别。展示元数据白名单允许自动 A；题句字面改动除约定的机械格式等价外，至少由有权限的独立复核人签署语义等价意见，否则按 C/D 或待定处理。变化未知一律暂缓冻结。G5 独立签核人确认 B；C/D 由独立 S07 判结论。核心字段即使题句完全相同也触发失效判定。上游快照只换封装版且内容严格可核等价，可留 A 类记录；更换文献版本、证据内容、定位或资格时逐项检查，至少 C，影响核心结论则 D；G4 当前未通过时不签发任何正式回执。

**记录及防绕开。** 变更事件至少包含 `change_id, run_id, previous_attempt, current_attempt, prior_review_ref/hash, old/new_question_ref, old/new_scope_sha256, old/new_g4_ref, old/new_plan_ref, changed_fields, impacted_item_ids, rule_version, class, reason, decided_by/at, decision_evidence, required_action`，定向复核追加 `base_review_ref, reviewed_items, inherited_items, current_snapshot_ref, result`。撤销、过期及失效另以只追加事件绑定报告和受影响链；删文件、改状态或缺父事件均失败，同报告的重签发不能消除撤销或过期。若源报告已撤销或过期，当前正式资格需由合规的新审查恢复；沿用历史仅供查证。把新 attempt 和旧 attempt 的衔接、最早恢复点、可复用依据写入门禁记录。

**边际效益。** A、B 通常由比较和原 G5 完成，不追加 S07 模型调用；C 汇总受影响项择一次定向复核，D 才完整审查。先核 G4 与完整性，失败即停止；不循环重审无新材料的题。时间与费用以后以实际回执记录。[独立用例](v3.1_测试设计.md)
