# v3.1 候选系统架构 · 自主 AI 论文写作

设计修订 `TOP-20261121-01`。运行配置暂名 `paper_autonomous_v31`，仅供设计。当前生产仍由 [v005 注册表](../../v005_第5版/module_registry.json)及[根架构](../../../项目架构.md)确定。现有运行锁定根架构和规范文件哈希，候选架构独立保存。候选实现、联调、真实验收和默认启用各有授权和证据。

## 1. 产品和责任

用户输入一句自然语言。系统保留原文，形成可追溯的意图、固定约束和可自主调整的偏好，随后自行研究、起草、复核和交付。正常路径的中间决定全部由总控调度。研究、文献、理论、反诘、设计、分析、写作是按需分配的职责，允许同一角色合并准备工作。S07 与论文放行审查各自隔离输入上下文、审查权限和裁决记录，与本轮产出的作者分离。审查模型暂定 GPT‑6.2 Sol，替代模型须经运行策略显式登记；不可用且无登记替代时保留可恢复状态。程序验证结构、来源、哈希、角色、预算和门禁。人工参与属于项目开发、启用或外部权限治理，正常业务不等待逐阶段签字。投稿不是自动论文交付的组成部分。

## 2. 单句入口到最终交付

| 阶段 | 输入及处理 | 交付与失败去向 |
|---|---|---|
| 00 / S01–S03 | 自然语言任务、已登记资源。区分主题、事实、现象、政策目标和推测，提出并比较主问题、子问题和附属任务 | `intent`、候选与排除理由、初步口径；无合理问题可自主补线索、分支或结束 |
| 04 + 11 / S04-A、S04-B / G4 | 主题→检索式→同义、理论词扩展→指定六刊检索→取源和去重→有效、相关、实读检查。初查可重用，后续与研究问题相互修正 | 保存原始响应定位、检索覆盖和四类计数、摘要矩阵、独立内容判断和有效 manifest。摘要不足先有界扩词、改式、补刊和换合法摘要渠道，再处理可行方向或记录阻塞 |
| 00 + 04 / S05–S06 | 用已核摘要拆作者观点、作者报告结果、机制条件、未知和系统推论。核最近研究、真实分歧或不可比，对预期与反例做反诘 | Q→解释→竞争解释→反诘→修订/弃题历史，逐变更记录证据、答案如何改变知识和贡献类型。有边际收益才补查，从实际失效的步骤回退 |
| S07 + 05 / S08 / G5 | 独立 S07 审当前问题版本、G4、方法计划和证据界限。程序核独立签发的审查报告、当期凭证及当前冻结计划 | 正式冻结问题、适用的假设或命题、证据和设计。拒绝、撤销、陈旧或探索通过时返回相关步骤，不生成正式冻结 |
| 06 | 合法材料和已冻结方法。定量复用现有适配、清洗、分析和复算。其他类型按候选方法适配及证据要求执行 | 材料授权、采集和选择日志、样本/语料流程、代码/分析记录、结果与局限、G6 放行。替换数据、改变题目或研究类型时更新演化；实质变化回到相应 G4/S07/G5，主结论不得沿用旧批准 |
| 07 / 单稿内部审查 | 冻结的适用资源和证据，自动生成提纲、正文、表图、引用索引和引用审计；独立审查研究、引用、设计、结果、创新、推论、格式与结构 | 可核完整论文、参考文献、摘要矩阵、数据来源/可分享数据与代码或方法所需材料、研究日志、最终独立审查及修改记录。按失败分类自动回到受影响的步骤，旧稿与旧批准留档 |
| 08/09 | 显式选择三稿时可续用 08；09 继续独立受控 | 默认单稿独立复核在 07 完成。无需额外三稿或自动投稿 |

候选方法先判断证据能回答何种问题，再选合法可取材料。支持范围须由 `method_profile` 和已验适配器声明。目标包括定量、定性、混合、理论、文献、比较及历史。对尚无适配能力的类型，系统留下理由并评估符合用户约束、具独立价值的替代方案；不能把模拟访谈、二手摘要或不存在的模型结果包装为实证。定量按需要执行数据获取、清洗、构建变量、描述、估计、稳健性、图表和复算。定性、历史与文献方法要求可访问的材料、纳入逻辑、位置可核的分析过程和适用边界；混合设计还需证据整合规则。适用的结构、语言、方法公共资源按现有快照复用；某方法的独立资源要求不计为六刊 G4 全文目标。

完整稿件按方法选用标题、摘要、关键词、引言、综述、理论框架、问题或假设、方法、结果、讨论、结论和参考文献。合理合并及不适用章节由写作计划解释。数据不能分发时交付合法来源、字典和可复现脚本及受控访问说明。

## 3. 六刊摘要合同

名单由现行正式采集模板核对为《中国社会科学》《社会学研究》《探索与争鸣》《中国青年研究》《经济研究》《管理世界》。冻结别名映射、源资格、查询式、日期、页游标、响应凭据、内容指纹和合并轨迹。优先合法可访问摘要来源，保留期刊及文章身份与联网检索来历；禁止绕过访问控制，不能从本地无联网凭据题录补计。

按计数漏斗分别回报 `retrieved_records`（原命中）、`records_with_source_abstract`（有可回溯真实摘要的记录）、`distinct_valid_abstracts`（去重后的有效摘要）、`distinct_relevant_read_abstracts`（其中实际判相关且有阅读记录的独立文章）。以现行模板中的 100 作为候选默认验收目标，正式成功按第四类计数。达到数量仍需核刊域、证据和论证适配。缺口如实记，跑完有界补查后允许该候选阻塞或转方向重新验收，数量不足不自动豁免。全文获取、PDF、精读和订阅均从候选 G4 义务移除，全文状态缺失不影响摘要计数或单独导致失败。

摘要矩阵用 `paper_id` 关联问题、理论、概念、机制、对象、方法、发现、结论、边界、当前关系及阅读状态。缺项带 `unknown_reason`。摘要快照定位保留规范 URL/来源 ID、取得时间、摘要区块和字符范围或短摘、原始与规范化文本哈希及转换版本。只有取得和实际查阅的正文才可使用页码声明；摘要可直接证明“作者在摘要报告 X”，跨文献综合和系统推论分别连到基础证据；不能补造方法细节、正文页码、效应量或将作者解释升级为已核因果。确实需要超出摘要的支持时，缩限主张、找适用合法证据或改题。可选材料按证据强度单列。

## 4. 总控、恢复和审查契约

- 以 `run_id` 锁定原始任务、候选 profile、注册版本、配置和预算。以 `stage/attempt` 锁定输入和输出哈希、模型与提示版本、证据快照、上游引用和裁决。状态至少有 `planned / ready / running / needs_review / passed / stale / blocked / failed`。数据分析开始前锁定计划；事后实质变更留为探索或重新批准，不从结果挑主模型。
- 控制器从有效检查点调度下一个动作。从被改变的最早依赖开始，只标失效实际下游。各阶段幂等键按阶段、实质输入、策略和预算计算。恢复核当前产物、撤销状态及进行中请求编号，再决定沿用、对账或重试；历史 attempt 只读。数据与代码隔离执行，记录授权与环境，私有个案保留受控引用。
- 先做程序校验再派发实质审查。共享摘要矩阵和证据图，依论文、证据版本和任务键复用阅读与裁决；只有新证据可能改变结果才追加工作。调用限额与检索限额分别设定，提供方调用、Token、费用、人工报告、失败重试分别记；无回执为未知。预算不足可走策略内替代或停止并保留恢复点，不能签假通过。
- 正式 G5 凭证绑定当前 run、G4 attempt、manifest/bundle、问题语义版本、科学设计快照、正式审查报告与当前 G5 attempt/计划。所有冻结入口和锁内提交前都重验。A 纯展示可重绑，B 由内部 G5 核对非实质变更，C 独立定向 S07，D 完整 S07。受影响项不能直接继承；对撤销及过期查权威的最新事件流和链头，缺失、回退或不可核则拒绝。锁前后竞态必须有回归。
- 终稿审查独立于写作，绑定稿件、证据包和结果版本。引用问题回证据/写作，分析问题回 06，设计或核心论证回上游复核。修订后只复用未失效覆盖，最后重新验证当期稿件。完成输出是完整论文及可追溯材料，另列未能取得且影响结论的证据。
