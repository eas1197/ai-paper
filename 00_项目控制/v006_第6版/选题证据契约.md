# 选题证据与问题演化契约 · v1

记录为 UTF-8 JSON，`schema_version` 为 1。每条记录在所属运行内使用稳定 ID。修改通过新增问题、解释或证据版本完成，引用已审查的旧记录时仍指向旧 ID。

| 集合 | 字段和约束 |
|---|---|
| `opportunities` | `opportunity_id`、`observation`、`social_process`、`evidence_ids`。观察标明来源所覆盖的对象，尚待查证的线索以问题表述。 |
| `questions` | `question_id`、`opportunity_id`、`text`、`population`、`scope`、`comparison`、`concepts`、`answer_value`。每条问题可追到机会。 |
| `evidence` | 沿用 `evidence_id`、`source_id`、`document_id`、`paper_id`、`locator`、`sha256`。`kind` 标记 `abstract`、`fulltext` 或 `context`，`path` 指向项目内证据快照，`excerpt` 留足以定位的短摘。页文本 JSON 使用从 1 开始的 `page`，`section` 和可选 `table` 供人工复核。摘要若嵌在全文页内，仍按摘要标记。 |
| `explanations` | `explanation_id`、`question_id`、`evidence_ids`、`author_claim`、`proposed_mechanism`、`observed_result`、`evidence_strength`、`applicable_scope`、`system_inference`。原文未交代的字段填 `null`，在 `unknown_reason` 写明原因。摘要里的主张可记录为 `author_report`。全文回查后按研究设计登记证据强度。 |
| `critiques` | `critique_id`、`explanation_ids`、`kind`（`premise`、`counterexample`、`competing`、`boundary` 或 `evidence`）、`text`、`evidence_ids`。质疑若为系统推论，在 `text` 说明所依据的事实与待检验部分。 |
| `evolution` | `question_id`、`explanation_ids`、`critique_ids`、`next_question_id`、`disposition`、`increment`。`retained` 须说明新增的比较或知识要求，`rejected` 要写退回原因。 |

证据事实、跨文献综合和系统推论沿用 10 模块的 `direct / synthesis / inference`。`evidence_strength` 描述原文提供的实证支持，`system_inference` 独立保存系统新增的推断。程序核对引用、材料哈希和短摘位置。作者是否有能力支持其主张、问题是否真有增量，由实际审查裁定。此契约记录选题阶段材料，G4 读量和 G5 冻结仍用正式报告认定。
