## 开发版入口

从项目根执行以下命令。预算按能够记录的模型调用和定向检索批次计。`prepare` 会给出当前研究任务、已审查候选、可复用文献入口与上轮意见。已有 11 模块现实材料索引时，可加 `--context-index <文件>`。指定主题时在 `init` 加 `--theme <主题>`。

```powershell
python -B .\00_项目控制\v006_第6版\tools\topic_run.py init <run-id> --model-calls 6 --search-calls 2
python -B .\00_项目控制\v006_第6版\tools\topic_run.py prepare <run-id>
python -B .\00_项目控制\v006_第6版\tools\topic_run.py allowance <run-id> --model-calls 1 --search-calls 1
python -B .\00_项目控制\v006_第6版\tools\topic_run.py record <run-id> <bundle.json> <review.json> <usage.json>
python -B .\00_项目控制\v006_第6版\tools\topic_run.py status <run-id>
```

执行者查看 `allowance` 后才派发研究或独立审查，接到返回后用 `record` 记账。运行文件保存于 `outputs/topic_runs/<run-id>`。`usage.json` 用 `model_calls`、`search_calls` 两项记录实际消耗。审查由当前 Codex 会话分别派发，Python 命令负责准备、预算、校验、落盘和恢复；审查失败等待有效输入。模型原始返回与审核时实际所见 bundle 的哈希一起保存。

状态为 `formal` 时使用 `formal-init <run-id>` 将证据索引和选题裁决交给现有 `project.py init`。正式文献可沿用既有 04 `acquire ... --action bridge` 和搜寻凭据，04 验证后才能计入六刊与实读目标。`final-gate <run-id> <bundle.json> <review.json> <G4-attempt目录>` 校验当前 G4，审查输入中附它的 `stage_manifest.json` SHA‑256（`formal_g4_sha256`）。放行结果交由现有 05 执行，G5 自己验收并生成冻结文件。

回退时继续使用已登记的第5版 `project.py` 和历史运行。开发阶段从第6版命令显式启动。发布前核对是否有真实运行达到启用要求，以及根规范和注册表版本变更对旧快照的影响。
