# 第15版 · 定性架构与实验写作方案

两条定性路径使用同一个骨架。正文按“问题的提出、文献综述与分析框架、案例介绍、逐维度分析、结论与讨论”组织。中段由框架决定有几个一级章节。每章以具体分析维度命名，结合实际材料和理论解释。结论整合各维度回应核心问题、与已有理论对话。凤翔泥塑的三个维度只用于说明一一对应关系。

框架先说明既有解释及其不足，交代理论选择理由，再围绕本研究问题推演维度。说明这些维度如何合力回答问题，以及框架与既有解释有何实质区别。理论增量需要文献比较及经验论证。案例章节写明问题相关背景、选择理由、资料来源和研究方法。

使用 06 经验矩阵时，在输入填 `analysis_matrix`（相对于本次实验的路径）和 `framework.core_concept`。07 核对同一核心问题、核心概念和维度顺序，审查请求保存矩阵哈希。结论与讨论须说明哪些发现支持、限制或修正对核心概念的推断。

## 执行与审查接口

总控 `run_mode.py --mode dev --run-id <id> --theme <主题>` 默认锁定 `writing_policy.deliverable=plan`。新建实验时可显式追加 `--full-paper`，并在清单中保存对应配置及指纹。v009 选题入口也支持该参数。历史实验清单缺此字段时按方案模式解释。正式模式沿用现行全文写作入口和审查。

执行 `run_mode.py --mode dev --run-id <id> --writing-plan <写作任务.json>`。任务文件的输入如下。

| 对象 | 内容 |
| --- | --- |
| 研究 | `method`、`core_question`、`answer_strategy`。若存在 S08 记录，题目与方法必须一致。 |
| 章节 | `chapters` 按正文顺序排列。每章有 `id`、`task`、`bridge` 和 `sections`。定量章节自行命名，提供 `title`。每节包含 `title`、`task`、`argument`、`evidence_use`、`source_ids`。 |
| 材料 | `sources` 按证据 ID 存 `kind`（理论 `theory`、文献 `literature`、经验 `empirical`）、`label`、`locator`。引用需写明用途，审查者查实际材料和允许的推断范围。 |
| 定性框架 | `framework` 包含 `prior_explanation`、`gap`、`theory_choice`、`deduction`、`increment`、`integration` 以及有序 `dimensions`。每个维度有 `id`、`title`、`deduction`。正文章节 ID 依次为 `problem`、`framework`、`case`、各维度 ID、`conclusion`。 |
| 定性案例 | `case` 包含 `background`、`selection`、`materials`、`method`。 |

运行产物为 `writing/论文写作方案.md` 和 `writing/writing_plan_review_request.json`。审查请求明确方法、指纹、计划状态、审查要点和全文入口状态。程序核验章节与材料对应，理论推演、文献增量和真实材料适切性仍由学术审查判断。方案不能登记为正式稿件。显式全文配置记录了授权，全文仍需现有定量入口与上游放行。定性全文入口、定性材料采集、编码、分析和逐段写作细则待实现。
