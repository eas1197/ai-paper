# ai-writer 4.0 · 定性写作新候选

## 定位与隔离
此版本对应07写作模块的 `v016_第16版`，研究写作子系统命名 **ai-writer 4.0**。严格保留原定量路径：生产注册表仍选择07/v014；定量继续按原G4—G6、G2/G3资源锁与 `stage07.py` 单稿/三稿逻辑写作、复核和交付，不修改生产文件、既有真运行或早期写作版本。

新增的定性路径读取候选 `07/v015/tools/writing_plan.py` 的完整输入结构，包括问题、七段结构（problem、framework、case、若干理论维度、conclusion）、来源ID与定位、每节论证任务、理论推演与材料用途。全文写作沿该框架继续，而不是换成定量论文的“变量—模型—回归结果”格式。可以使用 `secondary_interviews` 或 `online_qualitative`；定量传入新入口时仅报告原v014入口，不执行替代定量流程。

## 选用的语言库
- **主风格：03/v004。** 15项ST规则及逐篇风格笔记，特别适用于明确研究对象、关系动词、判断边界、概念辨析、引用衔接、长短句自然节奏、关键词稳定性和作者声音。使用机器可读 `assets/style_patterns.json`；同时读取原创例句和风格约定，**不得复制训练语料、范例的经验结论或生成伪引文**。
- **逐段选择：03/v005。** 已有52个功能单元和风格ID，可选择性复用其中适用于定性论文的语言功能，不套用源资源的定量假设、问卷与统计操作化任务。本文在 `assets/qualitative_style.json` 中建立五类定性章节用途的独立映射。维度个数和章序仍由V15真实理论框架决定。
- **论证复核：03/v003。** 将L01/L02/L04/L05/L06/L08/L09/L15/L17/L20/L23/L24/L27等用于概念边界、文献关系、受访者与记者声音、竞争解释、因果强度和判断范围的检查。统计估计和回归术语规则只在定量研究使用。
- **成稿标准：main/07-v014 的文字要求及 `language07.py`。** 优先以研究对象、现实事实与解释推进中文学术表达；普通作者尽可能用括号作者—年份，不用“某某指出”的写法代替学术论证；复核风格之后再做事实、引文、材料及理论增量的独立审查。

以上是版本化能力的复用，而非声称正式G3已通过。03/v004及v005当前正式业务报告 `needs_review`，因此**实验可使用，正式写作不得因读取资源而自动放行**。

## 真实调用流程
在完整仓库根目录使用Python 3.11：

```sh
# 用现有V15定性写作包检查方法路由（定量只返回原v014路径）
python 07_三稿独立写作/v016_第16版/tools/ai_writer4.py route --packet /path/to/写作任务V15输入.json

# 生成带来源与语言规则的逐节起草任务，输出到一个不存在的新目录
python 07_三稿独立写作/v016_第16版/tools/ai_writer4.py prepare --packet /path/to/写作任务V15输入.json --workspace /path/to/new_attempt --mode exploratory

# Chat或本地Codex实际按tasks/*.json起草，在真实原文与引用约束内逐节写作。
# 再接收稿件和源证据台账；不会启动额外的模型或互联网检索。
python 07_三稿独立写作/v016_第16版/tools/ai_writer4.py submit --packet /path/to/写作任务V15输入.json --workspace /path/to/new_attempt --manuscript /path/to/正文.md --claims /path/to/主张证据台账.json

# 离线合同测试
python -m unittest discover -s 07_三稿独立写作/v016_第16版/tests -v
```

写作任务以 `writer_manifest.json` 锁定原始packet及03风格库、映射和main写作规范的哈希。调用不需要API密钥，真实模型写作是Chat或本地Codex明确执行的任务，不能冒充自动模型调用。每节 `tasks/<章节>_<序号>.json` 包含本节论证、支持材料、来源定位、ST规则及其分寸、L3论证核对点。 `writing_plan_v15.md` 由实际调用V15 `render()` 生成。作稿后 `style_review.json` 提供旧V14确定性语言检查结果，`writing_review_request.json` 绑定正文/主张哈希并保留独立审查 `pending`。该检查只覆盖部分机器规则和被登记主张，不证明全文逐项事实无误。

## 正式关卡与失败分流
正式研究前必须有真正独立的选题反诘、研究终审、材料适足性、已锁定的理论与问题、G3正式语言资源发布和G7审查；不能只提交写在JSON里的 `pass` 标志。本版本 `formal` 入口有意拒绝无真实外部独立回执的任务，直到可信验收器完成并与当前证据包绑定。

- 缺研究资料或无法回答核心问题：交给06定性材料/矩阵关卡，标 `academic_stop` 或 `materials_pending`。
- 风格资源G3待审：实验文稿可标明 `needs_review` 使用资源；正式交稿阻塞。
- 文稿来源ID、章节、哈希、预算不匹配：`technical_revisions_needed`，不消耗学术返修次数。
- 同一Chat中的反方审查：记为内部复核，不生成虚构的独立模型会话号。
- 不能访问的期刊全文、未取得的访谈、缺失的事件结局：明确未知，禁止为凑段落或风格补写。

## 测试与兼容
程序不修改07/v014、07/v015、00原总控及生产注册表，不启动网页检索、不引入API计费。新代码为新的版本目录，只有被显式调用的定性任务进入本子流程。新增的 `tests/test_ai_writer4.py` 测试方法分流、文献风格哈希、V15章节检查、论文主张定位和不允许伪造独立审查。测试若未在真实Python环境执行，必须报告为未执行而非通过。

### 统一实验入口已接入（不改变原定量执行）
除上文直接调用V16工具外，现有 `00_项目控制/v007_第7版/tools/run_mode.py` 新增仅显式调用的 `--writer4` 分派：
```sh
python 00_项目控制/v007_第7版/tools/run_mode.py --mode dev --run-id <已存在且合规的run_id> --writer4 route --packet <V15写作包.json>
python 00_项目控制/v007_第7版/tools/run_mode.py --mode dev --run-id <run_id> --writer4 prepare --packet <V15写作包.json> --workspace <新的试验目录> --mode exploratory
python 00_项目控制/v007_第7版/tools/run_mode.py --mode dev --run-id <run_id> --writer4 submit --packet <V15写作包.json> --workspace <同目录> --manuscript <真实正文.md> --claims <主张表.json>
```
原`--writing-plan`仍只调用V15，生产`--mode formal`不接受writer4参数；`--writer4 route`对于定量只报告原main/V14写作路径，绝不切换到新定性执行器。该入口要求运行实际存在于`00/v007/runs_dev`且通过原实验运行锁；仅上传到`handoff_runs`的演练文件不是可冒充的本地正式run。已有Chat稿件可用V16独立测试脚本核对，但不得把它伪装成原总控的正式run输出。

### G15 状态语义（任务准备不等于正文完成）
- `route` 只识别方法；`prepare` 成功返回 `awaiting_draft`，产生 `tasks/*.json`、`writer_manifest.json` 与 `writing_plan_v15.md`，不产生正文或主张台账，不派发模型。即便 v012 命令层 `runtime_status=completed`，其 `scope=command` 仅表示命令成功，不表示研究或正文完成。
- 真实正文由执行者另行起草并提供正文及台账；`submit` 仅核查指定输入、产生诊断与待审请求，`exploratory_draft_awaiting_review` 不是 G7 通过，`technical_revisions_needed` 不是正式稿件。正式资源及独立审查门禁保持不变。

### G20 技术核验与学术审查边界
- 确定性技术检查：冻结输入及资源哈希、任务文件、段落位置和章节数量、登记主张的来源 ID 与定位、覆盖清单、声明的证据缺口、字数限制及机器语言诊断。成功只说明上述合同满足；不证明事实、因果、引用真实性或理论贡献。
- 实质性学术审查：逐项检验材料是否真的支持主张、遗漏主张及反证、文献近邻及增量、概念与因果范围、解释及章节论证推进、语言意义等。必须按 P0-D 提交与当前稿件/台账绑定的真实独立执行凭证。V16 的独立审查字段固定 pending，formal_pass=false；v012 候选审查包仅供派发，review_gate_guard 当前始终阻断原关卡状态修改，不得从候选或 JSON pass 自行推进。
