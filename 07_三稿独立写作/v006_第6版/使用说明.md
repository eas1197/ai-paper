# 第七步使用说明

在项目根目录运行。先按00初始化同一研究的运行标识，并完成04—06。仅用已验收的02/03资源，不在每篇论文重跑两步。

```powershell
python .\07_三稿独立写作\v006_第6版\tools\stage07.py status --run-id my_study
python .\07_三稿独立写作\v006_第6版\tools\stage07.py prepare --run-id my_study
python .\07_三稿独立写作\v006_第6版\tools\stage07.py run --run-id my_study --input <项目内draft_input.json>
python .\07_三稿独立写作\v006_第6版\tools\stage07.py export --attempt <实际attempt目录>
```

`status`检查论文起草前的关卡。02/03发布的可用快照须在文件哈希清单中附通过的业务报告。成功的`prepare`在运行内生成`frozen/<pack_id>/frozen_manifest.json`和`writing_task.json`。作者或离线写作工具从该入口读取锁定资料，完成计划、写作和自查。从第5版继承的 [写作计划](templates/写作计划.md) 和 [正文模板](templates/manuscript.md) 供理解字段和编排使用。

按 [draft_input.json](templates/draft_input.json) 填写。各稿的 `pack_id` 必须来自本次 `prepare`，`manuscript` 与 `review` 相对于输入JSON定位，只接受项目内文件。默认使用预定二级标题；如果使用合并章节或其他标题，`structure`按正文顺序为每个 `heading` 声明承担的 `functions`（I、L、T、D、R、C，依序各一次），合并必填 `reason`。篇幅采用 `standard`、`short`、`long` 或 `custom`，定制篇幅须附六项正整数字数及理由。实测字数记入每稿的 `writing_plan.json`，偏离由A02核查。

- `references` 中为每条参考文献填写冻结包中的 `paper_id` 或资料 `document_id`，同时填写正文作者—年份标记和参考文献完整条目。参考文献每条放在独立行。
- `claims` 按事实句或表格位置登记唯一 `claim_id`、所属二级标题 `section` 和可从稿件原样定位的 `text`。标记论断类型、对应证据和引用。实证论断绑定06的 `result_id`，并注明所用字段和显示数字，例如系数、区间、标准误、样本量。程序检验原尺度或百分比显示及其四舍五入容差。描述性数字、外部来源中的数字或计算转换在对应证据和A07复核说明中定位。
- `checks` 对照 [17项架构自检](templates/architecture_self_check.csv) 填写逐项状态和依据，包括简述关键表图位置、摘要与结论的一致性、字数偏离和实际支持的因果表述。
- 初次 `run` 后可在各稿目录读取 `quality_review_request.json`。确认内容和所有技术问题后另存复核记录，填写关联的 `content_sha256`、`decision: accepted`、真实复核人、日期和实质评语。在 `draft_input.json` 指向该文件，重新 `run`。修改稿件或台账会改变待复核哈希。三稿模式为每稿分别提供复核。

`export`复验当前通过记录及所有输入输出哈希，返回单稿交付清单或08评审所需材料清单，并给出冻结包和第6步复现材料入口。退出码 0 为就绪或通过，3 为待补证或未通过，2 为命令错误。工作流始终在本地，投稿关闭。
