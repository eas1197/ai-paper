# 第六步数据契约 · schema 2

## 输入

workflow_input.json的06对象包含phase=prepare/analyze/approve；run_id由命令指定，沿用04/05同一研究。路径相对于输入文件；protocol内部路径相对于协议文件，规范化后按绝对路径计算SHA256。

| 对象 | 核心约束 |
|---|---|
| upstream | 当前同run、G5 passed的stage_manifest.json；递归核对输入/产物及G5实质复核 |
| protocol | datasets、variables、models、sample_filters、joins、seed、survey_design、missing/diagnostics/robustness/multiple_testing/precision方案；结构例见templates/protocol_fields.json |
| protocol_review | accepted、reviewer、reviewed_at、assessment、content_sha256=规范化协议哈希 |
| preflight | analyze必须引用当前06 prepare manifest且analysis_plan.frozen=true |
| source | approve必须引用当前同run analyze manifest |
| quality_review | 绑定实际bundle内容哈希的研究判断；不得由程序自动接受 |
| config.provider_files | 自定义数据/估计提供方的实现文件；必须在计划中锁定SHA256 |

协议哈希必须事前进入05冻结analysis_design.execution06_sha256。主分析后变更冻结设计只可明确设analysis_mode=exploratory、各model.analysis_role=exploratory。主分析启动记录在run/analysis_history.jsonl及attempt/analysis_started.json。代码不更改旧假设、旧输出或旧包。

数据来源身份记录必须包含原始文件哈希、官方发布/版本证据文档哈希、定位及能在文档中找到的短摘、授权依据、具名审查及时间。文件名本身不是身份核验；程序核查链条与哈希，原始身份的实质判断仍由研究复核承担。

变量继承05的question_text、question_id、questionnaire_locator、value_labels、special_missing、population、measurement_time、rationale、evidence_ids。06只核对原始列名、实际标签/编码、波次并执行明确变换，不生成问卷原题。DTA保留标签集映射、Stata特殊缺失；SAV区分标签、用户缺失范围与系统缺失；CSV须sidecar绑定哈希。

## DatasetAdapter

discover(root)返回路径/格式/大小及unknown/historical_derived候选；read_metadata(path)返回format、n_rows、columns及reader；columns每列含label、value_labels、special_missing。read_subset(path, columns)只返回本地DataFrame给执行器，不写入manifest或模型请求。harmonize(frame, spec)只接受已核验显式映射，默认流程不猜测或自动跨年堆叠。

joins只允许left/inner、one_to_one/many_to_one/one_to_many；禁止空键、多对多及非键列覆盖。keys将原始主键映射为公用别名，不能与variable_id冲突。输出匹配计数，不输出键值。不同独立调查不直接合并为同一面板。

变量变换支持identity、recode、log、log1p、square；再编码须覆盖全部非缺失取值，对数定义域错误不静默删样本。sample_filters仅eq/ne/ge/gt/le/lt/in，须reason；缺失不通过ne筛选。完整案例按共同样本或事前指定逐模型样本；不按结果选择。

## EstimationEngine

engine_id固定标识；capabilities()返回methods、covariance、complex_survey、missing_policy；fit(frame, spec)返回：

- engine、environment、n_obs、covariance、ci_level。
- parameters：term、estimate、std_error、p_value、ci_low、ci_high、scale。不得返回个案预测或残差。
- diagnostics：converged、errors、warnings及方法所需诊断。模型指定diagnostics_required，缺任一项不能G6通过。

内置8类模型及聚类/稳健误差，具体见capabilities。复杂抽样设计型推断、插补和其他估计器使用可信替代实现；不支持时失败，不降级为普通回归。方法原理、实证范例及人工复核不由拟合成功取代。

## 输出

analysis_plan.json在prepare通过时冻结协议、上游与时间；ready不是passed。bundle.json记录统一内容，哈希不包含结果审查本身；approve保持同一bundle不变。

results.csv每行一个实际参数，包含result_id/model_id/hypothesis_id/sample_version、结局/term、参数尺度、估计及区间/p、N/聚类、引擎/版本/代码哈希/实际时间、analysis_role。探索、主分析及稳健性并存；只从实际引擎输出建结果。

sample_flow.csv、cleaning_log.json、descriptive.csv、model_outputs.json、diagnostics.json、reproduction.json保留全部样本变动、匹配与失败模型。knowledge.sqlite采用10当前DDL，追加stage06_snapshot；datasets、variables、variable_evidence、methods、method_references、models、model_variables、results具外键。

SQLite是当前attempt的索引，JSON/CSV为交换和证据台账。未通过研究复核的结果标executed/unverified，不写作已验证科研事实。prepare的空结果只表示尚未运行。

stage_manifest.json锁定input_files、output_files、upstream_manifests、config、规范、代码、环境和种子。新06只使07—09已执行状态stale，不使06自身失效。validate/status不修改历史；export只接受当前passed且哈希一致的approve。

导出文件集包含汇总表、诊断、分析计划及代码索引；不含个案数据、账号、方法原文和问卷。没有默认模型调用或网络发送。
