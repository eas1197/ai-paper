# 第六步通用模块使用说明

在项目根目录运行Python 3.10+。当前本机已具备pandas/numpy/scipy/statsmodels/pdfplumber；SAV另需pyreadstat。requirements.txt给兼容范围，运行时另锁定实际精确版本。默认无网络、无模型和外部消息。

## 1. 长期方法资源

2026-11-15已建设真实资源v001，入口为方法库/resources/library_v001_20261115/方法手册.md；22类方法每类原理/实证各一，共44条配对与31篇去重全文。资源索引.json及00配置analysis.method_library_resource登记冻结快照和哈希。

复用时将execution_protocol.json的method_library显式填写为该资源snapshot目录的绝对路径，再事前计算协议哈希并冻结。配置登记用于发现资源，不会自动改写现有研究协议或使G6通过。当前快照已生成，不要再次对同目录运行library-build；新增/纠错建立新资源版本。阅读范围与AI自查边界见资源README和验收说明。

方法库/method_catalog.csv有22类目录，不是已读文献。按templates/method_reference_fields.json填写真实记录，将数组放入method_library_input.json的references。每法须原理文献及实证范例各一，实证范例须有表格结构及页码短摘，均须合法本地保留并实际读全文。

    python .\06_数据方法与分析\v002_第2版\tools\stage06.py library-build --input <方法标注.json> --output <项目内新资源目录>

首次输出quality_review_request.json。实质复核后另存review，填写原content_sha256、decision=accepted、reviewer、reviewed_at、assessment，再以--review <复核.json>输出到新资源目录。PDF按哈希归档。全库不足22类仍needs_review；已覆盖方法具备绑定复核且两篇合格范例时，可供该方法的具体研究使用，不宣称全库完成。未覆盖方法仍阻断。

## 2. 只读发现与元数据

    python .\06_数据方法与分析\v002_第2版\tools\stage06.py discover --root E:\文章\教育 --output <项目内新清单.json>
    python .\06_数据方法与分析\v002_第2版\tools\stage06.py metadata --data <实际数据.dta> --output <项目内新元数据.json>
    python .\06_数据方法与分析\v002_第2版\tools\stage06.py capabilities

发现不读个案，不凭文件名确定原始身份；元数据不含个案值。CSV只读表头，需要绑定CSV哈希的metadata_sidecar提供标签；SAV依赖缺失会报错。DTA优先pyreadstat，否则使用已测试的pandas映射读取器；不兼容版本报错。

## 3. 在主分析前完善05冻结设计

复制execution_protocol.json，按protocol_fields.json填写实际数据、变量映射、样本筛选、全部主模型/稳健性/探索模型、方法库、抽样/缺失/诊断/精度/多重检验方案。路径以协议文件目录为基准，先转为绝对路径后计算哈希；冻结后移动路径也会改变协议。

    python .\06_数据方法与分析\v002_第2版\tools\stage06.py protocol-hash --protocol <执行协议.json>

把返回值写入05标注analysis_design.execution06_sha256，并在主分析前完成05原有G5实质复核冻结。05现有程序保留这个扩展字段，无须改旧版。旧设计缺此哈希不能直接跑主分析；先补充可执行计划并重新冻结，不能事后倒填确认性假设。

协议review使用相同content_sha256，由具名研究复核说明数据身份、变量/因果位置、方法适配和执行计划。这是研究证据关卡，不是每次运行向用户另行索取权限。

## 4. prepare：核对元数据

复制workflow_input.json到自己的项目目录，填写06.upstream（同run当前05 stage_manifest.json）、protocol和protocol_review。phase=prepare。

    python .\06_数据方法与分析\v002_第2版\tools\stage06.py run --input <06输入.json> --run-id <研究编号>

缺材料输出needs_review；检查通过输出ready和frozen=true的analysis_plan.json。ready并非研究验收。空模板可以运行以列缺口，不读个案、不制造结果。不填protocol也可生成缺口计划。

计划与执行可分开：plan --input ... --run-id ... --output <项目内新计划.json>，再execute --plan <新计划.json>。锁定输入或环境变化须重新plan。

## 5. analyze：全部模型与独立复算

新输入设phase=analyze，保留upstream/protocol/protocol_review，添加preflight=<刚才06 prepare的stage_manifest.json>，再次run。preflight须为同run当前attempt；程序先校验全部条件，再读取个案列。

每次新建attempt。实际结果、诊断、样本流、缺失和失败模型、结果台账与SQLite保留在run/stage_06/attempt_NNN。复现检查独立重读原始数据、清理和估计；rtol=1e-8、atol=1e-10，比较全部数值、样本和失败集合。

参数尺度：logit为log_odds，计数为log_mean，零过程为log_odds_structural_zero，负二项alpha为dispersion，有序阈值单列。不直接当作OR/IRR或概率差。边际效应、比例优势/IIA检验、设计型误差、因果识别等须用合适提供方和预定诊断；缺诊断不能放行。

analysis_history.jsonl在主分析前登记协议和05设计哈希；同run开始分析后变更协议/假设不能再按确认性方案运行。探索协议须analysis_mode=exploratory、全部模型analysis_role=exploratory，仍需证据与复核，不覆盖旧结论。

## 6. approve、validate及交07

审查实际结果quality_review_request.json，另存复核；检查全部预定模型、失败/不显著结果、诊断、稳健性与因果边界。有问题须修正设计/代码并保留偏离，不能强制放行。

新输入只需06.phase=approve、source=<analyze的stage_manifest.json>、quality_review=<结果复核.json>，同run执行。approve复制同一汇总结果，不重新估计，内容哈希不变。通过后：

若仅复核文件未通过，另存修正后的复核，再引用同一analyze来源建立新approve；程序允许该恢复路径，不要求重跑模型。若数据、代码、上游或实际结果改变，则先回到prepare，不可沿用旧审查。

    python .\06_数据方法与分析\v002_第2版\tools\stage06.py validate --attempt <当前approve目录>
    python .\06_数据方法与分析\v002_第2版\tools\stage06.py export --attempt <当前approve目录>
    python .\06_数据方法与分析\v002_第2版\tools\stage06.py status --run-id <研究编号>

导出限本run内exports，只含汇总表、诊断、分析计划和代码来源索引，不含原始数据、方法全文或问卷。第7步仍须检查02/03及04其他前置条件。不会自动写论文、投稿或发送消息。

## 扩展与恢复

Python接口execute(plan, {"dataset_adapter": ..., "engine": ...})允许替换。契约见DatasetAdapter及EstimationEngine。自定义代码路径放入config.provider_files后才可执行；程序锁定代码哈希。提供方须实现其宣称支持的方法、设计、诊断及统一结果输出，不能靠声明capabilities绕过科研复核。

内置仅8类模型和完整案例。其余方法、复杂抽样推断、插补会阻断，须提供已验证引擎。普通聚类稳健误差不代替复杂抽样。不自动选模型、删变量或按显著性改样本。

失败保存failure.json或模型失败日志，修正后新建attempt。不覆盖冻结包，不自动抢占.research.lock；确认记录PID退出后才能人工清理遗留锁。退出码0=成功或ready/passed，2=输入/执行错误，3=needs_review/failed/stale。validate/status只读。
