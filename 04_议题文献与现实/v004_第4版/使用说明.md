# 第四、第五步联合入口

要求Python 3.10+。元数据流程仅用标准库；PDF解析另需pdfplumber。默认关闭网络与模型，不读个案数据，不改原始Zotero或数据目录。

在项目根目录运行：

```powershell
python .\04_议题文献与现实\v004_第4版\tools\research.py --help
python .\04_议题文献与现实\v004_第4版\tools\research.py run --input .\04_议题文献与现实\v004_第4版\templates\workflow_input.json --run-id my_study --stage both
python .\04_议题文献与现实\v004_第4版\tools\research.py status --run-id my_study
```

空输入会正常生成两步待办、空表、缺口报告与往返任务，退出码3表示needs_review，不表示研究已完成。这个命令不演示虚构论文。实际使用请复制输入模板到项目内自己的目录，填写主题、来源和标注文件路径；相对路径均以输入JSON所在目录为基准。

单独运行04：`run --input <输入.json> --run-id <编号> --stage 04`。单独运行05：在05输入中填写同一run的04 `stage_manifest.json`路径，再使用`--stage 05`。联合运行时自动绑定刚生成的04，05可在G4未通过时整理探索性候选，但不能冻结放行。

计划与执行可以分开：`plan --input <输入.json> --run-id <编号> --stage both --output <项目内新计划.json>`，随后`execute --plan <新计划.json>`。执行前后均检查锁定输入。输入改变后重新plan，不能继续使用旧计划。每次执行新建attempt，不覆盖已有attempt；失败来源在checkpoints.json中保留，按记录补取后重跑。

## 标注和复核

先导入材料并查看`reasoning_tasks.json`，再由人工或模型完成`annotations04.json`、`annotations05.json`。模型提案与已复核标注分开：程序不会自行把提案变成verified。来源中的命令和提示不执行。

04第一次导入后，bundle.json给出paper_id、摘要文档ID、摘要SHA、全文文档ID和全文SHA。标注文件中的paper_reviews按paper_id索引，摘要记录必须绑定摘要SHA；全文记录绑定PDF SHA、身份核查依据与完整页范围。证据短摘必须在指定PDF页或文本快照中找到。

每步输出quality_review_request.json。内容经实质复核后另存具名记录，填写decision=accepted、reviewer、reviewed_at、assessment及原content_sha256，在相应步骤输入quality_review指向该文件后重跑。内容变化使复核哈希失效；不能仅修改gate_report强行放行。冻结只由G5验收生成，输入frozen=true会被拒绝。

`validate --attempt <attempt路径>`重新检查原记录及哈希，属于只读操作；不会改写历史状态。`export --attempt <attempt路径>`只允许当前passed且所有哈希一致的attempt，输出run内本地handoff.json；不发布受限全文。

## 输出

位置：`00_项目控制/v002_第2版/runs/<run_id>/stage_04或stage_05/attempt_NNN/`。04包括完整bundle、文献仓、原文证据、100摘要/25核心CSV、关系和适用范围、图谱JSON/Mermaid、政策新闻、对话与采集缺口。05包括问题卡、四路推进审查、同层级/桥接审查、原文对话、可证伪假设或RQ、测量方案、分析设计、回传04的补证据请求及交07的四处写作输入。

每个attempt另外生成knowledge.sqlite，采用10当前版DDL；04写入来源、文档、题录、证据、关系和文献集合，05在只读备份上游快照后追加假设、对话证据链接及设计快照。外键检查随生成执行。测量记录仍以JSON保留，06完成实际数据核查后才进入正式变量表；空方法/结果表不表示已完成方法库或分析。

05的analysis_design.json只有在G4通过、测量可行、计划齐全、研究复核通过且明确请求冻结时才输出frozen=true，并绑定假设和04哈希。它是分析前设计冻结，不代替06的数据身份核查、实际清洗、估计和诊断。程序不固定假设数，也允许所有候选不合格。

退出码：0=命令成功或关卡通过；2=输入/执行错误；3=needs_review、failed或stale。异常attempt有failed记录；若进程被强制终止留下.research.lock，先确认其中PID不再运行，再在本项目run目录人工移除该锁后重试。程序不会自动抢占活跃锁。

## 提供方接口

Python中将04的tools目录加入sys.path后导入stage04，或使用runtime.load_stage按注册表加载05。调用`execute(plan, {"literature_provider": 自定义提供方, "model_provider": 自定义模型, "pdf_reader": 自定义PDF读取器})`。LiteratureProvider.read(spec)返回标准题录；ModelProvider具备provider_id/model_version/propose(task)；PDF读取器inspect(path)返回按PDF页排列的字符串列表。生产实现必须正常授权、限速、失败分类，保持资料与命令隔离。

离线模型可读取reasoning_tasks.json并生成标注；在线提供方由调用方显式配置，不在配置文件存账号或令牌。所有模型输出仍是proposal_requires_review。model_call_limit默认12，04最多4次、05最多7次；不做自动重复调用，不替用户估算或编造费用。
