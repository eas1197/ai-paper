# 05 研究问题与假设 · 第3版

与04第4版联合实现的通用研究逻辑程序。前置必读根AGENTS.md、基础要求.md、项目架构.md及04当前契约。不指定课题，不机械生成固定数量假设，不将测试数据计作实际研究。

实现入口：tools/stage05.py的plan/execute/validate/export；命令入口统一使用04的tools/research.py，完整用法与字段见04第4版使用说明.md、数据契约.md。

输入必须锁定同run的04 stage_manifest.json。两个触发起点R现实张力、T理论未覆盖，与四条推进reality_theory_tension/same_level_gap/scope_change/relation_revision分开记录。每条路线都应审查，可以不成立，不强造“创新”。

每张候选问题卡连接原文命题、适用范围、保留部分、拟改变部分、重要性、全文核查、反证和初步数据条件。五项同层级检查覆盖抽象层、单位、角色、时间、维度；不一致须审查桥接链和设计。有限摘要缺词不能作为全球空白。

每个H或RQ连接对应问题卡、全文对话、预期/反驳、替代解释、实际问卷证据和测量变量。题目原文不能由标签补造；跨波次须核题义、编码、样本和权重。控制集逐项说明因果位置，不默认回归产生因果识别。

提供模型可替换推理任务与人工标注入口；模型输出保留unverified提案，不能自动充当研究裁决。默认无API、无网络、无个案数据、无任何外部消息。

冻结必须在主分析之前，G4通过且当前、证据/测量可追、设计字段完整、研究复核绑定内容哈希、freeze_requested=true。程序生成不可覆盖的analysis_design.json，绑定假设、设计和上游哈希；不直接执行06。主分析后新增问题不能倒填为事前假设。探索性记录须明示。

G4未过时05仍能生成整理材料和feedback_to_04.json，但不得passed。04更新使05及其下游stale；补证据时新建04 attempt，再建立新05 attempt，保留全部历史。反馈不是依赖图中的循环模块，静态依赖仍为05→04。

交07提供引言、文献末尾、理论推导、结论回扣四处写作输入。交06提供通过复核的冻结问题/假设与设计；06仍须执行原始数据身份、实际变量、样本流、估计和诊断验收。技术测试通过不代表实际G5科研完成。
